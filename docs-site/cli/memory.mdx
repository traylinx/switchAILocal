## Overview

The memory system records routing decisions, learned per-key preferences and
provider quirks on disk. The server writes to it when `memory.enabled: true`;
the `memory` subcommand lets you inspect and maintain it offline.

```bash
switchAILocal memory <command> [options]
```

`memory` must be the first argument. Flags such as `-config` before it are not
supported.

## Where the data lives

The server and the CLI resolve the folder differently:

| Who | Folder |
| --- | ------ |
| Server | `memory.base-dir` (default `.switchailocal/memory`, relative to the folder the server starts in) |
| `memory` CLI | `<auth-dir>/memory`, with `auth-dir` read from `./config.yaml`; `~/.switchailocal/memory` if there is no config or no `auth-dir` |

Neither expands `~`. An `auth-dir` of `"~/.switchailocal"` makes the CLI use a
literal `./~/.switchailocal/memory` folder under the current directory.

To make both point at the same place, use absolute paths:

```yaml config.yaml
auth-dir: "/Users/you/.switchailocal"
memory:
  enabled: true
  base-dir: "/Users/you/.switchailocal/memory"
```

## Commands

| Command | What it does |
| ------- | ------------ |
| `init` | Create the folder structure |
| `status` | Health, counts and disk usage |
| `history` | Recent routing decisions |
| `preferences` | Learned preferences for one client key |
| `reset` | Back up, then delete all memory data |
| `export` | Write a `.tar.gz` backup |

| Option | Used by | Default |
| ------ | ------- | ------- |
| `--limit <n>` | `history` | `100` |
| `--api-key-hash <hash>` | `history`, `preferences` | none |
| `--api-key <key>` | `preferences` | none |
| `--confirm` | `reset` | off |
| `--output <file>` | `export` | `switchailocal-memory-<YYYYMMDD-HHMMSS>.tar.gz` |

The CLI always uses fixed settings (90-day retention, 100 MB log size,
compression on); it does not read the `memory:` block.

### history

```bash
switchAILocal memory history --limit 20
switchAILocal memory history --api-key-hash sha256:3f9a...
```

Each entry shows the time, a shortened key hash, requested and selected model,
intent, tier with confidence, routing latency and outcome:

```text
[1] 2026-11-08T09:12:44Z
    API Key: sha256:3f9a1c2b...
    Model: auto → ollama:llama3.2
    Intent: coding
    Tier: semantic (confidence: 0.91)
    Latency: 4ms
    Outcome: ✓ Success: true, Response: 1830ms
```

### preferences

```bash
switchAILocal memory preferences --api-key sk-your-key
switchAILocal memory preferences --api-key-hash sha256:3f9a...
```

One of the two options is required. `--api-key` is hashed locally as
`sha256:<hex>` before the lookup. The output lists model preferences per
intent, provider bias and custom rules, or `No preferences learned yet.`

### reset

```bash
switchAILocal memory reset --confirm
```

Without `--confirm` it only prints a warning. With it, the command first writes
`memory-backup-before-reset-<YYYYMMDD-HHMMSS>.tar.gz` to the current directory,
then deletes the memory folder. If the backup fails, nothing is deleted.

### export

```bash
switchAILocal memory export --output memory-backup.tar.gz
```

Writes a gzip tarball of every file in the memory folder.

## Restore a backup

Archive entries are stored relative to the memory folder (no leading folder
name). Extract into the folder itself:

```bash
mkdir -p /Users/you/.switchailocal/memory
tar -xzf memory-backup.tar.gz -C /Users/you/.switchailocal/memory
```

<Warning>
  The hint printed by `reset` (`tar -xzf <file> -C ~/`) extracts into your home
  folder instead. Use the command above.
</Warning>

## Server configuration

```yaml config.yaml
memory:
  enabled: false        # opt-in
  base-dir: ".switchailocal/memory"
  retention-days: 90    # 0 disables cleanup; max 3650
  max-log-size-mb: 100  # 0 disables rotation; max 10000
  compression: true
```

| Key | Type | Default | Meaning |
| --- | ---- | ------- | ------- |
| `memory.enabled` | bool | `false` | Record routing decisions |
| `memory.base-dir` | string | `.switchailocal/memory` | Storage folder (relative to the start folder unless absolute) |
| `memory.retention-days` | int | `90` | Days of routing history to keep |
| `memory.max-log-size-mb` | int | `100` | Rotate a log file above this size |
| `memory.compression` | bool | `true` | Gzip rotated logs |

Changes take effect after a restart. A running server also reports memory
statistics at `GET /v0/management/memory/stats`. More on what is learned:
[Memory system](/intelligent-systems/memory).
