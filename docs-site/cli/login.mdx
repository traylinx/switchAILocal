## Overview

Login flags run a one-off flow, save a credential file into `auth-dir`, and
exit. They do not start the server. A running server picks up new credential
files automatically.

```bash
switchAILocal -claude-login
```

You only need these when you want switchAILocal to hold the credential itself.
Installed and logged-in `gemini`, `claude`, `codex` and `vibe` CLIs are used
directly without any login here, and API keys go into `config.yaml`
([Providers](/configuration/providers)).

<Note>
  Login commands load the configuration first, so run them where your
  `config.yaml` is (or pass `-config`). Credentials are written to the folder
  set by `auth-dir`, for example `~/.switchailocal`.
</Note>

## Summary

| Flag | Provider | Method | Local callback port | Required environment |
| ---- | -------- | ------ | ------------------- | -------------------- |
| `-login` | Google Gemini (Code Assist) | OAuth | `8085` | `GEMINI_CLIENT_ID`, `GEMINI_CLIENT_SECRET` |
| `-claude-login` | Anthropic Claude | OAuth (PKCE) | `54545` | none |
| `-codex-login` | OpenAI Codex | OAuth (PKCE) | `1455` | none |
| `-qwen-login` | Qwen | Device code | none | `QWEN_CLIENT_ID` |
| `-iflow-login` | iFlow | OAuth | `11451` | `IFLOW_CLIENT_ID`, `IFLOW_CLIENT_SECRET` |
| `-iflow-cookie` | iFlow | Browser cookie | none | none |
| `-antigravity-login` | Antigravity | OAuth | `51121` | `ANTIGRAVITY_CLIENT_ID`, `ANTIGRAVITY_CLIENT_SECRET` |
| `-vertex-import <file>` | Google Vertex AI | Service account JSON | none | none |
| `-ollama-login` | Ollama | Connectivity check | none | none |
| `-vibe-login` | Mistral Vibe | Local enable | none | none |

Export the OAuth client variables in your shell. They are read before the
`.env` file is loaded, so putting them in `.env` has no effect.

## Common flag

<ParamField path="-no-browser" type="boolean" default="false">
  Print the authorization URL instead of opening a browser. Use it over SSH or
  on headless machines. The provider still redirects to
  `http://localhost:<callback port>`, so either open the URL on the same machine,
  forward the port (`ssh -L 54545:localhost:54545 host`), or paste the final
  redirect URL when prompted. The paste prompt appears after 15 seconds for
  Claude, Codex, iFlow and Antigravity, and for Gemini when `-project_id` is
  given.
</ParamField>

## Google Gemini

```bash
switchAILocal -login [-project_id PROJECT_ID] [-no-browser]
```

Signs in with your Google account and onboards a Google Cloud project for
Gemini Code Assist. Without `-project_id`, the command lists your projects and
asks you to pick one, or type `ALL` to onboard every listed project.

Requires `GEMINI_CLIENT_ID` and `GEMINI_CLIENT_SECRET` (an OAuth client of your
own). If you already use the `gemini` CLI, you do not need this login: the CLI
is detected automatically.

Saved as `<email>-<project>.json`, or `gemini-<email>-all.json` for `ALL`.

## Claude

```bash
switchAILocal -claude-login [-no-browser]
```

```text
Opening browser for Claude authentication
Waiting for Claude authentication callback...
Claude authentication successful
Authentication saved to /Users/you/.switchailocal/claude-you@example.com.json
Claude authentication successful!
```

Saved as `claude-<email>.json`.

## Codex

```bash
switchAILocal -codex-login [-no-browser]
```

Signs in to your OpenAI account. Saved as `codex-<email>.json`.

## Qwen

```bash
switchAILocal -qwen-login [-no-browser]
```

Device-code flow: open the printed URL, approve, and the command finishes once
the token is issued. Requires `QWEN_CLIENT_ID`. Saved as `qwen-<email>.json`.

## iFlow

<Tabs>
  <Tab title="OAuth">
    ```bash
    switchAILocal -iflow-login [-no-browser]
    ```

    Requires `IFLOW_CLIENT_ID` and `IFLOW_CLIENT_SECRET`. Saved as
    `iflow-<email>-<timestamp>.json`.
  </Tab>
  <Tab title="Cookie">
    ```bash
    switchAILocal -iflow-cookie
    ```

    Log in to iFlow in your browser, copy the cookie from the developer tools,
    and paste it at the prompt:

    ```text
    Enter iFlow Cookie (from browser cookies):
    ```

    If a credential with the same `BXAuth` value already exists, the command
    stops and names the existing file. On success it prints the issued API key
    and its expiry, so do not run it where the terminal is recorded.
  </Tab>
</Tabs>

## Vertex AI service account

```bash
switchAILocal -vertex-import /path/to/service-account.json
```

Imports a Google Cloud service account key. The JSON must contain `project_id`
(and normally `client_email`). The key is stored as `vertex-<project>.json` and
the command prints the saved path:

```text
Vertex credentials imported: /Users/you/.switchailocal/vertex-my-project.json
```

The service account needs Vertex AI access in that project (for example the
`roles/aiplatform.user` role).

For third-party services that only mimic Vertex AI paths with a plain API key,
use `vertex-api-key` in `config.yaml` instead.

## Ollama

```bash
switchAILocal -ollama-login
```

Checks `ollama.base-url` (default `http://localhost:11434`) by calling
`/api/tags`, lists the installed models, and writes `ollama-local.json`.

```text
Checking Ollama at http://localhost:11434...
✅ Ollama connected! Found 2 model(s):
   - llama3.2:latest
   - qwen3:8b
Ollama configuration saved to /Users/you/.switchailocal/ollama-local.json
Ollama provider enabled successfully!
```

If Ollama is not running, the command fails with
`Ollama is not running at ... Please start Ollama with: ollama serve`.

For normal use, enabling the `ollama:` block in `config.yaml` is enough; this
command is optional.

## Vibe

```bash
switchAILocal -vibe-login
```

Writes `vibe-local.json` to enable the local Vibe provider. No account login
happens here; the `vibe` CLI must already be set up.

## Managing credentials

- Credential files are JSON with mode `0600`. Keep `auth-dir` at `0700`.
- To remove a credential, delete its file from `auth-dir` (the server notices),
  or use `DELETE /v0/management/auth-files` from the
  [Management API](/api/management/overview).
- OAuth tokens are refreshed automatically by the running server (checked every
  15 minutes). Re-run the login if a refresh fails.
- The management panel can also start OAuth flows; those callbacks arrive on
  the server's own port (`/anthropic/callback`, `/codex/callback`,
  `/google/callback`, `/iflow/callback`, `/antigravity/callback`).

## Troubleshooting

<AccordionGroup>
  <Accordion title="Callback never arrives / port already in use">
    The OAuth flows listen on fixed local ports (see the table). Free the port
    (`lsof -i :54545`), then retry. On a remote machine use `-no-browser` and
    forward the port over SSH, or paste the redirect URL when prompted.
  </Accordion>
  <Accordion title="Gemini login fails immediately">
    `GEMINI_CLIENT_ID` and `GEMINI_CLIENT_SECRET` are empty by default. Set them,
    or use the `gemini` CLI instead.
  </Accordion>
  <Accordion title="failed to read config file">
    Login commands need a loadable config. Run them in the folder with
    `config.yaml`, or pass `-config`.
  </Accordion>
  <Accordion title="Credentials not picked up">
    Check that the file landed in the `auth-dir` the server uses
    (`ls -la ~/.switchailocal`). With a PostgreSQL, object or Git store,
    credentials are kept in the store instead of `auth-dir`.
  </Accordion>
</AccordionGroup>
