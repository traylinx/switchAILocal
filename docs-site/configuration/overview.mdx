switchAILocal is configured with one YAML file. Client keys, providers,
routing, logging and the management API all live there.

## Where the file is

| How you start the server | File used |
| ------------------------ | --------- |
| `switchAILocal` | `./config.yaml` in the current directory |
| `switchAILocal -config <path>` | `<path>` (no `..` or `~`; absolute paths only under home, `/etc/`, `/usr/`, `/var/`) |
| Docker image | `/app/config.yaml` (mount it) |
| `PGSTORE_DSN`, `OBJECTSTORE_ENDPOINT` or `GITSTORE_GIT_URL` set | A copy managed by that store ([details](/cli/server#config-sources)) |

The file is required. If it is missing, the server logs
`failed to read config file` and exits.

Keep it private; the server warns at startup when the file is readable by
group or others:

```bash
chmod 600 config.yaml
```

## Start small

A working minimal config:

```yaml config.yaml
host: "127.0.0.1"
port: 18080
auth-dir: "~/.switchailocal"
api-keys:
  - "sk-your-key"
```

`config.example.yaml` in the repository and release archives documents every
section. It is a reference, not a safe default: it enables example providers,
virtual models, auto-routing, intelligence features, Prometheus metrics and a
test client key. Copy only the sections you need.

## Syntax rules

- Keys are kebab-case (`auth-dir`, `request-retry`). A few nested blocks use
  snake_case because they mirror API fields: `virtual-models` member options
  (`response_model`, `tool_history_replay`), model options (`context_length`,
  `native_tools`) and the whole `superbrain` block.
- **Unknown keys are ignored silently.** A typo such as `api_keys` simply has no
  effect. Compare against the [reference](/configuration/reference) when a
  setting seems to do nothing.
- **No environment variable expansion.** `api-key: "${OPENAI_KEY}"` is sent
  literally. Render the file with a tool such as `envsubst` if you need
  templating. A few settings have environment equivalents, for example
  `MANAGEMENT_PASSWORD` ([Server command](/cli/server#environment-variables)).
- Durations accept Go syntax (`15s`, `5m`, `24h`) where the reference says
  "duration".

## Validation

The server refuses to start when:

- the YAML does not parse;
- `remote-management.allow-remote` is `true` with no `secret-key` and no
  `MANAGEMENT_PASSWORD`;
- a `virtual-models` entry is invalid (unknown strategy, member without
  `id`, `provider` or `model`, duplicate member id, negative weight, or an
  exposed pool with no enabled member).

Some entries are dropped silently during loading:

- `codex-api-key`, `openai-compatibility` and `vertex-api-key` entries without
  `base-url`;
- `gemini-api-key` entries without `api-key`, and duplicate Gemini keys;
- a `prefix` containing `/` (treated as no prefix).

## Live reload

The server watches the config file and reloads it about 150 ms after a change.
Applied without a restart:

- `api-keys` and other client access settings;
- provider credentials, models and aliases, `oauth-excluded-models`,
  `virtual-models`, `payload`;
- `routing.strategy`, `force-model-prefix`, `request-retry`,
  `max-retry-interval`, `disable-cooling`, `quota-exceeded`;
- `debug`, `logging-to-file`, `logs-max-total-size-mb`,
  `observability.log-format`, `request-log`, `usage-statistics-enabled`,
  `ws-auth`, `proxy-url`;
- `remote-management` settings used by the management API;
- `superbrain` settings.

Restart after changing `host`, `port`, `tls`, `performance`,
`observability.metrics` or `observability.request-events`, and the subsystems
initialized at startup: `memory`, `heartbeat`, `steering`, `hooks`,
`intelligence`, `auto-routing` and `plugin`.

If the edited file does not load (for example invalid YAML), the reload is
rejected with `failed to reload config` in the log and the previous settings
stay active.

Credential files added to or removed from `auth-dir` are also picked up live.

## When the server writes your file

switchAILocal edits `config.yaml` itself in these cases:

| Trigger | Change |
| ------- | ------ |
| Plaintext `remote-management.secret-key` | Replaced with its bcrypt hash at startup |
| Legacy keys (`generative-language-api-key`, `amp-upstream-url`, `amp-*`, `routing.auto-model-priority`, old `openai-compatibility` `api-keys` lists) | Migrated to the current layout and saved |
| Management panel or field endpoints of the management API | The edited fields, comments preserved |
| `PUT /v0/management/config.yaml` | Whole file replaced with the request body |
| Setup screen of the management panel | `remote-management.secret-key` and `allow-remote` |

Writes keep the file in place (bind mounts keep working) and set its mode to
`0600`. The file must be writable by the server user for these to succeed.
