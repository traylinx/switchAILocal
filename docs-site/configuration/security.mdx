switchAILocal has two separate gates:

| Gate | Protects | Configured by |
| ---- | -------- | ------------- |
| Client keys | `/v1/*`, `/openai/v1/*`, `/v1beta/*`, `/v1/ws` | `api-keys`, `ws-auth` |
| Management key | `/v0/management/*` and the panel's actions | `remote-management`, `MANAGEMENT_PASSWORD` |

`/health`, `/`, `/management` (the panel page itself), OAuth callback routes
and, when enabled, `/metrics` are served without either key.
`/v1internal:*` (used by the Gemini CLI) skips the client key but only answers
`127.0.0.1`. The Amp routes under `/api/*` use the client key
([ampcode](/configuration/reference#ampcode)).

## Client API keys

```yaml config.yaml
api-keys:
  - "sk-your-key"
  - "sk-second-key"
```

<ParamField path="api-keys" type="string[]" default="[]">
  Keys clients must present. **When the list is empty or absent, client
  authentication is off** and any request is accepted. Set at least one key
  whenever the port is reachable by anything other than you.
</ParamField>

A key is accepted from any of these, checked in order:

| Location | Example |
| -------- | ------- |
| `Authorization` header | `Authorization: Bearer sk-your-key` |
| `X-Goog-Api-Key` header | Gemini SDKs |
| `X-Api-Key` header | Anthropic SDKs |
| `key` query parameter | `/v1beta/models?key=sk-your-key` |
| `auth_token` query parameter | `?auth_token=sk-your-key` |

Errors: `401 {"error":"Missing API key"}` or `401 {"error":"Invalid API key"}`.

Keys reload live. To rotate: add the new key, move clients over, remove the old
key. Generate keys with `openssl rand -hex 32` and use any string you like;
the `sk-` prefix is only a convention.

<ParamField path="ws-auth" type="boolean" default="true">
  Require a client key on the WebSocket relay (`/v1/ws`). Setting `false` logs
  a security warning at startup.
</ParamField>

## Management access

```yaml config.yaml
remote-management:
  allow-remote: false
  secret-key: "a-long-random-secret"
  disable-control-panel: false
  panel-github-repository: "https://github.com/traylinx/switchAILocal-Management-Center"
```

<ParamField path="remote-management.secret-key" type="string" default='""'>
  Management key. A plaintext value is replaced with its bcrypt hash in
  `config.yaml` at startup. The special value `disabled` turns authentication
  off for localhost only (remote callers are still rejected).
</ParamField>

<ParamField path="remote-management.allow-remote" type="boolean" default="false">
  Accept management requests from non-loopback addresses. Requires a
  `secret-key` or `MANAGEMENT_PASSWORD`, or the server refuses to start.
</ParamField>

<ParamField path="remote-management.disable-control-panel" type="boolean" default="false">
  Stop serving `/management` and stop downloading panel updates. The management
  API keeps working.
</ParamField>

<ParamField path="remote-management.panel-github-repository" type="string">
  Where the panel updater looks for a newer `management.html` (GitHub release
  asset). Accepts a repository URL or a GitHub API releases URL. Default:
  `https://github.com/traylinx/switchAILocal-Management-Center`.
</ParamField>

`MANAGEMENT_PASSWORD` (environment) is accepted as a management key in
addition to `secret-key`.

### How a management request is decided

| Request from | `secret-key` / `MANAGEMENT_PASSWORD` | Result |
| ------------ | ------------------------------------ | ------ |
| localhost | neither set | Allowed without a key |
| localhost | `secret-key: disabled`, no env password | Allowed without a key |
| localhost | set | Key required |
| remote | `allow-remote: false` | `403 {"error":"remote management disabled"}` |
| remote | `allow-remote: true` | Key required |

<Warning>
  With an empty `secret-key` the management API is **open to local
  processes**, including reading and rewriting `config.yaml` and your provider
  keys. Any program or browser page on the machine that can reach the port can
  use it. Set a `secret-key` unless the machine is single-user and trusted.
</Warning>

Details:

- Send the key as `Authorization: Bearer <key>` or `X-Management-Key: <key>`.
- "localhost" means a loopback address **with no** `X-Forwarded-For`,
  `X-Real-IP` or `Forwarded` header. Behind a reverse proxy every request
  counts as remote.
- After 5 failed attempts a remote IP is banned for 30 minutes
  (`403 IP banned due to too many failed attempts`).
- The setup endpoints (`/v0/management/setup-status`, `/initialize`, `/skip`,
  `/reset`) skip the key check; all but `setup-status` only work from
  localhost. `/initialize` sets the first secret and **also sets
  `allow-remote: true`**. `/skip` sets `secret-key: disabled` and
  `allow-remote: false`. `/reset` clears the secret and sets
  `allow-remote: false`.

## TLS

```yaml config.yaml
tls:
  enable: true
  cert: "/etc/letsencrypt/live/ai.example.com/fullchain.pem"
  key: "/etc/letsencrypt/live/ai.example.com/privkey.pem"
```

TLS replaces plain HTTP on the same port. Changes need a restart. Alternatively
keep `host: "127.0.0.1"` and terminate TLS in a reverse proxy; remember that
proxied management requests then count as remote.

## Files and permissions

| Path | Contains | Recommended mode |
| ---- | -------- | ---------------- |
| `config.yaml` | Client keys, provider keys, management hash | `600` (startup warns otherwise) |
| `auth-dir` | Provider credential files (`claude-<email>.json`, ...), written `600` | `700` (startup warns otherwise) |
| `logs/` | Logs; request logs may contain prompts | restrict if `request-log` is on |

```bash
chmod 600 config.yaml
chmod 700 ~/.switchailocal
```

Do not commit `config.yaml` or `auth-dir`. `config.yaml` has no environment
variable expansion, so `${VAR}` placeholders are not substituted; render the
file before starting if you keep secrets elsewhere.

## Checklist for anything beyond localhost

1. Set `api-keys` (otherwise client auth is off).
2. Set `remote-management.secret-key` to a long random value.
3. Keep `allow-remote: false` unless you need remote management; if you enable
   it, use TLS.
4. Keep `ws-auth: true`.
5. Leave `observability.metrics` off or firewall `/metrics`; it is
   unauthenticated.
6. Bind `host: "127.0.0.1"` when only local clients need access.
7. `chmod 600 config.yaml`, `chmod 700` on `auth-dir`.

## Troubleshooting

<AccordionGroup>
  <Accordion title="401 Missing API key / Invalid API key">
    Send `Authorization: Bearer <key>` with a value from `api-keys`. Keys are
    exact matches, including any `sk-` prefix.
  </Accordion>
  <Accordion title="403 remote management disabled">
    The request did not come from a direct loopback connection. Set
    `allow-remote: true` with a secret, or call from the same machine without a
    proxy in between.
  </Accordion>
  <Accordion title="401 invalid management key after editing secret-key">
    The file now holds a bcrypt hash; send the original plaintext. To start
    over, set a new plaintext value; it is hashed again at the next start.
  </Accordion>
  <Accordion title="Server refuses to start: allow-remote is true but no secret is set">
    Add `remote-management.secret-key`, set `MANAGEMENT_PASSWORD`, or set
    `allow-remote: false`.
  </Accordion>
</AccordionGroup>
