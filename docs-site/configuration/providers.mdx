Providers come from three places:

| Source | Configured by | Example prefix |
| ------ | ------------- | -------------- |
| CLI tools on `PATH` | nothing (auto-detected at startup) | `geminicli:`, `claudecli:`, `codex:`, `vibecli:` |
| Credential files in `auth-dir` | [Login commands](/cli/login) or the management panel | depends on provider |
| `config.yaml` | the keys on this page | `gemini:`, `claude:`, `codex:`, `switchai:`, `ollama:`, `opencode:` |

Several entries for the same provider are load-balanced according to
`routing.strategy` ([Server](/configuration/server#credential-selection)).

## Options shared by API-key providers

`gemini-api-key`, `claude-api-key`, `codex-api-key`, `switchai-api-key` and
`vertex-api-key` are lists; each item is one credential.

| Field | Meaning |
| ----- | ------- |
| `api-key` | Upstream key |
| `base-url` | Upstream endpoint (see each provider for whether it is required) |
| `prefix` | Namespace: models are also reachable as `<prefix>/<model>`. No `/` allowed. |
| `proxy-url` | Per-credential outbound proxy, overrides the global `proxy-url` |
| `headers` | Extra HTTP headers sent upstream |
| `models` | Explicit models: `name` (upstream ID) and `alias` (name clients use) |
| `models-url` | Override the model-list endpoint used for discovery (not for `vertex-api-key`) |
| `excluded-models` | Model IDs or wildcard patterns (`*-preview`) to hide (not for `vertex-api-key`) |

Prefixed IDs (`teamA/gemini-2.5-pro`) are routable but hidden from
`/v1/models` unless `force-model-prefix: true`.

## Google AI Studio (Gemini)

```yaml config.yaml
gemini-api-key:
  - api-key: "your-gemini-key"
  - api-key: "your-second-gemini-key"
    prefix: "team-b"
    excluded-models:
      - "*-preview"
```

| Field | Required | Default |
| ----- | -------- | ------- |
| `api-key` | yes; entries without it are dropped, duplicates removed | |
| `base-url` | no | Google's Generative Language API |

Prefix: `gemini:`.

## Anthropic API

```yaml config.yaml
claude-api-key:
  - api-key: "sk-ant-your-key"
    models:
      - name: "claude-sonnet-4-5-20250929"
        alias: "sonnet"
```

`base-url` is optional (default Anthropic API); set it for Claude-compatible
services. Prefix: `claude:`. Clients can also call the Anthropic-format
`/v1/messages` route.

## OpenAI API (`codex-api-key`)

```yaml config.yaml
codex-api-key:
  - api-key: "sk-your-openai-key"
    base-url: "https://api.openai.com/v1"
```

<Warning>
  `base-url` is required. Entries without it are dropped silently.
</Warning>

The name is historical; it serves OpenAI models in general. Prefix: `codex:`
(shared with the Codex CLI provider).

## Traylinx switchAI

```yaml config.yaml
switchai-api-key:
  - api-key: "sk-your-switchai-key"
    models:
      - name: "deepseek-reasoner"
        alias: "reasoner"
```

`base-url` defaults to `https://switchai.traylinx.com/v1`. Prefix: `switchai:`.

## OpenAI-compatible services

Any service that speaks the OpenAI API: Groq, OpenRouter, DeepSeek, Together,
Fireworks, a self-hosted vLLM, and so on.

```yaml config.yaml
openai-compatibility:
  - name: "groq"
    prefix: "groq"
    base-url: "https://api.groq.com/openai/v1"
    api-key-entries:
      - api-key: "gsk_your-key"
    models:
      - name: "openai/gpt-oss-20b"
        alias: "gpt-oss-20b"
  - name: "openrouter"
    base-url: "https://openrouter.ai/api/v1"
    models-url: "https://openrouter.ai/api/v1/models"
    api-key-entries:
      - api-key: "sk-or-your-key"
      - api-key: "sk-or-second-key"
        proxy-url: "socks5://127.0.0.1:1080"
```

| Field | Required | Meaning |
| ----- | -------- | ------- |
| `name` | yes | Provider ID used in logs, metrics, `performance.*.per-provider` and virtual-model `provider` fields |
| `base-url` | yes | API root ending in `/v1` (or equivalent). Entries without it are dropped. |
| `api-key-entries` | no | List of `{api-key, proxy-url}`; each key is a credential. Omit for keyless local servers. |
| `models` | no | Explicit model list with aliases (see [Model options](#model-options)) |
| `models-url` | no | Model-list endpoint; when set, models are discovered at startup using the first key |
| `prefix` | no | Namespace (`<prefix>/<alias>`) |
| `headers` | no | Extra headers, for example a required `User-Agent` |
| `excluded-models` | no | IDs or patterns to hide |
| `proxy-url` | no | Outbound proxy for this provider |
| `kimi-history-shim` | no | Default `true`. Adds a placeholder `reasoning_content` to earlier assistant tool-call messages that lack it, which Kimi and DeepSeek thinking models require. Harmless elsewhere; set `false` to disable. |

<Tip>
  A client that insists on a `vendor:model` string can be served by making that
  string the alias, for example `alias: "groq:gpt-oss-20b"`. Only the built-in
  prefixes (`ollama:`, `geminicli:`, ...) are parsed as prefixes; other strings
  are matched as model names.
</Tip>

## Vertex-compatible services

For services that use Vertex AI-style paths with a plain API key. For real
Vertex AI with a service account, use `-vertex-import` ([Login](/cli/login#vertex-ai-service-account)).

```yaml config.yaml
vertex-api-key:
  - api-key: "vk-your-key"
    base-url: "https://vertex-proxy.example.com"
    models:
      - name: "gemini-2.5-flash"
        alias: "flash"
```

`base-url` is required; entries without it are dropped.

## Ollama

```yaml config.yaml
ollama:
  enabled: true
  base-url: "http://localhost:11434"
  auto-discover: true
  excluded-models:
    - "llama2*"
```

| Field | Default | Meaning |
| ----- | ------- | ------- |
| `enabled` | `false` | Register the provider |
| `base-url` | `http://localhost:11434` | Ollama API root |
| `auto-discover` | `false` | Load the model list from `/api/tags` at startup; without it, models are not listed but `ollama:<model>` still routes |
| `proxy-url` | none | Outbound proxy |
| `excluded-models` | none | IDs or patterns to hide |

Use `ollama:<model>` (for example `ollama:llama3.2`). From a container, set
`base-url` to `http://host.docker.internal:11434`. The `models`, `headers` and
`models-url` fields are accepted but not used in 0.6.2.

## LM Studio

<Warning>
  In 0.6.2 the `lmstudio:` block registers the provider, but its models are not
  discovered and `lmstudio:` is not a recognized prefix. Requests fail with
  `unknown provider for model lmstudio:...`. Configure LM Studio as an
  OpenAI-compatible service instead.
</Warning>

```yaml config.yaml
openai-compatibility:
  - name: "lm-studio"
    base-url: "http://localhost:1234/v1"
    models-url: "http://localhost:1234/v1/models"
    models:
      - name: "qwen2.5-7b-instruct"          # the model ID LM Studio shows
        alias: "lmstudio:qwen2.5-7b-instruct"
```

The `lmstudio:` block itself (`enabled`, default `false`; `base-url`, default
`http://localhost:1234/v1`; `proxy-url`; `excluded-models`) is still read and
used for heartbeat checks.

## OpenCode

Connects to a running OpenCode server (`opencode serve`) and exposes its agents
as models.

```yaml config.yaml
opencode:
  enabled: true
  base-url: "http://localhost:4096"
  default-agent: "build"
```

| Field | Default | Meaning |
| ----- | ------- | ------- |
| `enabled` | `false` | Register the provider and discover agents from `<base-url>/agent` |
| `base-url` | `http://localhost:4096` | OpenCode server |
| `default-agent` | none | Agent used when the request does not name one |

Prefix: `opencode:`.

## Model options

`models` items in `openai-compatibility` accept these fields. For the other
providers, use `name` and `alias`.

| Field | Meaning |
| ----- | ------- |
| `name` | Upstream model ID |
| `alias` | ID clients send. Several aliases may point at one `name`. |
| `expose` | `false` keeps the alias routable but hides it from `/v1/models` (default `true`) |
| `visibility` | `private` also hides it from `/v1/models` |
| `context_length` | Context window reported by `/v1/models` |
| `capabilities` | `operations`, `input`, `output`, `tools`, `context`, `tool_history_replay`, `agentic_safe`, ... reported by `/v1/models` |
| `native_tools` | Provider-native tools (`type`, `description`, `params`) advertised in `/v1/models`, for example MiniMax `web_search` |

```yaml
models:
  - name: "deepseek-v4-pro"
    alias: "long-context"
    context_length: 1000000
    capabilities: {operations: [chat, chat_text_tools], input: [text], output: [text], tools: true}
```

## Virtual models

A virtual model is one public model ID backed by a pool of concrete
provider/model members. Requests are spread across enabled members by weight
and filtered by the capabilities the request needs (tools, images, ...).

```yaml config.yaml
virtual-models:
  my-default:
    description: "Chat pool"
    expose: true
    strategy: weighted-round-robin
    fallback: true
    response_model: requested
    members:
      - id: groq-oss
        provider: groq
        model: openai/gpt-oss-20b
        weight: 3
        capabilities: {operations: [chat, chat_text_tools], input: [text], output: [text], tools: true}
      - id: local-llama
        provider: ollama
        model: llama3.2
        weight: 1
        capabilities: {operations: [chat], input: [text], output: [text]}
```

| Field | Default | Meaning |
| ----- | ------- | ------- |
| `expose` | `false` | List the ID in `/v1/models`. An exposed pool needs at least one enabled member. |
| `strategy` | `weighted-round-robin` | Or `round-robin` |
| `fallback` | `false` | Try another member when one fails |
| `response_model` | `requested` | Model name reported back to the client |
| `members[].id` | required, unique | Member ID |
| `members[].provider` | required | Lower-case provider ID of a configured provider |
| `members[].model` | required | Upstream model for that provider |
| `members[].enabled` | `true` | Include in the pool |
| `members[].weight` | `1` | Relative share; must not be negative |
| `members[].capabilities` | none | What the member can do; used to filter members per request |

An invalid pool stops the server at startup. More detail:
[Virtual models](/advanced/virtual-models).

## Hiding models from OAuth and CLI credentials

`excluded-models` applies to one config entry. To hide models from credentials
that come from `auth-dir` files or CLI discovery, use a map keyed by provider:

```yaml config.yaml
oauth-excluded-models:
  geminicli:
    - "*-preview"
  claudecli:
    - "claude-3-5-haiku-20241022"
```
