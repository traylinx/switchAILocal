All keys on this page are top-level keys in `config.yaml`. "Default" means the
value used when the key is absent, which can differ from what
`config.example.yaml` sets.

## Listener

```yaml config.yaml
host: "127.0.0.1"
port: 18080
```

<ParamField path="host" type="string" default='""'>
  Interface to bind. Empty binds all interfaces (IPv4 and IPv6). Use
  `"127.0.0.1"` to accept local connections only. Inside a container keep it
  empty, or the published port is unreachable. Restart required.
</ParamField>

<ParamField path="port" type="integer" default="none">
  TCP port for HTTP or HTTPS. There is no built-in default: always set it.
  `18080` is the conventional value used throughout these docs and the Docker
  image. If omitted, the server binds a random free port. Restart required.
</ParamField>

## TLS

```yaml config.yaml
tls:
  enable: true
  cert: "/etc/letsencrypt/live/ai.example.com/fullchain.pem"
  key: "/etc/letsencrypt/live/ai.example.com/privkey.pem"
```

<ParamField path="tls.enable" type="boolean" default="false">
  Serve HTTPS on `port` instead of HTTP. There is no separate HTTP listener.
</ParamField>

<ParamField path="tls.cert" type="string">
  PEM certificate (full chain). Required when `enable` is `true`.
</ParamField>

<ParamField path="tls.key" type="string">
  PEM private key. Required when `enable` is `true`.
</ParamField>

With an empty `cert` or `key` the listener fails with
`tls.cert or tls.key is empty`. Restart after any TLS change.

## Credential folder

<ParamField path="auth-dir" type="string" default="none">
  Folder for credential files written by [logins](/cli/login) and the
  management panel (`claude-<email>.json`, `vertex-<project>.json`, ...). A
  leading `~` is expanded. After expansion, an absolute path must be inside your
  home directory, `/etc/`, `/usr/` or `/var/`, and `..` is not allowed. Created
  on first start if missing. The example config uses `"~/.switchailocal"`.
</ParamField>

## Logging

```yaml config.yaml
debug: false
logging-to-file: false
logs-max-total-size-mb: 0
request-log: false
usage-statistics-enabled: false
```

<ParamField path="debug" type="boolean" default="false">
  Debug-level logs and more detailed errors.
</ParamField>

<ParamField path="logging-to-file" type="boolean" default="false">
  Write logs to `logs/main.log` (relative to the start folder, or
  `$WRITABLE_PATH/logs`) instead of stdout. The file rotates at 10 MB.
</ParamField>

<ParamField path="logs-max-total-size-mb" type="integer" default="0">
  Upper bound for the `logs/` folder. When exceeded, the oldest files are deleted
  (the active `main.log` is kept). `0` disables the limit.
</ParamField>

<ParamField path="request-log" type="boolean" default="false">
  Record full request and response details for each API call in the `logs/`
  folder. Toggle it at runtime with `PUT /v0/management/request-log`; read
  entries with `GET /v0/management/request-log-by-id/:id` and
  `/v0/management/request-error-logs`. Bodies can contain prompts and secrets.
</ParamField>

<ParamField path="usage-statistics-enabled" type="boolean" default="false">
  Aggregate request and token counts in memory, served at
  `GET /v0/management/usage`. Lost on restart.
</ParamField>

## Observability

```yaml config.yaml
observability:
  log-format: "text"
  metrics:
    enabled: false
    path: "/metrics"
  request-events:
    enabled: false
    output: "stdout"
    file-path: "logs/events.ndjson"
```

<ParamField path="observability.log-format" type="string" default="text">
  `text` for human-readable logs, `json` for structured logs (Loki, ELK,
  Datadog).
</ParamField>

<ParamField path="observability.metrics.enabled" type="boolean" default="false">
  Serve Prometheus metrics on the main port. The endpoint is **not
  authenticated**; do not expose it publicly. Restart required.
</ParamField>

<ParamField path="observability.metrics.path" type="string" default="/metrics">
  HTTP path for metrics.
</ParamField>

<ParamField path="observability.request-events.enabled" type="boolean" default="false">
  Emit one JSON line per proxied request (model, provider, latency, tokens,
  routing metadata). Restart required.
</ParamField>

<ParamField path="observability.request-events.output" type="string" default="stdout">
  `stdout` or `file`.
</ParamField>

<ParamField path="observability.request-events.file-path" type="string" default="logs/events.ndjson">
  Target file when `output` is `file`. Parent folders are created.
</ParamField>

<Note>
  `observability.request-events.include-body` is accepted but has no effect in
  0.6.2.
</Note>

## Outbound proxy

<ParamField path="proxy-url" type="string" default='""'>
  Proxy for outbound provider requests: `socks5://`, `http://` or `https://`,
  credentials allowed (`socks5://user:pass@host:1080`). Provider entries can
  override it with their own `proxy-url`.
</ParamField>

## Retries and cooldowns

Within one attempt, a request already fails over across all matching
credentials and providers. These keys control what happens after every
candidate failed.

```yaml config.yaml
request-retry: 3
max-retry-interval: 30
disable-cooling: false
```

<ParamField path="request-retry" type="integer" default="0">
  Extra attempts after all candidates failed. A retry only happens when a
  failed credential will leave its cooldown within `max-retry-interval`; the
  server waits for that and tries again.
</ParamField>

<ParamField path="max-retry-interval" type="integer" default="0">
  Longest wait in seconds for a cooled-down credential before retrying. `0`
  disables these waits, so `request-retry` has no effect unless you set this.
</ParamField>

<ParamField path="disable-cooling" type="boolean" default="false">
  Do not put credentials into cooldown after quota or rate-limit errors.
</ParamField>

<ParamField path="quota-exceeded" type="object">
  `switch-project` and `switch-preview-model` (both default `false`) are
  accepted and editable through the management API, but no request path uses
  them in 0.6.2.
</ParamField>

## Streaming

```yaml config.yaml
streaming:
  keepalive-seconds: 15
  bootstrap-retries: 2
```

<ParamField path="streaming.keepalive-seconds" type="integer" default="disabled">
  Interval for SSE keep-alive comments (`: keep-alive`). Absent, `0` or negative
  disables them. Set this if a proxy between client and server closes idle
  streams.
</ParamField>

<ParamField path="streaming.bootstrap-retries" type="integer" default="0">
  How often a streaming request may be retried on another credential before the
  first byte reaches the client.
</ParamField>

Stream stall detection lives under [`performance.streaming`](#performance).

## Credential selection

```yaml config.yaml
routing:
  strategy: "round-robin"
force-model-prefix: false
```

<ParamField path="routing.strategy" type="string" default="round-robin">
  How to choose among several credentials that serve the same model:
  - `round-robin`: rotate across them.
  - `fill-first` (also `fillfirst`, `ff`): use the first until it fails or cools
    down, then the next.
</ParamField>

<ParamField path="force-model-prefix" type="boolean" default="false">
  When `true`, a model name without a credential prefix only uses credentials
  that have no `prefix`; `teamA/model` only uses credentials with
  `prefix: "teamA"`. When `false`, unprefixed requests may use prefixed
  credentials too.
</ParamField>

<Note>
  `routing.auto-model-priority` is a legacy key. On load it is converted into
  `auto-routing.preferences` and removed from the file. See
  [Auto-routing](/api/auto-routing).
</Note>

## Performance

All blocks are optional. Values shown are the defaults applied when a key is
absent. Restart after changes.

```yaml config.yaml
performance:
  rate-limiter:
    enabled: false
    global-requests-per-second: 1000
    global-burst: 500
    per-key-requests-per-second: 60
    per-key-burst: 30
  load-shedding:
    enabled: false
    max-in-flight: 500
    retry-after-seconds: 5
  circuit-breaker:
    enabled: false
    failure-threshold: 5
    reset-timeout: 30s
    half-open-max: 3
  provider-timeouts:
    default: 120s
    per-provider:
      ollama: 180s
  streaming:
    first-byte-timeout: 15s
    stall-timeout: 60s
    per-provider: {}
  profiling-enabled: false
  pprof-port: 6060
```

| Key | Default | Meaning |
| --- | ------- | ------- |
| `rate-limiter.enabled` | `false` | Token-bucket limits; excess requests get `429` with `Retry-After` |
| `rate-limiter.global-requests-per-second` / `global-burst` | `1000` / `500` | Limit across all clients |
| `rate-limiter.per-key-requests-per-second` / `per-key-burst` | `60` / `30` | Limit per `Authorization` value |
| `load-shedding.enabled` | `false` | Reject requests with `503` above the in-flight limit |
| `load-shedding.max-in-flight` | `500` | Concurrent requests before shedding |
| `load-shedding.retry-after-seconds` | `5` | `Retry-After` value on shed requests |
| `circuit-breaker.enabled` | `false` | Per-provider breaker; open providers are skipped so failover moves on |
| `circuit-breaker.failure-threshold` | `5` | Consecutive failures that open the circuit |
| `circuit-breaker.reset-timeout` | `30s` | Time open before a half-open probe |
| `circuit-breaker.half-open-max` | `3` | Probe requests allowed while half-open |
| `provider-timeouts.default` | `120s` | Whole-request timeout for providers without an entry |
| `provider-timeouts.per-provider` | `{}` | Map of provider name to timeout |
| `streaming.first-byte-timeout` | `15s` | Wait for the first upstream byte; a stall here can still fail over |
| `streaming.stall-timeout` | `60s` | Max gap between chunks; the stream then ends with an SSE error event |
| `streaming.per-provider` | `{}` | Map of provider name to first-byte timeout |
| `profiling-enabled` | `false` | Start a pprof server on `127.0.0.1:<pprof-port>` |
| `pprof-port` | `6060` | pprof port |

`config.example.yaml` enables the circuit breaker with
`failure-threshold: 3` and `reset-timeout: 5m`.

## Example

```yaml config.yaml
host: ""
port: 18080

auth-dir: "~/.switchailocal"
api-keys:
  - "sk-your-key"

logging-to-file: true
logs-max-total-size-mb: 500
observability:
  log-format: "json"

request-retry: 2
max-retry-interval: 30

streaming:
  keepalive-seconds: 15
  bootstrap-retries: 2

performance:
  circuit-breaker:
    enabled: true
    failure-threshold: 3
    reset-timeout: 5m
```
