Defaults are the values used when a key is absent from `config.yaml`. They are
not the values in `config.example.yaml`, which turns many features on.

Keys not listed here are ignored without a warning.

## Features

### payload

Default and override rules that set JSON fields in upstream requests per model
and protocol.

```yaml
payload:
  default: []    # set a field only if the request lacks it
  override: []   # always set the field
```

Details: [Payload injection](/advanced/payload-injection).

### plugin

```yaml
plugin:
  enabled: false
  plugin-dir: "./plugins"
  enabled-plugins: ["cortex-router"]
```

| Key | Default | Meaning |
| --- | ------- | ------- |
| `enabled` | `false` | Run Lua plugins |
| `plugin-dir` | none | Folder with plugin folders (the Docker image ships `/app/plugins`) |
| `enabled-plugins` | `[]` | Plugin names to load |

Details: [Lua plugins](/advanced/lua-plugins).

### intelligence

Cortex routing for `model: "auto"`: classification, semantic matching, skills,
caching. Restart required.

| Key | Default |
| --- | ------- |
| `enabled` | `false` |
| `router-model` | `ollama:qwen:0.5b` |
| `router-fallback` | `openai:gpt-4o-mini` |
| `matrix` | `{}` (intent to model) |
| `skills.enabled` / `skills.directory` | `false` / `plugins/cortex-router/skills` |
| `embedding.enabled` / `embedding.model` | `false` / `all-MiniLM-L6-v2` |
| `semantic-tier.enabled` / `.confidence-threshold` | `false` / `0.85` |
| `skill-matching.enabled` / `.confidence-threshold` | `false` / `0.80` |
| `semantic-cache.enabled` / `.similarity-threshold` / `.max-size` | `false` / `0.95` / `10000` |
| `confidence.enabled` | `false` |
| `verification.enabled` / `.confidence-threshold-low` / `-high` | `false` / `0.60` / `0.90` |
| `cascade.enabled` / `.quality-threshold` | `false` / `0.70` |
| `feedback.enabled` / `.retention-days` | `false` / `90` |
| `discovery` | `enabled`, `probe-on-startup`, `probe-interval`, `probe-timeout`, `passive-monitoring`, `cache-ttl` |
| `learning` | `min-sample-size` `100`, `confidence-threshold` `0.85`, `analysis-interval` `24h`, `auto-apply` `false` |

The embedding engine needs ONNX Runtime and a model downloaded with
`scripts/download-embedding-model.sh` (to `~/.switchailocal/models/`). Without
them the server logs a warning and disables the semantic tier and cache.

`config.example.yaml` lists `intelligence.discovery.refresh-interval` and
`cache-dir`; those keys are not read.

Details: [Cortex router](/intelligent-systems/cortex-router).

### auto-routing

Scores candidate models when a client asks for `auto`. Restart required.

| Key | Default |
| --- | ------- |
| `enabled` | `false` |
| `max-resolution-ms` | `5ms` |
| `weights` (`availability`, `quota`, `latency`, `success-rate`) | `0.35`, `0.25`, `0.20`, `0.20` (restored if they do not sum to 1) |
| `preferences` | `[]` of `{model, preference, reason}` |
| `providers` | map of `{tier, monthly-budget, model-tiers}` |
| `discovery` | `probe-interval` `15m`, `probe-timeout` `5s`, `cache-ttl` `24h`, plus `enabled`, `probe-on-startup`, `passive-monitoring` |
| `conservation` | `enabled`, `simple-threshold-tokens`, `premium-conservation-at` |
| `lab` | `enabled`, `adaptation-interval`, `max-weight-drift`, `min-observation-window` |
| `intent-matrix` | map of intent to model list |
| `disabled-providers` | providers that are never selected |

Details: [Auto-routing](/api/auto-routing).

### superbrain

Monitoring and self-healing for CLI executions. `enabled: false`,
`mode: disabled` by default. This block uses snake_case keys
(`component_flags`, `stdin_injection`, ...). Live-reloadable.
Details: [Superbrain](/intelligent-systems/superbrain).

### billboard

```yaml
billboard:
  enabled: false
  base-dir: "~/.switchailocal/billboard"
```

When enabled, CLI-provider calls run in `base-dir` and get a system
instruction to use it for file output when no path is given. When disabled,
CLI calls run in an empty `~/.switchailocal/cli-sandbox` folder.

### ampcode

Integration for the Amp coding CLI: Amp's account and thread routes under
`/api/*` are proxied to an upstream, and model requests can be remapped.

| Key | Default | Meaning |
| --- | ------- | ------- |
| `upstream-url` | `""` | Upstream Amp control plane |
| `upstream-api-key` | `""` | Authorization override for upstream calls |
| `restrict-management-to-localhost` | `false` | Only accept those `/api/*` routes from loopback |
| `model-mappings` | `[]` | `{from, to, regex}` rewrites for models Amp requests |
| `force-model-mappings` | `false` | Apply mappings even when a local credential serves the original model |

Legacy top-level keys `amp-upstream-url`, `amp-upstream-api-key`,
`amp-restrict-management-to-localhost` and `amp-model-mappings` are migrated
into this block.

### notifications

Lets clients send Telegram messages through the gateway without holding the
bot token: `POST /v1/notifications/telegram/sendMessage`.

```yaml
notifications:
  telegram:
    enabled: false
    bots:
      - name: "default"
        token: "123456:your-bot-token"
        allowed-chat-ids: [123456789]
```

| Key | Default | Meaning |
| --- | ------- | ------- |
| `telegram.enabled` | `false` | Endpoint answers `503` when off or when `bots` is empty |
| `telegram.bots[].name` | | Selected by the request's `bot` field; `default` when omitted |
| `telegram.bots[].token` | | Bot token (stored as written; no `${VAR}` expansion) |
| `telegram.bots[].allowed-chat-ids` | `[]` (any chat) | Allowed `chat_id` values; others get `403` |

Details: [Notifications](/advanced/notifications).
