---
title: Quickstart
description: Run switchAILocal and make your first request in a few minutes
---

By the end of this page you will have the server running on
`http://localhost:18080` and a successful chat completion.

<Steps>
  <Step title="Get the binary">
    <Tabs>
      <Tab title="Release archive">
        Prebuilt archives exist for macOS Apple Silicon and Linux (x86_64, arm64).

        ```bash
        VERSION=0.6.2
        OS=darwin ARCH=arm64   # or OS=linux ARCH=amd64 / ARCH=arm64
        curl -LO https://github.com/traylinx/switchAILocal/releases/download/v${VERSION}/switchAILocal_${VERSION}_${OS}_${ARCH}.tar.gz
        tar xzf switchAILocal_${VERSION}_${OS}_${ARCH}.tar.gz
        cd switchAILocal_${VERSION}_${OS}_${ARCH}
        ```
      </Tab>
      <Tab title="Docker">
        ```bash
        docker pull ghcr.io/traylinx/switchailocal:0.6.2
        ```

        Create `config.yaml` in the next step, then run:

        ```bash
        docker run -d --name switchailocal -p 18080:18080 \
          -v "$PWD/config.yaml:/app/config.yaml" \
          ghcr.io/traylinx/switchailocal:0.6.2
        ```

        In a container, leave `host` empty (`""`) so the published port works.
        See [Docker deployment](/guides/docker-deployment).
      </Tab>
      <Tab title="From source">
        Needs Go 1.26.9+ with CGO (a C compiler).

        ```bash
        git clone https://github.com/traylinx/switchAILocal.git
        cd switchAILocal
        ./ail.sh setup
        ```

        `setup` builds the binaries, copies `config.example.yaml` to
        `config.yaml` if it does not exist, and installs the `ail` helper in
        `~/bin`. See [Installation](/installation#build-from-source).
      </Tab>
    </Tabs>
  </Step>

  <Step title="Create config.yaml">
    The server reads `config.yaml` from the current directory and exits if it
    is missing. A minimal file:

    ```yaml config.yaml
    host: "127.0.0.1"      # use "" inside Docker
    port: 18080
    auth-dir: "~/.switchailocal"
    api-keys:
      - "sk-your-key"
    ```

    ```bash
    chmod 600 config.yaml
    ```

    <Note>
      `config.example.yaml` documents every option, but it also enables
      providers, virtual models and a test key (`sk-test-123`). If you start
      from it, remove what you do not use and replace the key.
    </Note>
  </Step>

  <Step title="Connect at least one provider">
    <Tabs>
      <Tab title="CLI tool">
        If `gemini`, `claude`, `codex` or `vibe` is installed and logged in, it
        is detected at startup. Nothing to configure.
      </Tab>
      <Tab title="API key">
        ```yaml config.yaml
        gemini-api-key:
          - api-key: "your-gemini-key"

        claude-api-key:
          - api-key: "sk-ant-your-key"

        codex-api-key:
          - api-key: "sk-your-openai-key"
            base-url: "https://api.openai.com/v1"   # required
        ```
      </Tab>
      <Tab title="Local model">
        ```yaml config.yaml
        ollama:
          enabled: true
          base-url: "http://localhost:11434"
          auto-discover: true

        lmstudio:
          enabled: true
          base-url: "http://localhost:1234/v1"
        ```
      </Tab>
    </Tabs>
  </Step>

  <Step title="Start the server">
    ```bash
    ./switchAILocal
    ```

    The first log line prints the version. When the listener is up you see:

    ```text
    API server started successfully on: 127.0.0.1:18080
    Management UI available at: http://localhost:18080/management
    ```

    Check health from another terminal:

    ```bash
    curl http://localhost:18080/health
    # {"status":"ok"}
    ```
  </Step>

  <Step title="Make your first request">
    <CodeGroup>
      ```bash curl
      curl http://localhost:18080/v1/chat/completions \
        -H "Content-Type: application/json" \
        -H "Authorization: Bearer sk-your-key" \
        -d '{
          "model": "geminicli:gemini-2.5-pro",
          "messages": [{"role": "user", "content": "Say hello"}]
        }'
      ```

      ```python Python
      from openai import OpenAI

      client = OpenAI(base_url="http://localhost:18080/v1", api_key="sk-your-key")
      response = client.chat.completions.create(
          model="geminicli:gemini-2.5-pro",
          messages=[{"role": "user", "content": "Say hello"}],
      )
      print(response.choices[0].message.content)
      ```

      ```javascript Node.js
      import OpenAI from "openai";

      const client = new OpenAI({ baseURL: "http://localhost:18080/v1", apiKey: "sk-your-key" });
      const response = await client.chat.completions.create({
        model: "geminicli:gemini-2.5-pro",
        messages: [{ role: "user", content: "Say hello" }],
      });
      console.log(response.choices[0].message.content);
      ```
    </CodeGroup>

    Replace the model with one your providers serve. List them with:

    ```bash
    curl http://localhost:18080/v1/models -H "Authorization: Bearer sk-your-key"
    ```
  </Step>
</Steps>

## Quick tips

<AccordionGroup>
  <Accordion title="Pick a specific provider">
    Prefix the model: `geminicli:`, `claudecli:`, `codex:`, `vibecli:`,
    `ollama:`, `lmstudio:`, `opencode:`, `gemini:`, `claude:`, `switchai:`.
    Without a prefix, any provider that serves that model name may be used.
    See [Provider prefixes](/api/provider-prefixes).
  </Accordion>

  <Accordion title="Stream responses">
    Add `"stream": true` (or `stream=True` in the SDK). Responses arrive as
    server-sent events.
  </Accordion>

  <Accordion title="Run it in the background">
    From a source checkout, `ail start` (or `./ail.sh start`) builds and starts
    the server in the background, writes its PID to `.ail/local.pid` and logs to
    `server.log`. `ail status`, `ail logs -f` and `ail stop` manage it.
  </Accordion>

  <Accordion title="Open the management panel">
    Browse to `http://localhost:18080/management`. With no
    `remote-management.secret-key`, localhost gets in without a password. See
    [Management dashboard](/guides/management-dashboard).
  </Accordion>
</AccordionGroup>

## Common first-run errors

| Message | Fix |
| ------- | --- |
| `failed to read config file: open .../config.yaml: no such file or directory` | Create `config.yaml` in the directory you start from, or pass `-config`. |
| `{"error":"Missing API key"}` / `{"error":"Invalid API key"}` | Send `Authorization: Bearer <key>` with a key from `api-keys`. |
| `bind: address already in use` | Another process owns the port. Change `port` or stop it (`lsof -i :18080`). |
| Empty `/v1/models` | No provider is connected. Install and log in to a CLI, or add a key or local server. |

More in [Troubleshooting](/guides/troubleshooting).
