## Overview

Routing happens in two stages:

1. **Model resolution** turns the `model` field of the request into an ordered list of provider IDs plus the model name to send upstream (`sdk/api/handlers/handlers.go`, `getRequestDetailsWithOperation`).
2. **Credential selection** picks one credential of the first provider, executes the call, and moves on to the next credential or provider if it fails (`sdk/switchailocal/auth/conductor.go`).

## Stage 1: model resolution

The first matching rule wins:

| # | Rule | Example `model` | Result |
|---|------|-----------------|--------|
| 1 | **Explicit provider prefix** (`provider:model`, recognized prefixes only) | `ollama:llama3.2`, `geminicli:gemini-2.5-pro` | Provider `ollama`, model `llama3.2`. `provider:` with nothing after it sends `auto` to that provider. The Lua `on_request` hook still runs and may rewrite model or provider. |
| 2 | **Lua `on_request` hook** (if the plugin system is enabled) | `auto`, `cortex` | A plugin such as `cortex-router` may set `model` and/or `provider`. If it sets a provider, resolution stops here. |
| 3 | **Virtual model** | `ail-compound` | One member is chosen by capability and weight; see [Virtual Models](/advanced/virtual-models). |
| 4 | **Auto-routing** for `auto`, `auto:<intent>`, `cortex` or an empty model | `auto:coding` | The [auto-routing engine](/guides/auto-routing-setup) scores candidates. If it is disabled or fails, the newest available model in the registry is used. |
| 5 | **Registry lookup** | `deepseek-pro`, `team-a/gemini-2.5-pro` | Every provider that has registered this model ID (alias, upstream name, or `prefix/model`). |

If nothing matches, the request fails with `400 unknown provider for model <name>`.

### Recognized colon prefixes

`switchai`, `gemini`, `geminicli`, `claude`, `claudecli`, `codex`, `ollama`, `vibecli`, `openai`, `openai-compat`, `opencode` (`internal/util/provider.go`).

- A prefix pin fails fast: an unknown prefix cannot occur (it is treated as a model name), and an API provider with no registered models returns `503 Provider '<id>' is not active`. Local providers (`geminicli`, `claudecli`, `vibecli`, `ollama`, `opencode`) are always accepted.
- Anything else with a colon, such as `groq:gpt-oss-20b` or `minimax:MiniMax-M3`, is **not** a prefix. It works only if some credential registered that exact string, which is why `openai-compatibility` examples use colon-shaped **aliases**.
- Slash-style IDs (`team-a/model`) come from the `prefix:` option on a credential; see [Providers](/concepts/providers#how-models-become-routable).

### Model name suffixes

Before resolution, the model name is normalized:

- `name(<number>)` sets a thinking budget, `name(high|medium|low)` sets a reasoning effort, and the suffix is removed. Example: `gemini-2.5-pro(8192)`.
- A trailing `-vision` is stripped if the name with the suffix is not itself a registered or virtual model (some editors append it to enable image upload).

## Stage 2: credential selection

For each provider in the list, the auth manager:

1. Collects that provider's credentials that are not disabled and that have registered the requested model. Local credentials (Ollama, LM Studio, OpenCode, detected CLIs) skip the model check.
2. Drops credentials that are cooling down for this model.
3. Lets the **selector** pick one.
4. Executes the call. On failure it marks the credential (see [Cooldowns](#quota-cooldowns)) and tries the next credential, then the next provider.

### Selector strategy

```yaml config.yaml
routing:
  strategy: "round-robin"   # default; "fill-first" (aliases: "fillfirst", "ff")
```

| Strategy | Behaviour | Use it when |
|----------|-----------|-------------|
| `round-robin` | Rotates through available credentials. One cursor per `provider:model` pair. | You want to spread load across keys or accounts. |
| `fill-first` | Always picks the first available credential; moves on only while it is cooling down. | You want to use up one subscription before touching the next (rolling message caps). |

Example: three OpenAI-compatible keys sharing load.

```yaml config.yaml
routing:
  strategy: "round-robin"

openai-compatibility:
  - name: "groq"
    base-url: "https://api.groq.com/openai/v1"
    api-key-entries:
      - api-key: "gsk_key_one"
      - api-key: "gsk_key_two"
      - api-key: "gsk_key_three"
    models:
      - name: "openai/gpt-oss-20b"
        alias: "gpt-oss-20b"
```

Changing `routing.strategy` is picked up on config reload.

### Multiple providers for the same model

When several providers registered the same model ID, the list from stage 1 contains all of them. The starting provider rotates per model on every request, so traffic alternates between providers; the others act as fallbacks within the same request.

### Circuit breaker

Before execution, providers whose circuit breaker is open are skipped. If all are open the request fails with `503 all downstream providers (...) are currently overloaded or open`. The breaker is off unless `performance.circuit-breaker.enabled: true`; when enabled the code defaults are 5 consecutive failures and a 30 s reset timeout (the example config uses 3 and `5m`). Failures (5xx and 429) are only recorded for requests resolved by the auto-routing engine, so in practice the breaker opens only from `auto` traffic. See [Failover](/advanced/failover).

### Retries

```yaml config.yaml
request-retry: 3          # extra passes over the provider list
max-retry-interval: 30    # seconds; 0 disables waiting for cooldowns
```

After every provider and credential has failed, the manager may wait for the credential whose cooldown ends soonest and try again, up to `request-retry` extra passes. It only waits if that cooldown ends within `max-retry-interval` seconds. With the default `max-retry-interval: 0`, no waiting retries happen.

For streaming, failures before the first byte are retried up to `streaming.bootstrap-retries` times on 401, 402, 403, 408, 429 and 5xx. The code default is `0` (off); the example config sets `2`.

### Quota cooldowns

A failed call puts the credential in cooldown **for that model only**; it keeps serving other models. A success clears the state.

| Upstream status | Cooldown for that credential + model |
|-----------------|--------------------------------------|
| 429 | Upstream retry hint if present, otherwise exponential backoff: 1 s, 2 s, 4 s, ... up to 30 min |
| 401, 402 | 30 minutes |
| 403 | 3 seconds (treated as a transient WAF/bot block) |
| 404 | 12 hours |
| 408, 500, 502, 503, 504 | 1 minute |
| other | none |

Set `disable-cooling: true` to turn off the 429 backoff (the other cooldowns still apply).

<Note>
`quota-exceeded.switch-project` and `quota-exceeded.switch-preview-model` are accepted and editable through the Management API, but no routing code reads them in this release.
</Note>

### Response headers

Auto-routed requests add `X-Auto-Routed: true`, `X-Selected-Model` and `X-Selected-Provider`. Virtual-model requests return the public model name in the body; the chosen member is only visible in the logs.

## Model visibility

`GET /v1/models` lists exposed virtual models and registered models, minus anything marked `visibility: private` / `expose: false`. If any listed ID starts with `ail-`, only `ail-*` IDs are returned. Filter by modality with `?modality=text|image|audio|embedding|vision`. A request with a `User-Agent` starting with `claude-cli` gets the Anthropic-style model list instead.

## Troubleshooting

<AccordionGroup>
  <Accordion title="400 unknown provider for model X">
    No credential registered `X`. Check `GET /v1/models`, the `models:` lists in `config.yaml`, and `excluded-models`. Remember that `something:X` is only a prefix pin for the recognized prefixes.
  </Accordion>
  <Accordion title="503 Provider 'gemini' is not active">
    You pinned an API provider with no registered models. Add `models:` to its config block.
  </Accordion>
  <Accordion title="Requests always hit the same key with round-robin">
    The cursor is per provider and model; different models rotate independently. Keys that are cooling down are skipped, so with one healthy key every request lands on it.
  </Accordion>
  <Accordion title="model_cooldown errors">
    Every credential for that provider and model is cooling down after 429s. Wait, add credentials, or set `max-retry-interval` so the server waits instead of failing.
  </Accordion>
</AccordionGroup>
