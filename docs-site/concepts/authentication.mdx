## Two kinds of credentials

| | Who presents it | Configured in |
|---|---|---|
| **Client keys** | Your apps and tools, when calling switchAILocal | `api-keys:` |
| **Upstream credentials** | switchAILocal, when calling a provider | provider blocks in `config.yaml`, OAuth token files in `auth-dir`, or nothing for local CLIs/servers |

The Management API has its own key (`remote-management.secret-key`); see [Security](/configuration/security).

## Client keys

```yaml config.yaml
api-keys:
  - "sk-test-123"
  - "sk-another-client"
```

A request to any `/v1/*` route is accepted if one of these carries a configured key:

| Location | Example |
|----------|---------|
| `Authorization` header | `Authorization: Bearer sk-test-123` |
| `X-Api-Key` header (Anthropic clients) | `x-api-key: sk-test-123` |
| `X-Goog-Api-Key` header (Gemini clients) | `x-goog-api-key: sk-test-123` |
| `key` query parameter | `/v1beta/models/...?key=sk-test-123` |
| `auth_token` query parameter | `?auth_token=sk-test-123` |

Failures return `401 {"error": "Missing API key"}` or `401 {"error": "Invalid API key"}`.

<Warning>
If `api-keys` is empty, **every request is accepted** (any key or none). This is convenient on a laptop bound to `127.0.0.1`, unsafe on a shared network. Set `host: "127.0.0.1"` or configure keys.
</Warning>

The WebSocket relay at `/v1/ws` checks the same keys while `ws-auth: true` (the default).

## Upstream credentials

### API keys in `config.yaml`

```yaml config.yaml
gemini-api-key:
  - api-key: "your-gemini-key"
    models: [{name: "gemini-2.5-flash"}]
claude-api-key:
  - api-key: "sk-ant-your-key"
    models: [{name: "claude-sonnet-4-5-20250929", alias: "sonnet"}]
openai-compatibility:
  - name: "groq"
    base-url: "https://api.groq.com/openai/v1"
    api-key-entries:
      - api-key: "gsk_your_key"
```

These stay in `config.yaml` and are hot-reloaded when the file changes. They are never copied into `auth-dir`. Config values are taken literally; `${VAR}` is **not** expanded.

### Local providers

CLI tools (`gemini`, `claude`, `codex`, `vibe`) found on `PATH`, and enabled `ollama` / `lmstudio` / `opencode` blocks, get an implicit credential. CLIs use their own login.

### OAuth logins

Each login flag runs a browser flow (PKCE where the provider supports it), writes a JSON token file into `auth-dir`, and exits.

| Flag | Provider ID | Callback | Refreshed | Required env vars |
|------|-------------|----------|-----------|-------------------|
| `--login` | `geminicli` | `localhost:8085` | by the OAuth2 token source | `GEMINI_CLIENT_ID`, `GEMINI_CLIENT_SECRET` |
| `--codex-login` | `codex` | `localhost:1455` | 5 days before expiry | — |
| `--claude-login` | `claudecli` | `localhost:54545` | 4 hours before expiry | — |
| `--qwen-login` | `qwen` | device code | 3 hours before expiry | `QWEN_CLIENT_ID` |
| `--iflow-login` | `iflow` | `localhost:11451` | 24 hours before expiry | `IFLOW_CLIENT_ID`, `IFLOW_CLIENT_SECRET` |
| `--iflow-cookie` | `iflow` | paste a cookie | — | — |
| `--antigravity-login` | `antigravity` | `localhost:51121` | yes | `ANTIGRAVITY_CLIENT_ID`, `ANTIGRAVITY_CLIENT_SECRET` |
| `--vertex-import <file>` | `vertex` | — | service-account JWT | — |

```bash
./switchAILocal --codex-login --no-browser   # print the URL instead of opening a browser
./switchAILocal --login --project_id my-gcp-project
```

On a remote host, forward the callback port first, for example `ssh -L 1455:localhost:1455 user@host`. The same flows can be started from the Management API (`GET /v0/management/{anthropic,codex,gemini-cli,antigravity,qwen,iflow}-auth-url`) and the dashboard.

<Note>
Some login-based providers are not fully routable in this release (no models registered, or no matching executor). See [Providers](/concepts/providers#oauth-and-login-based-providers) before relying on one.
</Note>

### Token files

```text
~/.switchailocal/              # auth-dir (default)
├── you@example.com-my-project.json   # --login
├── codex-you@example.com.json
├── claude-you@example.com.json
├── antigravity-you@example.com.json
└── cache/discovery/           # model discovery cache
```

- The provider is taken from the file's `"type"` field (`gemini` → `geminicli`, `claude` → `claudecli`, `vibe` → `vibecli`).
- Optional fields `"prefix"` and `"proxy_url"` in a token file set a model prefix and a per-credential proxy.
- Files are written with `0600` permissions. Adding, editing or deleting a file is picked up without a restart.
- A Gemini login that activated several Google Cloud projects is split into one virtual credential per project, which the selector rotates like separate keys.

### Token refresh

A background loop checks credentials every 5 seconds and refreshes OAuth tokens ahead of expiry (lead times above). A refresh that is still pending is retried after 1 minute; a failed refresh after 5 minutes. A credential that keeps failing upstream is put in cooldown (401/402: 30 minutes); see [Routing](/concepts/routing#quota-cooldowns).

## Storage backends

By default credentials live in `auth-dir` on disk. For shared or containerized setups, environment variables switch the token store (and the config file) to a remote backend. The first configured one wins in this order: Postgres, object store, Git.

<Tabs>
  <Tab title="Postgres">
    ```bash
    export PGSTORE_DSN="postgres://user:password@db.example.com:5432/switchai"
    export PGSTORE_SCHEMA="public"          # optional
    export PGSTORE_LOCAL_PATH="/var/lib/switchai"   # optional local spool
    ```
    Uses tables `config_store` and `auth_store`. On first start the config is bootstrapped from `config.example.yaml`.
  </Tab>
  <Tab title="Object store (S3-compatible)">
    ```bash
    export OBJECTSTORE_ENDPOINT="https://s3.example.com"   # http:// disables TLS
    export OBJECTSTORE_BUCKET="switchai"
    export OBJECTSTORE_ACCESS_KEY="your-access-key"
    export OBJECTSTORE_SECRET_KEY="your-secret-key"
    export OBJECTSTORE_LOCAL_PATH="/var/lib/switchai"      # optional
    ```
    Stores `config/config.yaml` and token files under `auths/` in the bucket (path-style addressing).
  </Tab>
  <Tab title="Git">
    ```bash
    export GITSTORE_GIT_URL="https://git.example.com/you/switchai-auth.git"
    export GITSTORE_GIT_USERNAME="you"
    export GITSTORE_GIT_TOKEN="your-access-token"
    export GITSTORE_LOCAL_PATH="/var/lib/switchai"   # optional
    ```
    Clones the repository and commits token changes back.
  </Tab>
</Tabs>

These variables can also be set in a `.env` file in the working directory.

## Troubleshooting

<AccordionGroup>
  <Accordion title="401 Missing API key">
    The client sent no key in any supported location. Check the header name, and for Claude Code use `ANTHROPIC_AUTH_TOKEN` (Bearer) or `ANTHROPIC_API_KEY` (`x-api-key`).
  </Accordion>
  <Accordion title="Login opens a browser on the wrong machine">
    Use `--no-browser`, open the printed URL locally, and forward the callback port with SSH.
  </Accordion>
  <Accordion title="--login fails immediately">
    `GEMINI_CLIENT_ID` and `GEMINI_CLIENT_SECRET` are not set. For most users the `gemini` CLI is simpler: install it, log in once, and switchAILocal picks it up.
  </Accordion>
  <Accordion title="Credential shows as cooling down after a 401">
    The upstream rejected the token. Re-run the login (or fix the API key); the cooldown is 30 minutes otherwise.
  </Accordion>
  <Accordion title="insecure permissions warning at startup">
    The config file is readable by other users. `chmod 600 config.yaml`.
  </Accordion>
</AccordionGroup>
