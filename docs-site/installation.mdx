switchAILocal is a single Go binary plus a `config.yaml`. Pick the install path
that matches your platform.

## Platform support

| Platform | Release archive | Docker image | Source build |
| -------- | --------------- | ------------ | ------------ |
| macOS, Apple Silicon | `darwin_arm64` | yes | yes |
| macOS, Intel | not published | yes | yes |
| Linux x86_64 | `linux_amd64` | yes (`linux/amd64`) | yes |
| Linux arm64 | `linux_arm64` | yes (`linux/arm64`) | yes |
| Windows | not published | yes | WSL |

Optional, depending on the providers you use:

- The `gemini`, `claude`, `codex` or `vibe` CLI, installed and logged in.
- Ollama, LM Studio or an OpenCode server running locally.

## Release archive

Every GitHub release ships one archive per platform plus `checksums.txt`.

<Steps>
  <Step title="Download and verify">
    ```bash
    VERSION=0.6.2
    OS=darwin ARCH=arm64   # or OS=linux ARCH=amd64 / ARCH=arm64
    BASE=https://github.com/traylinx/switchAILocal/releases/download/v${VERSION}
    ARCHIVE=switchAILocal_${VERSION}_${OS}_${ARCH}.tar.gz

    curl -LO "$BASE/$ARCHIVE"
    curl -LO "$BASE/checksums.txt"
    grep "$ARCHIVE" checksums.txt | shasum -a 256 -c -   # Linux: sha256sum -c -
    ```
  </Step>

  <Step title="Unpack">
    ```bash
    tar xzf "$ARCHIVE"
    cd switchAILocal_${VERSION}_${OS}_${ARCH}
    ```

    The folder contains:

    | File | Purpose |
    | ---- | ------- |
    | `switchAILocal` | The gateway |
    | `bridge-agent` | Optional host-side CLI bridge for Docker setups ([details](#bridge-agent)) |
    | `config.example.yaml` | Annotated reference of every config section |
    | `managed-server/` | Optional updater for Linux Compose hosts ([guide](/guides/managed-server)) |
    | `README.md`, `LICENSE`, `CHANGELOG.md` | Docs |
  </Step>

  <Step title="Create config.yaml and run">
    ```bash
    cat > config.yaml <<'EOF'
    host: "127.0.0.1"
    port: 18080
    auth-dir: "~/.switchailocal"
    api-keys:
      - "sk-your-key"
    EOF
    chmod 600 config.yaml
    ./switchAILocal
    ```

    Optionally put the binary on your `PATH` (`sudo install switchAILocal /usr/local/bin/`).
    It still reads `config.yaml` from the directory you start it in, or from
    `-config`.
  </Step>
</Steps>

<Note>
  The release archive does not include the management panel file. To use
  `/management`, place `management.html` in a `static/` folder next to your
  `config.yaml`:

  ```bash
  mkdir -p static
  curl -L -o static/management.html \
    https://raw.githubusercontent.com/traylinx/switchAILocal/v0.6.2/static/management.html
  ```
</Note>

<Tip>
  If macOS blocks a binary you downloaded with a browser, remove the quarantine
  flag: `xattr -d com.apple.quarantine switchAILocal`.
</Tip>

## Docker

Images are published to GitHub Container Registry for `linux/amd64` and
`linux/arm64`, tagged by version without a `v` (for example `0.6.2`).

```bash
docker run -d --name switchailocal \
  -p 18080:18080 \
  -v "$PWD/config.yaml:/app/config.yaml" \
  -v "$HOME/.switchailocal:/home/appuser/.switchailocal" \
  ghcr.io/traylinx/switchailocal:0.6.2
```

Set `host: ""` in a container config. Compose files, volumes, permissions and
networking are covered in [Docker deployment](/guides/docker-deployment).

## Build from source

Requires Go 1.26.10 or newer with CGO enabled (the embedding engine links
ONNX Runtime through cgo), so a C compiler must be installed.

<Tabs>
  <Tab title="ail.sh setup">
    ```bash
    git clone https://github.com/traylinx/switchAILocal.git
    cd switchAILocal
    ./ail.sh setup
    ```

    `setup` runs six steps:

    1. Checks for Go; on macOS it installs Go and Docker with Homebrew if Go is missing.
    2. Builds `switchAILocal` and `bridge-agent` in the repository root.
    3. Copies `config.example.yaml` to `config.yaml` unless one exists.
    4. Creates the `.ail/` state folder.
    5. On macOS, installs and loads the bridge launchd job
       `~/Library/LaunchAgents/com.traylinx.switchailocal.bridge.plist`.
    6. Writes the `ail` wrapper to `~/bin/ail` and adds `~/bin` to `PATH` in
       `~/.zshrc` (or `~/.bashrc`).

    Then start the server from anywhere with `ail start`.

    <Warning>
      `config.yaml` created by `setup` is a copy of `config.example.yaml`. It
      enables example providers and the test key `sk-test-123`. Edit it before
      use.
    </Warning>
  </Tab>
  <Tab title="Manual build">
    ```bash
    git clone https://github.com/traylinx/switchAILocal.git
    cd switchAILocal
    go build -o switchAILocal ./cmd/server
    ```

    Embed version information the same way release builds do:

    ```bash
    VERSION=$(git describe --tags --always)
    COMMIT=$(git rev-parse HEAD)
    BUILD_DATE=$(date -u +%Y-%m-%dT%H:%M:%SZ)
    CGO_ENABLED=1 go build \
      -ldflags="-s -w -X main.Version=${VERSION} -X main.Commit=${COMMIT} -X main.BuildDate=${BUILD_DATE}" \
      -o switchAILocal ./cmd/server
    ```

    Build the optional bridge with `go build -o bridge-agent ./cmd/bridge-agent`.
  </Tab>
</Tabs>

Check the build: every invocation prints the version first.

```bash
./switchAILocal -h | head -1
# switchAILocal Version: 0.6.2, Commit: ..., BuiltAt: ...
```

There is no `--version` flag.

### ail.sh reference

`ail.sh` (or the `ail` wrapper after `setup`) manages a source checkout. It
always runs from the repository folder.

| Command | What it does |
| ------- | ------------ |
| `setup` | First-time install (see above) |
| `start` | `go build` the server, start it in the background, PID in `.ail/local.pid`, output in `server.log` |
| `stop` | Stop the background server |
| `restart` | `stop` then `start` |
| `status` | Local PID status, `docker compose ps`, bridge launchd status |
| `logs` | Last 50 lines of `server.log` (`-f` to follow) |
| `check` | Verify Go and Docker are installed |
| `install` | Install Go and Docker with Homebrew (macOS only) |
| `bridge` | Show whether the bridge launchd job is loaded (macOS) |
| `help` | Usage |

<Warning>
  `ail bridge start` and `ail bridge stop` do not reach the bridge in 0.6.2: the
  argument parser treats `start`/`stop` as the main command, so they start or
  stop the **server**. Manage the bridge job with `launchctl` directly:

  ```bash
  launchctl unload ~/Library/LaunchAgents/com.traylinx.switchailocal.bridge.plist   # stop
  launchctl load -w ~/Library/LaunchAgents/com.traylinx.switchailocal.bridge.plist  # start
  ```
</Warning>

| Option | Meaning |
| ------ | ------- |
| `-d`, `--docker` | Act on the Docker Compose service instead of the local process (`start`, `stop`, `restart`, `logs`) |
| `-b`, `--build` | With `start -d`: rebuild the image (`docker compose up -d --build`) |
| `-f`, `--follow` | With `start` or `logs`: follow log output |

```bash
ail start -f          # build, start, follow server.log
ail start -d --build  # docker compose up -d --build --remove-orphans
ail logs -d -f        # docker compose logs -f
```

### Bridge agent

`bridge-agent` lets a containerised gateway run the `gemini`, `claude`, `vibe`
or `codex` CLI on the host. The gateway forwards CLI executions to it when the
`REMOTE_COMMAND_HOST` environment variable is set (the bundled
`docker-compose.yml` sets it to `http://host.docker.internal:18888`).

| Setting | Default | Meaning |
| ------- | ------- | ------- |
| `BRIDGE_AGENT_SECRET` (env) | none, required | Bearer token the agent demands on `POST /run`; it exits at startup without it |
| `BRIDGE_PORT` (env) | `18888` | Port when `-listen-address` is not set |
| `-listen-address` (flag) | `127.0.0.1:<BRIDGE_PORT>` | Full listen address |

<Warning>
  In 0.6.2 the bridge path is not usable out of the box: the launchd job that
  `ail.sh setup` installs does not set `BRIDGE_AGENT_SECRET`, so the agent exits
  and launchd keeps restarting it, and the gateway does not send that secret
  with its requests, so the agent rejects them. If you do not run the gateway
  in Docker, unload the job with the `launchctl unload` command above. In
  Docker, clear `REMOTE_COMMAND_HOST` so CLIs installed in the container run
  directly.
</Warning>

### Rebuild the management panel

The panel source lives in `frontend/` and builds to a single
`static/management.html`.

```bash
cd frontend && npm install && cd ..
./ail_ui.sh            # runs `npm run build` in frontend/, writes static/management.html
```

`ail_ui.sh` then opens `http://localhost:18080/management` on macOS.

## npx

The npm package `@traylinx/switchailocal` is a small launcher that downloads a
release binary and runs it with your arguments.

```bash
npx @traylinx/switchailocal                  # latest GitHub release
npx @traylinx/switchailocal --version=v0.6.2 # a specific release tag
```

- `--version` is read by the launcher; every other argument is passed to
  `switchAILocal`.
- Binaries are cached per version in `~/Library/Caches/switchailocal` (macOS),
  `$XDG_CACHE_HOME/switchailocal` or `~/.cache/switchailocal` (Linux), or
  `%LOCALAPPDATA%\switchailocal` (Windows).
- The binary runs in your current directory, so `config.yaml` must exist there
  (or pass `-config`). The launcher does not create one.

<Warning>
  Known issue: the launcher expects the binary at the top level of the archive,
  but current release archives place it inside a versioned folder, so
  extraction fails. It also requests assets that are not published
  (`darwin_amd64`, Windows). Until the launcher is fixed, use the
  [release archive](#release-archive) or [Docker](#docker).
</Warning>

## Files switchAILocal creates

| Path | Created by | Contents |
| ---- | ---------- | -------- |
| `auth-dir` (`~/.switchailocal` in the example config) | Logins, management panel | Provider credential files such as `claude-<email>.json`, `codex-<email>.json`, `ollama-local.json` |
| `~/.switchailocal/cli-sandbox/` | CLI providers | Empty working folder for CLI calls (unless `billboard` is enabled) |
| `~/.switchailocal/cache/discovery/` | Model discovery | Cached model lists |
| `.switchailocal/steering`, `.switchailocal/hooks` (relative to the start folder) | Startup | Rule folders for steering and hooks |
| `logs/` (relative to the start folder, or `$WRITABLE_PATH/logs`) | `logging-to-file`, `request-log` | `main.log` and request logs |
| `static/management.html` next to `config.yaml` | Panel updater | Management panel |

## Upgrade

- **Archive:** download the new archive, replace the binary, keep your
  `config.yaml` and `auth-dir`. Read `CHANGELOG.md` for config changes.
- **Docker:** change the image tag (for example `0.6.2` to the next version) and
  recreate the container.
- **Source:** `git pull`, then `ail restart` (rebuilds) or rebuild manually.
- **Managed Linux servers:** see [Managed server updates](/guides/managed-server).

## Verify the installation

```bash
curl http://localhost:18080/health
# {"status":"ok"}

curl http://localhost:18080/v1/models -H "Authorization: Bearer sk-your-key"
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="failed to read config file: ... no such file or directory">
    The server looks for `config.yaml` in the current directory. Create it, `cd`
    to its folder, or pass `-config /absolute/path/config.yaml`.
  </Accordion>
  <Accordion title="invalid config path: ...">
    `-config` paths may not contain `..` or `~`, and absolute paths must be under
    your home directory, `/etc/`, `/usr/` or `/var/`. Use `$HOME/...` (the shell
    expands it) instead of a quoted `~`.
  </Accordion>
  <Accordion title="Go build fails">
    Check `go version` (1.26.10+ required by `go.mod`) and that a C compiler is
    available (`CGO_ENABLED=1`). Then retry `go mod download`.
  </Accordion>
  <Accordion title="bind: address already in use">
    Another process owns the port. Find it with `lsof -i :18080`, or change
    `port` in `config.yaml`.
  </Accordion>
</AccordionGroup>
