title: Heartbeat Monitor
description: Background health checks for configured providers, exposed through the management API and the hooks event bus

The heartbeat monitor runs in the background and probes each configured provider on a fixed interval. It records whether each one is `healthy`, `degraded` or `unavailable`. Results are available from `GET /v0/management/heartbeat/status`, and state changes are published as [hook events](/intelligent-systems/hooks).

<Note>
Heartbeat results are informational. In 0.6.2 they don't feed the request router. Live failover is handled by the circuit breaker and retries. See [Failover](/advanced/failover).
</Note>

## When to use it

- You want to know that a provider key was revoked or a local server stopped before a user request fails.
- You want a webhook or log line when a provider becomes unreachable, using the `provider_unavailable` or `health_check_failed` hook events.

## Minimal working config

```yaml config.yaml
heartbeat:
  enabled: true
  interval: "5m"
  timeout: "5s"
```

Restart the server. The log shows `Registered N provider health checkers` and `Heartbeat Monitor started successfully`. The first check cycle runs right away.

## What gets checked

Checkers are registered once at startup from your provider configuration:

| Provider config | Checker name | Probe | Status rules |
|---|---|---|---|
| `ollama.enabled: true` | `ollama` | `GET <base-url>/api/tags` | 200 is healthy and reports `models_count`. Anything else is a failed attempt. |
| First `gemini-api-key` entry | `gemini` | `GET https://generativelanguage.googleapis.com/v1beta/models` | See the API rules below |
| First `claude-api-key` entry | `claude` | `GET https://api.anthropic.com/v1/models` | API rules |
| First `switchai-api-key` entry | `switchai` | `GET <base-url>/models` | API rules |
| Every `openai-compatibility` entry | the entry's `name` | `GET <base-url>/models` with the first key | API rules |
| `lmstudio.enabled: true` | `lmstudio` | `GET <base-url>/models` | API rules |

API rules: 401 or 403 means `degraded` ("Authentication failed"). 5xx means `unavailable`. Any other status, including 404 and 429, counts as `healthy`. Network errors and timeouts count as failed attempts. After `retry-attempts + 1` failed attempts the provider is marked `unavailable`.

CLI providers (`geminicli`, `claudecli`, `codex`, `vibe`), OAuth providers, `codex-api-key` and `vertex-api-key` aren't checked.

## Example request

```bash
curl http://localhost:18080/v0/management/heartbeat/status \
  -H "X-Management-Key: $MANAGEMENT_KEY"
```

```json
{
  "enabled": true,
  "running": true,
  "providers": {
    "ollama": {
      "provider": "ollama",
      "status": "healthy",
      "last_check": "2026-11-08T10:20:00Z",
      "response_time": 4120000,
      "models_count": 7,
      "quota_used": 0,
      "quota_limit": 0
    },
    "groq": {
      "provider": "groq",
      "status": "degraded",
      "last_check": "2026-11-08T10:20:00Z",
      "response_time": 183000000,
      "models_count": 0,
      "quota_used": 0,
      "quota_limit": 0,
      "error_message": "Authentication failed"
    }
  },
  "stats": {
    "start_time": "2026-11-08T10:00:00Z",

```

`response_time` is a Go duration in nanoseconds. When `heartbeat.enabled` is false, the endpoint returns `{"enabled": false, "message": "Heartbeat monitor is disabled"}`.

## Configuration reference

| Key | Default | Validation and notes |
|---|---|---|
| `heartbeat.enabled` | `false` | Opt-in |
| `heartbeat.interval` | `5m` | Minimum `30s`. Shorter or invalid values reset to `5m`. |
| `heartbeat.timeout` | `5s` | Minimum `1s`. Per-check context deadline. Each HTTP probe also has a fixed 5 s client timeout. |
| `heartbeat.retry-attempts` | `2` | Clamped to 0–5 |
| `heartbeat.retry-delay` | `1s` | Minimum `100ms` |
| `heartbeat.max-concurrent-checks` | `10` | Clamped to 1–50 |
| `heartbeat.quota-warning-threshold` | `0.80` | See the note below |
| `heartbeat.quota-critical-threshold` | `0.95` | Raised above the warning threshold if needed |
| `heartbeat.auto-discovery` | `true` | Reported in the start event only. No discovery runs from heartbeat in 0.6.2. |
| `heartbeat.providers.<name>.*` | — | Accepted and validated, but per-provider overrides aren't applied in 0.6.2 |

<Note>
Quota thresholds only fire when a checker reports `quota_used` and `quota_limit`. None of the built-in checkers fill these fields, so `quota_warning` and `quota_exceeded` events don't occur in 0.6.2.
</Note>

## Events

The monitor publishes these events on the internal event bus. [Hooks](/intelligent-systems/hooks) can subscribe to them.

| Heartbeat event | Hook event | When |
|---|---|---|
| Provider status changes to unavailable | `provider_unavailable` | All attempts failed or the probe returned 5xx |
| A single probe attempt fails | `health_check_failed` | Network error, timeout, or an unexpected Ollama status, once per attempt |
| Quota thresholds crossed | `quota_warning`, `quota_exceeded` | Not emitted in 0.6.2 (see above) |

Changes to `healthy` or `degraded` aren't forwarded to hooks.

## Related settings that are not the heartbeat monitor

- `streaming.keepalive-seconds` (default 15) sends SSE `: keep-alive` comments on streaming responses. It is unrelated to provider health.
- `GET /health` is a liveness probe for switchAILocal itself and always returns `{"status": "ok"}`.
- `GET /v0/management/metrics` returns [Superbrain](/intelligent-systems/superbrain) counters, not heartbeat data.

## Troubleshooting

<AccordionGroup>
  <Accordion title="The status endpoint returns an empty providers map">
    The first cycle may still be running. Wait a few seconds. If it stays empty, check `Registered 0 provider health checkers` in the log. Only the provider types in the table above get checkers.
  </Accordion>
  <Accordion title="A provider shows degraded with 'Authentication failed'">
    The `/models` probe returned 401 or 403. Check the key in `config.yaml`. For `openai-compatibility` entries only the first `api-key-entries` key is probed.
  </Accordion>
  <Accordion title="A provider that rejects requests still shows healthy">
    The probe only checks that `/models` doesn't return 401, 403 or 5xx. A 404 or 429 still counts as healthy. To confirm a provider really works, send it a small chat completion.
  </Accordion>
  <Accordion title="My interval setting is ignored">
    Values below `30s` reset to `5m`. Use a Go duration string such as `"2m"`.
  </Accordion>
</AccordionGroup>
