The memory system records one routing decision per proxied request (requested model, selected model, latency, success or error) as JSONL on disk. It also keeps daily logs, computes analytics every 24 hours, and comes with a `switchAILocal memory` CLI for inspection, backup and reset.

<Note>
**What it does not do in 0.6.2.** The user-preference learning and provider-quirk tracking in `internal/memory` are only called by components that aren't on the request path. `memory preferences` will report "No preferences learned yet", and `provider-quirks.md` stays a template. Recorded decisions don't influence routing.
</Note>

## When to use it

- You want a local audit trail of which model actually served each request and whether it succeeded.
- You want per-provider and per-model success and latency summaries without running an external metrics stack.

For high-volume metrics, prefer Prometheus (`observability.metrics`) and request events (`observability.request-events`). See [Configuration](/configuration/overview).

## Minimal working config

```yaml config.yaml
memory:
  enabled: true
  base-dir: "/home/you/.switchailocal/memory"   # use an absolute path, see below
  retention-days: 90
  max-log-size-mb: 100
  compression: true
```

Restart the server. On startup you should see `Memory System initialized successfully`.

<Warning>
**Use an absolute `base-dir`.** The server doesn't expand `~` and resolves relative paths against its working directory. The default is `.switchailocal/memory`, relative to wherever you started the server. A value like `~/.switchailocal/memory` creates a directory literally named `~` in the working directory.
</Warning>

## Example

Send any request, then inspect the log:

```bash
curl http://localhost:18080/v1/chat/completions \
  -H "Authorization: Bearer sk-test-123" \
  -H "Content-Type: application/json" \
  -d '{"model": "ollama:qwen:0.5b", "messages": [{"role": "user", "content": "hi"}]}'

tail -n 1 /home/you/.switchailocal/memory/routing-history.jsonl
```

```json
{
  "timestamp": "2026-11-08T10:15:02Z",
  "api_key_hash": "sha256:3f1c...e9a2",
  "request": {"model": "ollama:qwen:0.5b", "intent": "", "content_hash": "", "content_length": 0},
  "routing": {"tier": "reflex", "selected_model": "qwen:0.5b", "confidence": 1, "latency_ms": 812},
  "outcome": {"success": true, "response_time_ms": 815, "quality_score": 0}
}
```

What each field holds:

- `api_key_hash` is `sha256:` plus the hex SHA-256 of the client API key. With no access provider configured, the hash of the string `anonymous_local_user` is used.
- `request.model` is the model string the client sent.
- `routing.selected_model` is the model name after prefix stripping and alias resolution.
- `routing.tier` is a rough label taken from the provider name: `reflex` for `ollama` and `lmstudio`, `cognitive` for `openai`, `anthropic` and `google`, `semantic` for everything else.
- `latency_ms` is the time the upstream call took. `response_time_ms` is measured from the start of request handling.
- Prompt and response content are never stored.

## Known limitation: which decisions get stored

Every decision is validated before it is written, and invalid ones are dropped with a `Failed to record routing decision` error in the log. In 0.6.2 two rules reject many real requests:

| Rule | Effect |
|---|---|
| `selected_model` must match `name:tag` (`^[a-zA-Z0-9_-]+:[a-zA-Z0-9_.-]+$`) | Names without a colon, such as `MiniMax-M3` or `llama3.2`, are rejected. Names whose part before the colon contains a dot are also rejected. `qwen:0.5b`, `gpt-oss:20b` and colon-style aliases like `alibaba:glm-5.2` pass. |
| `latency_ms` ≤ 60000, `response_time_ms` ≤ 300000 | Very long generations are rejected. |

In practice the history fills reliably for Ollama models with tags and for aliases written as `provider:model`.

## CLI

The CLI runs offline against the files on disk. It doesn't need a running server.

```bash
switchAILocal memory init
switchAILocal memory status
switchAILocal memory history [--limit 100] [--api-key-hash sha256:...]
switchAILocal memory preferences --api-key sk-test-123     # or --api-key-hash
switchAILocal memory export [--output backup.tar.gz]
switchAILocal memory reset --confirm
```

| Command | Behavior |
|---|---|
| `init` | Creates the directory layout below. Doesn't need `memory.enabled`. |
| `status` | Totals, users, disk usage, oldest and newest decision, daily-log stats |
| `history` | Most recent decisions, 100 by default |
| `preferences` | Learned preferences for one key. Empty in 0.6.2. |
| `export` | Writes a `.tar.gz` of the whole memory directory. Default name: `switchailocal-memory-<timestamp>.tar.gz` |
| `reset` | Without `--confirm`, prints a warning and stops. With it, writes `memory-backup-before-reset-<timestamp>.tar.gz` to the current directory and then deletes the memory directory. |

<Warning>
**The CLI and the server may look at different directories.** The CLI reads `config.yaml` from the **current directory** and uses `<auth-dir>/memory`. It ignores `memory.base-dir` and doesn't expand `~` in `auth-dir`. Without a `config.yaml` in the current directory it uses `~/.switchailocal/memory`.

To make both agree, set absolute paths and run the CLI from the directory that holds `config.yaml`:

```yaml config.yaml
auth-dir: "/home/you/.switchailocal"
memory:
  enabled: true
  base-dir: "/home/you/.switchailocal/memory"
```
</Warning>

## Directory layout

```
<base-dir>/
├── routing-history.jsonl     # one decision per line (0600)
├── provider-quirks.md        # template; not populated in 0.6.2
├── user-preferences/         # <api_key_hash>.json; not populated in 0.6.2
├── daily/                    # YYYY-MM-DD.jsonl, gzip-compressed after rotation if compression is on
└── analytics/                # analytics-summary.json, provider-stats.json, model-performance.json
```

Directories are created with mode `0700` and files with `0600`.

## Configuration reference

| Key | Default | Notes |
|---|---|---|
| `memory.enabled` | `false` | Opt-in |
| `memory.base-dir` | `.switchailocal/memory` | Relative to the server's working directory. `~` is not expanded. |
| `memory.retention-days` | `90` | Clamped to 0–3650. The server refuses to start the memory system if the value is below 1. |
| `memory.max-log-size-mb` | `100` | Clamped to 0–10000. Must be at least 1 for the memory system to start. Size-based rotation isn't implemented; daily logs rotate by date. |
| `memory.compression` | `true` | Gzip daily logs when they rotate at midnight |

A cleanup job runs every 24 hours after startup. It removes daily logs older than `retention-days`, compresses old files, and recomputes analytics.

## Management API

| Endpoint | Method | Returns |
|---|---|---|
| `/v0/management/memory/stats` | GET | `{"enabled": true, "stats": {...}}` with `total_decisions`, `total_users`, `disk_usage_bytes`, `oldest_decision`, `newest_decision`, `retention_days`, `compression_enabled`, `daily_logs_stats` |
| `/v0/management/analytics` | GET | The last computed analytics summary: provider stats, model performance, tier effectiveness |

```bash
curl http://localhost:18080/v0/management/memory/stats \
  -H "X-Management-Key: $MANAGEMENT_KEY"
```

When the memory system is disabled, both return `{"enabled": false, "message": "Memory system is disabled"}`. Analytics are first computed by the 24-hour cleanup job, so they may be empty right after startup.

## Privacy

- Client API keys are stored only as SHA-256 hashes.
- Prompt and response bodies aren't written.
- Error messages from failed requests are stored, up to 1000 characters with newlines removed. Upstream error text can contain fragments of the request, so treat `routing-history.jsonl` as sensitive.

## Troubleshooting

<AccordionGroup>
  <Accordion title="routing-history.jsonl stays empty">
    1. Check that `memory.enabled: true` is set and the log shows `Memory System initialized successfully`.
    2. Run with `debug: true` and look for `invalid selected_model format (must be provider:model)`. This is the validation limitation described above.
    3. Make sure you are looking in `memory.base-dir`, relative to the server's working directory, and not in the CLI's directory.
  </Accordion>
  <Accordion title="memory status says 'Memory system not initialized'">
    The CLI looked in `<auth-dir>/memory` relative to your current directory. Use absolute paths as shown above, or run `switchAILocal memory init`.
  </Accordion>
  <Accordion title="The server logs 'invalid configuration: retention days must be at least 1'">
    `retention-days: 0` disables the memory system. Use a value of 1 or more.
  </Accordion>
</AccordionGroup>
