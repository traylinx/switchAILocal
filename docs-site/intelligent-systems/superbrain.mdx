<Warning>
**Status in 0.6.2: not active.** The `superbrain:` block is parsed, validated and hot-reloaded, and `GET /v0/management/metrics` returns its counters. The components that would act on requests (Overwatch, Doctor, Stdin Injector, Recovery, Fallback Router, Context Sculptor) are in the source tree, but the server never wraps any provider with them. Setting `superbrain.enabled: true` changes nothing about how requests are executed, and the metrics stay at zero.

For working failover today, use [virtual models](/concepts/routing), the circuit breaker described in [Failover](/advanced/failover), and the [auto-routing engine](/guides/auto-routing-setup).
</Warning>

## What it is meant to do

Superbrain is designed as a supervisor around CLI-backed providers such as `geminicli` and `claudecli`:

- **Overwatch** watches a CLI process's stdout and stderr and flags it as hung after a silence threshold.
- **Doctor** classifies the failure from the captured log lines, using pattern matching first and then a small model.
- **Stdin Injector** answers known safe interactive prompts, such as permission confirmations.
- **Recovery** restarts the process with corrective flags.
- **Fallback Router** retries on another provider from a configured list.
- **Context Sculptor** estimates tokens before the request and trims low-priority content to fit the model's context window.
- **Audit log** records every autonomous action.

The implementation is under `internal/superbrain/` (components) and `internal/runtime/executor/superbrain_cli_executor.go` (a CLI executor wrapper). In 0.6.2 the server registers plain CLI executors, so none of this runs.

## Configuration reference

You can keep a `superbrain:` block in `config.yaml`. It is validated at startup and on hot reload, and these are the values the code accepts.

```yaml config.yaml
superbrain:
  enabled: false
  mode: "disabled"   # disabled | observe | diagnose | human-in-the-loop | conservative | autopilot

  component_flags:
    overwatch_enabled: true
    doctor_enabled: true
    injector_enabled: true
    recovery_enabled: true
    fallback_enabled: true
    sculptor_enabled: true

  overwatch:
    silence_threshold_ms: 30000
    log_buffer_size: 50
    heartbeat_interval_ms: 1000
    max_restart_attempts: 2

  doctor:
    model: "gemini-flash"
    timeout_ms: 5000

  stdin_injection:
    mode: "conservative"          # disabled | conservative | autopilot
    custom_patterns: []           # name, regex, response, is_safe, description
    forbidden_patterns: []        # regexes that must never be answered

  context_sculptor:
    enabled: true
    token_estimator: "tiktoken"   # tiktoken | simple
    priority_files: ["README.md", "main.go", "index.ts", "package.json"]

  fallback:
    enabled: true
    providers: ["geminicli", "gemini", "ollama"]
    min_success_rate: 0.5

  consensus:
    enabled: false
    verification_model: "gemini-flash"
    trigger_patterns: ["abrupt_ending", "missing_code_blocks"]

  security:
    audit_log_enabled: true
    audit_log_path: "./logs/superbrain_audit.log"
    forbidden_operations: ["file_delete", "system_command"]
```

<Note>
Superbrain keys use `snake_case` (`component_flags`, `silence_threshold_ms`), unlike most other blocks, which use `kebab-case`.
</Note>

### Defaults and validation

| Key | Default | Validation |
|---|---|---|
| `enabled` | `false` | Forced to `false` when `mode` is `disabled` |
| `mode` | `disabled` | Unknown values become `disabled` |
| `overwatch.silence_threshold_ms` | `30000` | Minimum 1000 |
| `overwatch.log_buffer_size` | `50` | Minimum 10 |
| `overwatch.heartbeat_interval_ms` | `1000` | Minimum 100 |
| `overwatch.max_restart_attempts` | `2` | Clamped to 0–5 |
| `doctor.model` | `gemini-flash` | Empty becomes `gemini-flash` |
| `doctor.timeout_ms` | `5000` | Clamped to 1000–30000 |
| `stdin_injection.mode` | `conservative` | Unknown values become `conservative` |
| `context_sculptor.token_estimator` | `tiktoken` | Must be `tiktoken` or `simple` |
| `fallback.providers` | `geminicli, gemini, ollama` | Lower-cased and de-duplicated |
| `fallback.min_success_rate` | `0.5` | Clamped to 0.0–1.0 |
| `consensus.enabled` | `false` | |
| `security.audit_log_path` | `./logs/superbrain_audit.log` | Empty becomes the default |

### Modes

| Mode | Intended behavior |
|---|---|
| `disabled` | Pass-through |
| `observe` | Monitor and log only |
| `diagnose` | Diagnose and log proposed actions without running them |
| `human-in-the-loop` | Accepted by validation. The executor wrapper treats it as pass-through. |
| `conservative` | Run only actions marked safe |
| `autopilot` | Run all healing actions |

## Metrics endpoint

The management route exists and returns the global counters:

```bash
curl http://localhost:18080/v0/management/metrics \
  -H "X-Management-Key: $MANAGEMENT_KEY"
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="I enabled Superbrain and nothing changed">
    That is expected in this release. No `superbrain` field is added to responses, no audit log is written, and no CLI prompt is answered automatically.
  </Accordion>
  <Accordion title="My mode was reset to disabled">
    The value wasn't one of the six accepted modes. Values are trimmed and lower-cased before they are checked.
  </Accordion>
  <Accordion title="A CLI provider hangs on an interactive prompt">
    Superbrain won't answer it. Send `"extra_body": {"cli": {"flags": {"auto_approve": true}}}` so switchAILocal adds the CLI's auto-approve flag (see [CLI Integrations](/guides/cli-integrations)), or use an API-key provider for unattended workloads.
  </Accordion>
</AccordionGroup>
