## GET /v1/models

Lists the models clients can request. Also served at `GET /openai/v1/models`. For the Gemini-format list, see [`GET /v1beta/models`](/api/gemini).

**Auth:** client API key.

### Query parameters

<ParamField query="modality" type="string">
  Keep only models whose `capabilities` array contains this value: `text`, `vision`, `image`, `audio`, or `embedding`.
</ParamField>

### What is listed

- Exposed virtual models (`virtual-models.<id>.expose: true`) come first, then every registered model.
- Models with `visibility: private`, `expose: false` aliases, and credential-prefixed IDs (`prefix/model`) are hidden. They stay routable.
- IDs are de-duplicated case-insensitively.
- **If any listed ID starts with `ail-`, only `ail-*` IDs are returned.** This keeps a curated public catalog when you define stable `ail-*` aliases.

### Response

```json
{
  "object": "list",
  "data": [
    {
      "id": "ail-compound",
      "object": "model",
      "owned_by": "switchai",
      "capabilities": ["text", "vision"],
      "attachment": true,
      "tool_call": true,
      "reasoning": false,
      "modalities": {"input": ["text", "image"], "output": ["text"]},
      "vision": true,
      "context_length": 1000000
    }
  ]
}
```

<ResponseField name="id" type="string">The value to send as `model`.</ResponseField>
<ResponseField name="object" type="string">Always `model`.</ResponseField>
<ResponseField name="created" type="integer">Registration time (Unix seconds), when known.</ResponseField>
<ResponseField name="owned_by" type="string">Provider or `switchai` for operator-defined aliases and virtual models.</ResponseField>
<ResponseField name="capabilities" type="string[]">
  Coarse capability labels. Taken from the virtual-model pool for virtual models. Otherwise derived from `intelligence.matrix`: `image_gen` gives `image`, `vision` gives `vision`, `transcription`/`speech`/`audio` give `audio`, `embedding` gives `embedding`, any other key gives `text`. Defaults to `["text"]`.
</ResponseField>
<ResponseField name="attachment, tool_call, reasoning, modalities, vision, audio" type="mixed">
  Capability-discovery fields used by AI-SDK based clients (OpenCode, Cursor, Continue) to decide whether to send images or audio. Present when known.
</ResponseField>
<ResponseField name="native_tools" type="object[]">
  Provider-native tools the model supports, for example `[{"type":"web_search","description":"...","params":{...}}]`. Only present when configured. Splice entries into your own `tools` array; see [Native tool injection](/api/chat-completions#native-tool-injection).
</ResponseField>
<ResponseField name="context_length, max_completion_tokens" type="integer">Present when configured or discovered.</ResponseField>

### Claude Code clients

When the `User-Agent` starts with `claude-cli`, the endpoint answers in the Anthropic models shape instead: `{"data":[{"id","object","owned_by","created","type","display_name"}]}` built from models registered for the Claude handler.

### Example

```bash
curl "http://localhost:18080/v1/models?modality=vision" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

## GET /v1/providers

Lists providers that currently have at least one registered model.

**Auth:** client API key.

<ParamField query="filter" type="string" default="all">
  `active`, `inactive`, or `all`. Providers are only listed while they have models, so they always report `active`, and `filter=inactive` returns an empty list.
</ParamField>

```json
{
  "object": "list",
  "data": [
    {
      "id": "geminicli",
      "name": "Gemini CLI",
      "type": "cli",
      "mode": "local",
      "status": "active",
      "model_count": 3,
      "models": ["gemini-2.5-flash", "gemini-2.5-pro", "gemini-3-pro-preview"]
    },
    {
      "id": "ollama",
      "name": "Ollama (Local)",
      "type": "api",
      "mode": "local",
      "status": "active",
      "model_count": 2,
      "models": ["llama3.2", "qwen3-embedding:0.6b"]
    }
  ]
}
```

| Field | Values |
|---|---|
| `id` | Provider key used for routing and `provider:` prefixes (`geminicli`, `claudecli`, `codex`, `vibe`/`vibecli`, `ollama`, `gemini`, `claude`, `switchai`, OpenAI-compatible entry names, ...) |
| `type` | `cli` or `api` |
| `mode` | `local` or `online` |
| `models` | All registered IDs for this provider, including hidden aliases |

Results are sorted by `id`.

```bash
curl http://localhost:18080/v1/providers -H "Authorization: Bearer YOUR_API_KEY"
```

## POST /v1/models/refresh

Re-runs model discovery and re-registers discovered models. The call is synchronous and has a 30-second timeout.

**Auth:** client API key.

<ParamField query="provider" type="string">
  Refresh one discovery source only (for example `ollama`). Omit to refresh all.
</ParamField>

| Status | Body |
|---|---|
| `200` | `{"message":"Model refresh completed","provider":"ollama"}` (`provider` is `""` when omitted) |
| `500` | `{"error":"refresh failed: <reason>"}` |
| `503` | `{"error":"Model discovery not initialized"}` |

```bash
curl -X POST "http://localhost:18080/v1/models/refresh?provider=ollama" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

## Where models come from

- **Config:** `models:` aliases under `gemini-api-key`, `claude-api-key`, `codex-api-key`, `switchai-api-key`, and `openai-compatibility` entries, plus `virtual-models`.
- **Discovery:** installed CLIs (`gemini`, `claude`, `codex`, `vibe`), Ollama (`ollama.auto-discover`), LM Studio, OpenCode, and provider `models-url` endpoints.
- **OAuth credentials:** auth files in `auth-dir`.

Model IDs are case-sensitive when routing.
