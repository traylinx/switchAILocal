## POST /v1/chat/completions

OpenAI-compatible chat completions. Also served at `POST /openai/v1/chat/completions`.

**Auth:** client API key ([Authentication](/api/authentication)).

The gateway reads only a few fields itself. The rest of the body is translated into the selected provider's native format, so support for sampling and tool options depends on the provider.

### Fields the gateway reads

<ParamField body="model" type="string" required>
  Selects the provider and model. Accepts a plain model ID, `provider:model`, a configured alias, a virtual model such as `ail-compound`, or `auto` / `auto:<intent>`. See [Provider Prefixes](/api/provider-prefixes) and [Auto-Routing](/api/auto-routing).

  Two suffixes are understood: `model(8192)` sets a thinking budget, and `model(high)` sets a reasoning-effort level, for providers that support it. A trailing `-vision` is stripped when the name without it is a registered model and the full name is not.
</ParamField>

<ParamField body="messages" type="array" required>
  OpenAI message objects (`role`, `content` as a string or content-part array, `tool_calls`, `tool_call_id`, ...).
</ParamField>

<ParamField body="stream" type="boolean" default="false">
  `true` returns Server-Sent Events. Only the JSON boolean `true` enables streaming.
</ParamField>

<ParamField body="tools" type="array">
  OpenAI function tools, passed through. Provider-native tools such as `{"type":"web_search"}` are also passed through, and may be added by the gateway (see [Native tool injection](#native-tool-injection)).
</ParamField>

<ParamField body="extra_body" type="object">
  Options for local CLI providers (`extra_body.cli`). See [CLI Attachments](/api/cli-attachments).
</ParamField>

Other OpenAI fields (`temperature`, `top_p`, `max_tokens`, `stop`, `tool_choice`, `response_format`, `reasoning_effort`, ...) are forwarded through the request translator. The gateway applies no defaults of its own.

<Note>
If the body has no `messages` but has `input` or `instructions`, it is treated as an OpenAI **Responses** payload and converted to chat format before routing. New code should call [`/v1/responses`](/api/responses) directly.
</Note>

### Response (non-streaming)

A standard `chat.completion` object:

```json
{
  "id": "chatcmpl-123",
  "object": "chat.completion",
  "created": 1767225600,
  "model": "llama3.2",
  "choices": [
    {
      "index": 0,
      "message": {"role": "assistant", "content": "Hello! How can I help?"},
      "finish_reason": "stop"
    }
  ],
  "usage": {"prompt_tokens": 9, "completion_tokens": 7, "total_tokens": 16}
}
```

The `model` value comes from the provider. Virtual models configured with `response_model: requested` rewrite it to the public name you sent.

Response headers: `X-Ail-Build` on every response, `X-Auto-Routed` / `X-Selected-Model` / `X-Selected-Provider` when auto-routing picked the model, `X-Matched-Skill` when skill matching applied.

### Streaming

With `"stream": true` the response is `text/event-stream`:

```text
data: {"id":"chatcmpl-123","object":"chat.completion.chunk","choices":[{"index":0,"delta":{"content":"Hel"}}]}

data: {"id":"chatcmpl-123","object":"chat.completion.chunk","choices":[{"index":0,"delta":{"content":"lo"},"finish_reason":"stop"}]}

data: [DONE]
```

- If the provider fails before the first chunk, you get a normal JSON error with the real status code instead of a stream.
- If it fails after streaming started, the gateway writes one `data: {"error":{...}}` event and closes the stream without `[DONE]`.
- `: keep-alive` comments are sent when `streaming.keepalive-seconds` is above `0`.

### Examples

<CodeGroup>
```bash cURL
curl http://localhost:18080/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "ollama:llama3.2",
    "messages": [
      {"role": "system", "content": "You are concise."},
      {"role": "user", "content": "What is the capital of France?"}
    ]
  }'
```

```bash cURL (stream)
curl -N http://localhost:18080/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "geminicli:gemini-2.5-pro", "stream": true,
       "messages": [{"role": "user", "content": "Tell me a short story"}]}'
```

```python Python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:18080/v1", api_key="YOUR_API_KEY")

stream = client.chat.completions.create(
    model="geminicli:gemini-2.5-pro",
    messages=[{"role": "user", "content": "Tell me a short story"}],
    stream=True,
)
for chunk in stream:
    if chunk.choices and chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="")
```

```javascript Node.js
import OpenAI from "openai";

const client = new OpenAI({ baseURL: "http://localhost:18080/v1", apiKey: "YOUR_API_KEY" });

const res = await client.chat.completions.create({
  model: "ollama:llama3.2",
  messages: [{ role: "user", content: "Hello!" }],
});
console.log(res.choices[0].message.content);
```
</CodeGroup>

### Native tool injection

Some upstream models have built-in tools (for example MiniMax `web_search`). The gateway can add them to `tools` for you:

1. **Discovery (always on).** If the requested model ID is configured with `native_tools` (under `openai-compatibility.*.models[]`), each listed tool type that is not already in your `tools` is appended. The same list is published on that model in [`GET /v1/models`](/api/models).
2. **Environment fallback.** For models without `native_tools`, `{"type":"web_search"}` is appended only when `AIL_AUTOINJECT_WEBSEARCH=true` and the exact model name is in the comma-separated `AIL_AUTOINJECT_MODELS`.

Rules for both paths:

- Your own entries always win. Nothing is appended if your `tools` already has an entry of that type.
- If your request already contains at least `AIL_AUTOINJECT_FORCE_THRESHOLD` function tools (default `5`; `0` disables this), the injected `web_search` gets `"force_search": true`.
- When a `web_search` tool ends up in the request through injection, `max_tokens` is raised to `2000` if it is missing or lower. Search results can add thousands of prompt tokens.
- Send `X-Ail-Autoinject: off` to skip injection for one request.

Setting `AIL_DEBUG_DUMP=true` logs every raw chat request body.

### Errors

| Status | When |
|---|---|
| `400` | Unreadable body, `unknown provider for model <id>`, unknown prefix, or invalid thinking configuration |
| `401` | Missing or invalid API key |
| `422` | Virtual model has no member that can serve this request (for example images sent to a text-only pool) |
| `503` | Prefixed API provider not active, or every candidate provider is open in the circuit breaker |
| upstream status | Provider errors are passed through with their status (`429`, `5xx`, ...) |

## POST /v1/completions

Legacy text completions. Also served at `POST /openai/v1/completions`. Internally the request becomes a single-user-message chat completion, and the answer is converted back.

**Auth:** client API key.

| Field | Notes |
|---|---|
| `model` | As for chat completions |
| `prompt` | String. When empty, the prompt `"Complete this:"` is used |
| `max_tokens`, `temperature`, `top_p`, `frequency_penalty`, `presence_penalty`, `stop`, `stream`, `logprobs`, `top_logprobs`, `echo` | Copied into the chat request. Any other field is dropped |

Response:

```json
{
  "id": "chatcmpl-123",
  "object": "text_completion",
  "created": 1767225600,
  "model": "llama3.2",
  "choices": [{"index": 0, "text": "Paris.", "finish_reason": "stop"}],
  "usage": {"prompt_tokens": 5, "completion_tokens": 2, "total_tokens": 7}
}
```

With `"stream": true`, each SSE event is a `text_completion` chunk carrying `choices[].text`. Chunks with no text and no `finish_reason` are skipped, and the stream ends with `data: [DONE]`.

```bash
curl http://localhost:18080/v1/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "ollama:llama3.2", "prompt": "The capital of France is", "max_tokens": 5}'
```
