All paths are relative to `/v0/management` and need the [management key](/api/management/overview#authentication).

<Warning>
GET on any key list returns the keys in clear text. Keep the Management API local.
</Warning>

## Client API keys

`/api-keys` manages the top-level `api-keys` list that clients use to call `/v1/*` (see [Authentication](/api/authentication)).

| Method | Body / query | Effect |
|---|---|---|
| GET | none | `{"api-keys": ["..."]}` |
| PUT | `["key1","key2"]` or `{"items":["key1","key2"]}` | Replace the list. A bare `[]` clears it, which **makes the gateway accept every request**. `{"items":[]}` returns `400` |
| PATCH | `{"index": 0, "value": "new"}` | Replace by position |
| PATCH | `{"old": "a", "new": "b"}` | Replace the first exact match, or append `b` if there is none |
| DELETE | `?index=0` or `?value=<key>` | Remove by position, or every match |

```bash
curl -X PATCH http://localhost:18080/v0/management/api-keys \
  -H "Authorization: Bearer YOUR_MANAGEMENT_KEY" -H "Content-Type: application/json" \
  -d '{"old": "", "new": "sk-new-client-key"}'
```

## Provider key lists

Four lists share one pattern: `/gemini-api-key`, `/claude-api-key`, `/codex-api-key`, `/switchai-api-key`. They map to the config keys of the same name.

**Entry fields:** `api-key`, `prefix`, `base-url`, `proxy-url`, `models-url`, `headers` (map), `excluded-models` (string list), and `models`:

- claude and switchai: `[{name, alias}]`.
- gemini and codex: `[{name, alias, expose, visibility, context_length, capabilities, native_tools}]`.

| Method | Body / query | Effect |
|---|---|---|
| GET | none | `{"<list-name>": [ ...entries ]}` |
| PUT | `[ ...entries ]` or `{"items":[...]}` | Replace the list. A bare `[]` clears it |
| PATCH | `{"index": 0, "value": {...}}` or `{"match": "<api-key>", "value": {...}}` | Merge the given fields into one entry. `index` wins if valid. `404 {"error":"item not found"}` when nothing matches |
| DELETE | `?api-key=<key>` or `?index=0` | Remove one entry. Neither parameter returns `400` |

Per-list details:

- **gemini:** PUT drops entries without `api-key` and removes duplicates. PATCH with `"api-key": ""` deletes the entry. DELETE returns `404` when nothing matched.
- **claude:** PUT drops `models` entries that have neither `name` nor `alias`.
- **codex:** PUT drops entries without `base-url`. PATCH with `"base-url": ""` deletes the entry.
- **switchai:** PUT fills in the default `base-url` when it is empty.

```bash
curl -X PUT http://localhost:18080/v0/management/gemini-api-key \
  -H "Authorization: Bearer YOUR_MANAGEMENT_KEY" -H "Content-Type: application/json" \
  -d '[{"api-key": "YOUR_GEMINI_KEY", "prefix": "team-a"}]'
```

## OpenAI compatibility

`/openai-compatibility` manages `openai-compatibility` providers (Groq, OpenRouter, MiniMax, LM-Studio-style servers, ...).

**Entry fields:** `name`, `prefix`, `base-url`, `models-url`, `api-key-entries` (`[{api-key, proxy-url}]`), `models` (`[{name, alias, expose, visibility, context_length, capabilities, native_tools}]`), `headers`, `excluded-models`.

| Method | Body / query | Effect |
|---|---|---|
| GET | none | `{"openai-compatibility": [...]}` |
| PUT | `[...]` or `{"items":[...]}` | Replace. Entries without `base-url` are dropped |
| PATCH | `{"index": 0, "value": {...}}` or `{"name": "groq", "value": {...}}` | Merge fields into one entry. Matches on `name`, not `match`. `"base-url": ""` deletes the entry. `404` when nothing matches |
| DELETE | `?name=groq` or `?index=0` | Remove one entry |

```bash
curl -X PUT http://localhost:18080/v0/management/openai-compatibility \
  -H "Authorization: Bearer YOUR_MANAGEMENT_KEY" -H "Content-Type: application/json" \
  -d '[{"name": "groq", "base-url": "https://api.groq.com/openai/v1",
        "api-key-entries": [{"api-key": "YOUR_GROQ_KEY"}],
        "models": [{"name": "openai/gpt-oss-20b", "alias": "groq:gpt-oss-20b"}]}]'
```

## OAuth excluded models

`/oauth-excluded-models` is a map from provider to model IDs to hide for OAuth / file-based credentials.

| Method | Body / query | Effect |
|---|---|---|
| GET | none | `{"oauth-excluded-models": {"gemini": ["gemini-1.5-pro"]}}` (provider keys lowercased) |
| PUT | `{"gemini": [...]}` or `{"items": {...}}` | Replace the map |
| PATCH | `{"provider": "gemini", "models": ["..."]}` | Set one provider. An empty `models` removes it (`404` if absent) |
| DELETE | `?provider=gemini` | Remove one provider. `400` when the parameter is missing, `404` when the provider is unknown |

## Testing providers

### POST /providers/test

Checks a provider configuration **without saving it**. Body:

```json
{"provider_id": "groq", "category": "cloud", "config": {"api-key": "...", "base-url": "https://api.groq.com/openai/v1", "models-url": "https://api.groq.com/openai/v1/models", "proxy-url": ""}}
```

The `category` is matched by substring, case-insensitively:

| Category contains | What happens |
|---|---|
| `cli` | Checks that the binary is on `PATH`. Accepted `provider_id`: `claude-cli`/`claudecli`, `gemini-cli`/`geminicli`, `vibe-cli`/`vibecli`, `codex-cli`/`codex`, `opencode-cli`/`opencode`. Returns `{"status":"success"\|"error","message"}`. An unknown ID returns `400 unknown_cli` |
| `cloud` | Requires `config.api-key` (except for `ollama`/`lmstudio`). GETs `base-url` (10 s timeout) and `models-url` with a Bearer key. Returns `{"status","message","tests":{"apiKey","baseUrl","proxy","modelsUrl"}}`, where each test is `{passed, message, latency?}` |
| `local` | GETs `config.base-url`, or the configured Ollama / LM Studio / OpenCode URL, with a 3 s timeout. Any 2xx–4xx counts as reachable |

Other categories return `400 invalid_category`. URLs must be `http`/`https`, with a host and without credentials or fragments; otherwise `400 invalid_url`.

### POST /providers/discover-models

Lists a provider's models **without saving anything**. The body uses camelCase:

```json
{"baseUrl": "http://localhost:11434", "modelsUrl": "", "apiKey": "", "proxyUrl": "", "headers": {}}
```

- When `modelsUrl` is empty, it is derived as `baseUrl + /models`, or `baseUrl + /api/tags` for Ollama (URL contains `ollama` or uses port 11434).
- Both OpenAI (`{data:[{id}]}`) and Ollama (`{models:[{name}]}`) responses are understood.
- Returns `{"success": true, "models": [{"id": "llama3.2"}]}`.
- Errors: `400 missing_url` / `invalid_url` / `invalid_proxy`; upstream `4xx`/`5xx` passed through as `provider_error`; `502 upstream_error` / `parse_error` (unknown format or empty list).

## Auth files

OAuth and credential files live in `auth-dir` (default `~/.switchailocal`).

| Route | Notes |
|---|---|
| `GET /auth-files` | `{"files":[{"id","auth_index","name","type","provider","label","status","status_message","disabled","unavailable","runtime_only","source","size","email","account_type","account","created_at","modtime","updated_at","last_refresh","path"}]}`, sorted by name. Optional fields are omitted when unknown |
| `GET /auth-files/models?name=<file>` | Models registered for that credential: `{"models":[{"id","display_name","type","owned_by"}]}` |
| `GET /auth-files/download?name=<file>.json` | Downloads the file. `400` if the name is invalid or does not end in `.json`, `404` if missing |
| `POST /auth-files` | Upload either as multipart field `file` (name must end in `.json`) or as a raw JSON body with `?name=<file>.json`. The JSON's `type` sets the provider. Returns `{"status":"ok"}` |
| `DELETE /auth-files?name=<file>.json` | Deletes one file. Returns `{"status":"ok"}` |
| `DELETE /auth-files?all=true` | Deletes every `.json` file in `auth-dir`. Returns `{"status":"ok","deleted":N}` |
| `POST /vertex/import` | Multipart field `file` = Google service-account JSON, optional `location` (form or query, default `us-central1`). Saves `vertex-<project>.json` and returns `{"status":"ok","auth-file","project_id","email","location"}` |

Upload, list, and delete return `503` when the credential manager is unavailable.

## OAuth login flows

Logins for subscription-based providers run in three steps.

**1. Start a login** with one of these GET routes. Each returns `{"status":"ok","url":"<authorize URL>","state":"<state>"}`:

| Route | Provider |
|---|---|
| `/anthropic-auth-url` | Claude (Anthropic OAuth) |
| `/codex-auth-url` | OpenAI Codex |
| `/gemini-cli-auth-url` | Gemini CLI / Code Assist. Optional `?project_id=` (empty = auto, `ALL` = every project) |
| `/antigravity-auth-url` | Antigravity |
| `/iflow-auth-url` | iFlow |
| `/qwen-auth-url` | Qwen (device-code flow; `url` is the verification page) |

**2. Finish the browser step** in one of two ways:

- Add `?is_webui=true` to the start request. The gateway briefly listens on the provider's fixed local callback port and redirects the browser to `/{anthropic,codex,google,iflow,antigravity}/callback` on the main port, which records the result.
- Without `is_webui`, paste the final redirect URL into:

  ```bash
  curl -X POST http://localhost:18080/v0/management/oauth-callback \
    -H "Authorization: Bearer YOUR_MANAGEMENT_KEY" -H "Content-Type: application/json" \
    -d '{"provider": "anthropic", "redirect_url": "http://localhost:54545/callback?code=...&state=..."}'
  ```

  `provider` accepts `anthropic`/`claude`, `codex`/`openai`, `gemini`/`google`, `iflow`/`i-flow`, `antigravity`/`anti-gravity`, `qwen`. You can send `code`, `state`, and `error` directly instead of `redirect_url`.

  Errors are shaped `{"status":"error","error":...}`:

  | Status | Cause |
  |---|---|
  | `400` | Bad provider, URL, or state |
  | `404` | Unknown or expired state |
  | `409` | The flow is no longer pending |

**3. Poll** `GET /get-auth-status?state=<state>`:

| Response | Meaning |
|---|---|
| `{"status":"wait"}` | Still pending |
| `{"status":"error","error":"..."}` | Login failed |
| `{"status":"ok"}` | Completed. Unknown or expired states also return `ok` |

Logins wait up to 5 minutes for the callback, and sessions expire after 10 minutes.

**iFlow cookie login:** `POST /iflow-auth-url` with `{"cookie": "..."}` logs in directly.

- Success: `{"status":"ok","saved_path","email","expired","type"}`.
- `409` when that account already has a credential file.
