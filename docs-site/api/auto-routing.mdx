---
title: 'Auto-Routing'
description: 'What happens when you send model "auto", "auto:<intent>", or "cortex", and how to observe the decision'
---

Send `"model": "auto"` (or `auto:<intent>`) and switchAILocal chooses the model for you. Resolution happens in up to three layers. The first one that produces a model wins.

## 1. Cortex router plugin (optional)

If the Lua plugin system is enabled with the bundled `cortex-router` plugin, requests whose model is exactly `auto` or `cortex` are classified (using `intelligence.router-model`, skills, and `intelligence.matrix`) and rewritten to a concrete model before anything else runs.

```yaml config.yaml
plugin:
  enabled: true
  enabled-plugins: ["cortex-router"]
intelligence:
  enabled: true
  router-model: "ollama:qwen:0.5b"
  matrix:
    coding: "ail-compound"
    fast: "ollama:llama3.2"
```

## 2. Auto-routing engine (`auto-routing.enabled: true`)

Applies to `auto`, `auto:<intent>`, `cortex`, and an empty `model`. The engine scores the candidate models found by provider discovery and picks the best one, with a fallback chain.

### Intent hints

`auto:<hint>` passes an intent. Hints are normalized:

| You send | Intent |
|---|---|
| `code`, `coding`, `program`, `programming`, `dev` | `coding` |
| `reason`, `reasoning`, `think`, `thinking`, `math`, `logic` | `reasoning` |
| `creative`, `write`, `writing`, `story`, `poem` | `creative` |
| `fast`, `quick`, `simple`, `chat` | `fast` |
| `vision`, `image`, `visual`, `screenshot` | `vision` |
| `secure`, `private`, `local`, `sensitive` | `secure` |
| anything else | passed through as-is |

Without a hint, the intent is classified heuristically from the request body.

### Scoring

```text
BaseScore  = availability·W_a + quota·W_q + latency·W_l + success_rate·W_s
FinalScore = (BaseScore + tier boost + preference boost) × conservation multiplier
```

### Configuration

```yaml config.yaml
auto-routing:
  enabled: true
  max-resolution-ms: 5ms
  weights: {availability: 0.35, quota: 0.25, latency: 0.20, success-rate: 0.20}
  preferences:
    - model: "ail-compound"
      preference: 0.9
      reason: "default assistant"
  providers:                       # tier per provider: premium | standard | free | local | reserve
    ollama: {tier: local}
  intent-matrix:                   # restrict candidates per intent
    coding: ["claude:claude-sonnet-4-5", "geminicli:gemini-2.5-pro"]
  disabled-providers: ["claude"]   # never selected
  conservation:                    # steer simple prompts away from premium tiers
    enabled: true
    simple-threshold-tokens: 500
    premium-conservation-at: 0.20
  discovery:
    enabled: true
    probe-on-startup: true
    probe-interval: 15m
    probe-timeout: 5s
  lab:                             # shadow-test perturbed weights and promote winners
    enabled: true
    adaptation-interval: 24h
    max-weight-drift: 0.10
```

At startup, candidates come from probing the Gemini CLI, Claude CLI, Codex, configured Gemini and Claude API keys, and Ollama (when `ollama.enabled`).

### Response headers

When the engine picks the model, the response carries:

```text
X-Auto-Routed: true
X-Selected-Model: <model>
X-Selected-Provider: <provider>
```

## 3. Legacy fallback

If the engine is disabled or cannot decide, and the model is exactly `auto`, the gateway picks the first available model from `routing.auto-model-priority`, then the newest registered model:

```yaml config.yaml
routing:
  auto-model-priority:
    - "ollama:llama3.2"     # provider:model pins the owner
    - "gemini-2.5-pro"
```

`auto:<intent>`, `cortex`, and an empty model have no legacy fallback. If neither layer 1 nor layer 2 handled them, the request fails with `400 unknown provider for model ...`.

## Observing decisions

These management endpoints need the [management key](/api/management/overview#authentication):

```bash
curl http://localhost:18080/v0/management/autoroute/status \
  -H "Authorization: Bearer YOUR_MANAGEMENT_KEY"
curl "http://localhost:18080/v0/management/autoroute/journal?limit=20" \
  -H "Authorization: Bearer YOUR_MANAGEMENT_KEY"
```

`status` reports the live and shadow weights and the lab hypothesis. `journal` lists recent decisions. Both return `503` when the engine is not initialized. See [Configuration & Monitoring](/api/management/config#auto-routing-telemetry).

## Routing without `auto`

Requests for a concrete model ID never go through the auto-routing engine. When several providers serve the same ID, credentials rotate according to `routing.strategy` (`round-robin` or `fill-first`), with failover and the circuit breaker (`performance.circuit-breaker`). Virtual models (`ail-compound`) do weighted member selection on their own. See [Provider Prefixes & Model Routing](/api/provider-prefixes).
