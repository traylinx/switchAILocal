## What `/v1/ws` is

`/v1/ws` is **not** a chat-streaming API. Use `stream: true` on the HTTP endpoints for that.

A WebSocket client that connects here **becomes a provider**. The gateway sends it HTTP-style requests over the socket, and the client executes them (typically against Google AI Studio from a browser session) and sends the responses back. Requests routed to the `aistudio` provider are delivered to connected relay clients.

## Connecting

```text
GET /v1/ws   (WebSocket upgrade)
```

**Auth:** client API key when `ws-auth: true` (the default). Browsers cannot set headers on the handshake, so use a query parameter:

```javascript
const ws = new WebSocket("ws://localhost:18080/v1/ws?auth_token=YOUR_API_KEY");
```

`?key=` and the usual headers also work (see [Authentication](/api/authentication)). Missing or wrong keys get `401` before the upgrade.

Other details:

- Any `Origin` is accepted.
- Only `GET` is allowed.
- Each connection is registered as a provider session named `aistudio-<random>`. A new connection with the same name replaces the old one.
- When `ws-auth` changes from `false` to `true` at runtime, all existing sessions are closed.

## Message envelope

Every frame in both directions is a JSON object:

```json
{"id": "<request id>", "type": "<message type>", "payload": {}}
```

### Server to client

`http_request`, sent when the gateway routes a request to this relay:

```json
{
  "id": "6f1c...",
  "type": "http_request",
  "payload": {
    "method": "POST",
    "url": "https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-pro:streamGenerateContent?alt=sse",
    "headers": {"Content-Type": ["application/json"]},
    "body": "{...}",
    "sent_at": "2026-01-01T00:00:00Z"
  }
}
```

`pong` is sent in reply to a client `ping`, with the same `id`.

### Client to server

Reply with the same `id` as the request:

| `type` | `payload` | Meaning |
|---|---|---|
| `http_response` | `{"status": 200, "headers": {...}, "body": "..."}` | Complete, non-streaming response (ends the request) |
| `stream_start` | `{"status": 200, "headers": {...}}` | Start of a streaming response |
| `stream_chunk` | `{"data": "..."}` | One chunk of the streaming body |
| `stream_end` | `{}` | End of the stream (ends the request) |
| `error` | `{"error": "message", "status": 502}` | Failure (ends the request) |
| `ping` | none | Keep-alive; the server answers `pong` |

`headers` values may be strings or string arrays.

## Timeouts and limits

| Setting | Value |
|---|---|
| Server WebSocket ping interval | 30 s |
| Read deadline (reset by pong) | 60 s |
| Maximum inbound message size | 64 MiB |

If a session closes while requests are in flight, each pending request fails with an `error` message.

## Configuration

```yaml config.yaml
ws-auth: true   # require a client API key for /v1/ws (default true)
```

`ws-auth` can be read and changed at runtime via [`/v0/management/ws-auth`](/api/management/config#settings).
