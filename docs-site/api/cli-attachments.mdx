---
title: 'CLI Attachments & Flags'
description: 'extra_body.cli: attach files and folders, set CLI flags, and resume sessions on local CLI providers'
---

When a request is routed to a local CLI provider (`geminicli`, `claudecli`, `vibecli`, `codex`), the gateway runs that CLI as a subprocess. The optional `extra_body.cli` object in a chat-completions body controls how it is run.

API providers ignore `extra_body.cli`.

## Shape

```json
{
  "model": "geminicli:gemini-2.5-pro",
  "messages": [{"role": "user", "content": "Review this code"}],
  "extra_body": {
    "cli": {
      "attachments": [
        {"type": "file", "path": "/home/me/project/main.go"},
        {"type": "folder", "path": "/home/me/project/internal"}
      ],
      "flags": {"sandbox": true, "auto_approve": false, "yolo": false},
      "session_id": "latest"
    }
  }
}
```

<ParamField body="extra_body.cli.attachments" type="object[]">
  Each item is `{"type": "file" | "folder", "path": "..."}`. Folders get a trailing `/`. Every item becomes an `@<path>` reference placed before the prompt.
</ParamField>

<ParamField body="extra_body.cli.flags.sandbox" type="boolean">Adds the CLI's sandbox flag.</ParamField>
<ParamField body="extra_body.cli.flags.auto_approve" type="boolean">Adds the CLI's auto-approve flag.</ParamField>
<ParamField body="extra_body.cli.flags.yolo" type="boolean">Adds the CLI's most permissive flag.</ParamField>
<ParamField body="extra_body.cli.session_id" type="string">
  Passed unchanged to the CLI's resume flag. Its meaning (for example `latest`) is defined by the CLI.
</ParamField>

## What each CLI supports

| | `geminicli` | `vibecli` | `claudecli` | `codex` |
|---|---|---|---|---|
| Attachments | yes (`@path`, sent on stdin) | yes (`@path`) | ignored | ignored |
| `sandbox` | `-s` | none | none | `--sandbox` |
| `auto_approve` | `-y` | `--auto-approve` | `--dangerously-skip-permissions` | `--full-auto` |
| `yolo` | `--yolo` | `--auto-approve` | `--dangerously-skip-permissions` | `--full-auto` |
| `session_id` | `--resume=<id>` | `--continue <id>` | `--resume <id>` | none |
| Real streaming | yes (`stream-json`) | buffered | yes (`stream-json`) | buffered |

Notes:

- `claudecli` always gets `--dangerously-skip-permissions` when the server has no TTY (the normal case for a background server), so it never hangs on a permission prompt.
- "Buffered" means a `stream: true` request is answered as an SSE stream, but only after the CLI has finished.
- Each CLI call is killed after **5 minutes**.
- The CLI runs in an empty working directory (`billboard.base-dir` when `billboard.enabled`, otherwise a sandbox folder in your home directory), so it does not scan the server's directory for context.

## Path rules

Attachment paths are checked against the **server process's working directory**:

- A path that resolves outside it (`..` traversal, or an absolute path elsewhere) is rejected, and the request fails.
- Because the CLI itself runs in a different directory, use **absolute paths** under the server's working directory. Relative paths are checked against the server directory but resolved by the CLI against its own.
- `~` is not expanded.
- The gateway does not enforce a file-size limit. Limits come from the CLI and model context.

## OpenCode

The `opencode` provider talks to an OpenCode server over HTTP instead of running a CLI. It does not read `extra_body.cli`. It reads `extra_body.session_id` (or a top-level `session_id`) to continue an OpenCode session.

## Example

```bash
curl http://localhost:18080/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "geminicli:gemini-2.5-pro",
    "messages": [{"role": "user", "content": "Summarize what this package does"}],
    "extra_body": {"cli": {
      "attachments": [{"type": "folder", "path": "/srv/switchailocal/workspace/internal/api"}],
      "flags": {"sandbox": true}
    }}
  }'
```

With the OpenAI Python SDK, pass the object through `extra_body`. The SDK merges `extra_body` into the top level of the request, so nest `extra_body` inside it:

```python
client.chat.completions.create(
    model="geminicli:gemini-2.5-pro",
    messages=[{"role": "user", "content": "Review main.go"}],
    extra_body={"extra_body": {"cli": {"attachments": [{"type": "file", "path": "/srv/app/main.go"}]}}},
)
```

## Errors

| Status | When |
|---|---|
| `500` | `invalid attachment: security violation: attachment path ... attempts to traverse outside working directory` |
| `500` | `local CLI missing valid auth: ...` (the CLI needs re-login) or `CLI execution failed: <last stderr lines>` |
| `4xx` / `5xx` | When the CLI's stderr clearly shows a quota, auth, or rate-limit problem, the gateway returns a matching status |
