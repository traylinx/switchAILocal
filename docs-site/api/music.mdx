title: 'Music & Lyrics'
description: 'POST /v1/music/generations and POST /v1/music/lyrics (MiniMax music-2.6 / music-cover)'
---

Two routes under `/v1/music/*`. Both need a MiniMax provider configured as an `openai-compatibility` entry whose name contains `minimax`. Any other provider returns `501`. They are not reachable via `/v1/chat/completions` and have no `/openai/v1` alias.

**Auth:** client API key.

## Prerequisite: model aliases

Routing goes through the model registry, so the music models must exist as aliases. The example config defines them like this:

```yaml config.yaml
openai-compatibility:
  - name: "minimax"
    base-url: "https://api.minimax.io/v1"
    api-key-entries:
      - api-key: "YOUR_MINIMAX_KEY"
    models:
      - name: "music-2.6"
        alias: "ail-music"
      - name: "music-cover"
        alias: "ail-music-cover"

intelligence:
  matrix:
    music_generation: "ail-music"
    lyrics_generation: "ail-music"
```

Before routing, `/v1/music/generations` maps common spellings to these aliases:

| You send | Routed as |
|---|---|
| `music-2.6`, `music-2.6-free`, `ail-music`, `minimax/ail-music`, and anything starting with `minimax:music-2.` or `minimax/music-2.` | `ail-music` |
| `music-cover`, `music-cover-free`, `ail-music-cover`, `minimax/ail-music-cover`, and anything starting with `minimax:music-cover` or `minimax/music-cover` | `ail-music-cover` |
| anything else | unchanged |

So if `ail-music` / `ail-music-cover` are not configured, those names fail with `unknown provider for model ail-music`.

## POST /v1/music/generations

Generates a song. A synchronous call usually takes 30–90 s, so use a long client timeout.

### Request

<ParamField body="model" type="string">
  See the mapping above. Defaults to `intelligence.matrix.music_generation`; with neither, the request fails with `400`. The upstream model name is sent to MiniMax, and `music-2.6` is used if it is still empty.
</ParamField>

<ParamField body="lyrics" type="string">
  Song lyrics, optionally with section tags (`[Verse]`, `[Chorus]`, `[Bridge]`, ...). MiniMax requires it for `music-2.6` (code `2013` otherwise). For covers, if it is shorter than 10 characters, the lyrics MiniMax extracts from the reference are used.
</ParamField>

<ParamField body="prompt" type="string">Style description. Forwarded.</ParamField>

<ParamField body="audio_url | audio_base64" type="string">
  Reference audio for `music-cover`. The gateway first runs MiniMax's preprocessing step to get a `cover_feature_id`, then generates. A WAV `audio_base64` reference shorter than 30 s is rejected with `400`.
</ParamField>

<ParamField body="stream" type="boolean" default="false">
  `true` streams raw MP3 bytes (see below).
</ParamField>

Other fields (for example `output_format`, `cover_feature_id`) are forwarded to MiniMax.

### Response (sync)

```json
{
  "model": "music-2.6",
  "trace_id": "0632...",
  "data": {
    "audio": "<base64 MP3>",
    "format": "mp3",
    "size_bytes": 3150729,
    "duration_ms": 98298,
    "sample_rate": 44100,
    "channels": 2,
    "bitrate": 256000
  },
  "extra_info": {"music_duration": 98298, "music_sample_rate": 44100, "bitrate": 256000}
}
```

- MiniMax returns hex. The gateway re-encodes it as base64 in `data.audio`.
- If MiniMax returns a URL (for example with `output_format: "url"`), `data.format` is `"url"` and `data.audio_url` holds it.
- `model` is the upstream model name, not your alias.

### Streaming

With `"stream": true` the response is `200 Content-Type: audio/mpeg`: raw MP3 bytes arriving progressively, so playback can start before the song is finished. The first byte typically takes about 20 s.

- Errors before the first byte return a normal JSON error with the right status.
- Errors after bytes are flushed just close the connection. The MP3 frames received so far are still playable.
- An upstream stream that ends without audio returns `502`.

### Examples

<CodeGroup>
```bash Sync
curl -sS http://localhost:18080/v1/music/generations \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  --max-time 300 \
  -d '{"model": "ail-music", "prompt": "calm lo-fi piano, 60 bpm",
       "lyrics": "[Verse]\nCode flows through the night\n[Chorus]\nDebugging makes it right"}' \
  | jq -r .data.audio | base64 -d > song.mp3
```

```bash Stream
curl -sN http://localhost:18080/v1/music/generations \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "ail-music", "stream": true, "lyrics": "[Verse]\nNeon dreams"}' > song.mp3
```

```bash Cover
curl -sS http://localhost:18080/v1/music/generations \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  --max-time 300 \
  -d '{"model": "ail-music-cover", "prompt": "piano jazz rework",
       "audio_url": "https://example.com/reference.mp3"}'
```
</CodeGroup>

## POST /v1/music/lyrics

Generates structured lyrics. JSON in, JSON out, usually in a few seconds.

<ParamField body="model" type="string">
  Only used for routing; it is removed before the upstream call. Defaults to `intelligence.matrix.lyrics_generation`, then `music_generation`.
</ParamField>
<ParamField body="mode" type="string" default="write_full_song">`write_full_song` or `edit`.</ParamField>
<ParamField body="prompt" type="string">Theme or style of the song.</ParamField>
<ParamField body="lyrics" type="string">Existing lyrics to continue (for `edit`).</ParamField>
<ParamField body="title" type="string">Desired title.</ParamField>

The MiniMax response is returned unchanged:

```json
{
  "song_title": "Midnight Code",
  "style_tags": "lo-fi, chill, piano",
  "lyrics": "[Intro]\n\n[Verse]\nScreen glow bright...",
  "base_resp": {"status_code": 0, "status_msg": "success"}
}
```

```bash
curl http://localhost:18080/v1/music/lyrics \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt": "a calm lo-fi study session with gentle rain"}'
```

A common workflow is to call `/v1/music/lyrics`, then pass `style_tags` as `prompt` and `lyrics` to `/v1/music/generations`.

## Errors

MiniMax reports failures in `base_resp.status_code`. The gateway maps them to HTTP statuses:

| MiniMax code | HTTP | Meaning |
|---|---|---|
| `1002` | `429` | Rate limit |
| `1004`, `1008` | `401` | Invalid key / insufficient balance |
| `2013` | `400` | Invalid parameters (often missing `lyrics`) |
| `2061` | `402` | Plan does not include this model |
| other | `502` | Upstream error |

Gateway-level errors:

| Status | When |
|---|---|
| `400` | No model and no matrix slot configured, unknown model, or a WAV cover reference shorter than 30 s |
| `401` | Missing or invalid client API key |
| `501` | `music_generation not supported for provider "<name>"` (provider is not MiniMax) |
| `502` | Empty audio payload or empty stream from upstream |
