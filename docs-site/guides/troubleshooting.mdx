## Quick diagnostics

<Steps>
  <Step title="Is it running?">
    ```bash
    curl http://localhost:18080/health
    # {"status":"ok"}
    ```
  </Step>
  <Step title="Which version?">
    The first line of every run prints it:

    ```bash
    switchAILocal -h 2>&1 | head -1
    ```
  </Step>
  <Step title="Which providers and models are live?">
    ```bash
    curl http://localhost:18080/v1/providers -H "Authorization: Bearer sk-your-key"
    curl http://localhost:18080/v1/models -H "Authorization: Bearer sk-your-key"
    ```
  </Step>
  <Step title="Read the logs">
    | How it runs | Logs |
    | ----------- | ---- |
    | Foreground | The terminal (stdout) |
    | `ail start` | `server.log` in the repository (`ail logs -f`) |
    | `logging-to-file: true` | `logs/main.log` under the start folder or `$WRITABLE_PATH` |
    | Docker | `docker logs switchailocal` |

    Set `debug: true` for more detail (applies live).
  </Step>
</Steps>

## Startup

<AccordionGroup>
  <Accordion title="failed to read config file: open .../config.yaml: no such file or directory">
    The server only reads `./config.yaml` or the file given with `-config`.
    Create it (see [Quickstart](/quickstart)) or start from the folder that
    contains it. In Docker, mount it at `/app/config.yaml`.
  </Accordion>

  <Accordion title="invalid config path: ...">
    `-config` may not contain `..` or `~`, and absolute paths must be under
    your home folder, `/etc/`, `/usr/` or `/var/`. `/tmp/...` and `/opt/...`
    are rejected. Use `-config "$HOME/..."` (unquoted `~` expansion by the
    shell is fine).
  </Accordion>

  <Accordion title="invalid auth directory path: ...">
    The same rule applies to `auth-dir` after `~` is expanded. Use
    `"~/.switchailocal"` or a path under `/var/`.
  </Accordion>

  <Accordion title="remote-management.allow-remote is true but no secret is set">
    Set `remote-management.secret-key` or `MANAGEMENT_PASSWORD`, or set
    `allow-remote: false`.
  </Accordion>

  <Accordion title="failed to parse config file / virtual-models.<id> ...">
    Fix the YAML or the named virtual model (each member needs `id`,
    `provider`, `model`; ids must be unique; weights must not be negative; an
    exposed pool needs one enabled member).
  </Accordion>

  <Accordion title="bind: address already in use">
    Another process owns the port:

    ```bash
    lsof -i :18080
    ```

    Stop it or change `port`. A stale `ail` instance can be stopped with
    `ail stop`.
  </Accordion>

  <Accordion title="Server listens on an unexpected port">
    `port` is missing from `config.yaml`; without it the OS picks a random
    port and the startup line reads `API server started successfully on: :0`.
    Set `port: 18080`.
  </Accordion>

  <Accordion title="security warning: file ... has insecure permissions">
    Harmless but worth fixing: `chmod 600 config.yaml` and
    `chmod 700 ~/.switchailocal`.
  </Accordion>

  <Accordion title="Process exits right after starting when launched by an app">
    If `-password` is set, the server shuts down after 10 seconds without a
    `/keep-alive` call. Do not pass `-password` for a normal server
    ([details](/cli/server#flags)).
  </Accordion>
</AccordionGroup>

## Client requests

<AccordionGroup>
  <Accordion title='401 {"error":"Missing API key"} or {"error":"Invalid API key"}'>
    Send `Authorization: Bearer <key>` with a value from `api-keys` (exact
    match). `X-Api-Key`, `X-Goog-Api-Key`, `?key=` and `?auth_token=` also work.
  </Accordion>

  <Accordion title="unknown provider for model lmstudio:... (or vibe:...)">
    Only these prefixes are parsed: `geminicli`, `claudecli`, `codex`,
    `vibecli`, `ollama`, `opencode`, `gemini`, `claude`, `switchai`, `openai`,
    `openai-compat`. Use `vibecli:` for Vibe. For LM Studio, configure it as an
    OpenAI-compatible service ([Providers](/configuration/providers#lm-studio)).
  </Accordion>

  <Accordion title="Provider '...' is not active. Please configure it in config.yaml or use --login flags.">
    The prefix is valid but nothing provides it. Add the credential, start the
    local server, or install and log in to the CLI. `openai:` is not served by
    `codex-api-key`; use `codex:` or no prefix.
  </Accordion>

  <Accordion title="Model not found / empty /v1/models">
    - Check `GET /v1/providers` for what is registered.
    - CLIs are detected only at startup: install or log in, then restart.
    - Ollama models are listed only with `ollama.auto-discover: true`; with
      `ollama:` prefix any installed model routes anyway.
    - Aliases with `expose: false` or `visibility: private`, and prefixed IDs
      (`team/model`), route but are not listed.
    - Re-run discovery: `curl -X POST http://localhost:18080/v1/models/refresh -H "Authorization: Bearer sk-your-key"`.
  </Accordion>

  <Accordion title="CLI execution failed: ...">
    The message after `CLI execution failed:` comes from the CLI itself, for
    example a missing login or API key in its own config. Run the CLI by hand
    (`gemini`, `claude`, `codex`, `vibe`) as the same user to fix it.
  </Accordion>

  <Accordion title="failover[provider/transient]: ... connection refused">
    The upstream (often a local server) is not reachable at the configured
    `base-url`. Start it or fix the URL. From Docker use
    `host.docker.internal`.
  </Accordion>

  <Accordion title="429 Too Many Requests">
    From switchAILocal itself only if `performance.rate-limiter.enabled` is on
    (it sets `Retry-After`). Otherwise it is the provider's limit: add more
    credentials (they rotate per `routing.strategy`), or enable retries with
    both `request-retry` and `max-retry-interval`.
  </Accordion>

  <Accordion title="503 with Retry-After">
    `performance.load-shedding` rejected the request because more than
    `max-in-flight` requests were running.
  </Accordion>

  <Accordion title="Streams stop or proxies drop idle connections">
    Set `streaming.keepalive-seconds: 15` (keep-alives are off by default). A
    stream that sends nothing for `performance.streaming.stall-timeout`
    (default `60s`) is ended with an SSE error event; raise it for slow models.
    Long non-streaming calls are cut at `performance.provider-timeouts`
    (default `120s`).
  </Accordion>
</AccordionGroup>

## Logins and OAuth

<AccordionGroup>
  <Accordion title="Gemini, Qwen, iFlow or Antigravity login fails immediately">
    These flows need your own OAuth client: `GEMINI_CLIENT_ID` /
    `GEMINI_CLIENT_SECRET`, `QWEN_CLIENT_ID`, `IFLOW_CLIENT_ID` /
    `IFLOW_CLIENT_SECRET`, `ANTIGRAVITY_CLIENT_ID` /
    `ANTIGRAVITY_CLIENT_SECRET`. For Gemini, using the `gemini` CLI avoids this.
  </Accordion>

  <Accordion title="OAuth callback never arrives">
    Callbacks use fixed ports: Gemini `8085`, Claude `54545`, Codex `1455`,
    iFlow `11451`, Antigravity `51121`. Free the port, or on a remote machine use
    `-no-browser` with SSH port forwarding, or paste the redirect URL when the
    command prompts for it.
  </Accordion>
</AccordionGroup>

## Management API and dashboard

<AccordionGroup>
  <Accordion title='403 {"error":"remote management disabled"}'>
    The call did not come from a direct loopback connection (other machine,
    reverse proxy headers, or Docker port mapping). Set
    `remote-management.allow-remote: true` together with a `secret-key`.
  </Accordion>

  <Accordion title="401 missing management key / invalid management key">
    Send the plaintext secret as `X-Management-Key` or
    `Authorization: Bearer`. The value in `config.yaml` is a bcrypt hash and is
    not the key.
  </Accordion>

  <Accordion title="403 IP banned due to too many failed attempts">
    Five wrong keys from a remote IP block it for 30 minutes. Wait, or restart
    the server to clear the counter.
  </Accordion>

  <Accordion title="/management returns 404">
    `management.html` is not in `static/` next to `config.yaml` (release
    archives do not ship it), or `disable-control-panel` is `true`. See
    [Management dashboard](/guides/management-dashboard#where-the-page-comes-from).
  </Accordion>

  <Accordion title="Dashboard save fails with invalid_yaml ... time.Duration">
    Known issue in 0.6.2. Edit `config.yaml` directly; it reloads live.
  </Accordion>
</AccordionGroup>

## Docker

<AccordionGroup>
  <Accordion title="Container exits immediately">
    `docker logs switchailocal`. Usually `/app/config.yaml` is not mounted or
    not readable by the container user (UID `100`).
  </Accordion>

  <Accordion title="Port published but connection refused">
    Set `host: ""` in the container's config; `127.0.0.1` is not reachable
    through a published port.
  </Accordion>

  <Accordion title="Permission denied on config.yaml, credentials or logs">
    On Linux hosts: `sudo chown 100:101 config.yaml` and
    `sudo chown -R 100:101 ~/.switchailocal ./logs`.
  </Accordion>

  <Accordion title="bridge request failed / bridge returned error (401 or 403)">
    `REMOTE_COMMAND_HOST` is set (the bundled compose file sets it), so CLI
    calls go to a host bridge, which 0.6.2 cannot authenticate to. Set
    `REMOTE_COMMAND_HOST: ""` in the compose file.
  </Accordion>

  <Accordion title="Cannot reach Ollama on the host">
    Use `http://host.docker.internal:11434` with
    `extra_hosts: ["host.docker.internal:host-gateway"]`, and on Linux make
    Ollama listen on a reachable interface (`OLLAMA_HOST=0.0.0.0`).
  </Accordion>

  <Accordion title="pull access denied for traylinx/switchailocal">
    That Docker Hub name is not published. Use
    `ghcr.io/traylinx/switchailocal:<version>`
    ([Docker deployment](/guides/docker-deployment)).
  </Accordion>
</AccordionGroup>

## Intelligence features

<AccordionGroup>
  <Accordion title="Embedding model not found: all-MiniLM-L6-v2">
    Run `scripts/download-embedding-model.sh` (downloads to
    `~/.switchailocal/models/`) and make ONNX Runtime available
    (`ONNXRUNTIME_LIB_PATH` if it is not found automatically). Until then the
    semantic tier and semantic cache stay off; everything else works.
  </Accordion>

  <Accordion title="Failed to load skills: skills directory does not exist">
    `intelligence.skills.directory` (default `plugins/cortex-router/skills`) is
    relative to the start folder. Start from the repository root, use an
    absolute path, or disable `intelligence.skills`.
  </Accordion>

  <Accordion title="Router model errors with model: auto">
    `intelligence.router-model` must be a model your providers serve. Change it
    or disable `intelligence`.
  </Accordion>
</AccordionGroup>

## Memory CLI

<AccordionGroup>
  <Accordion title="memory commands show nothing although the server records">
    The CLI reads `<auth-dir>/memory`, the server writes `memory.base-dir`.
    Point both at the same absolute folder
    ([Memory commands](/cli/memory#where-the-data-lives)).
  </Accordion>
  <Accordion title="A folder named ~ appeared in my working directory">
    The memory CLI does not expand `~` in `auth-dir`. Remove the folder and use
    an absolute `auth-dir`.
  </Accordion>
</AccordionGroup>

## Reporting a bug

Open an issue at
[github.com/traylinx/switchAILocal/issues](https://github.com/traylinx/switchAILocal/issues)
with:

1. The version line (`switchAILocal -h 2>&1 | head -1`).
2. OS and install method (archive, Docker tag, source commit).
3. The exact request and the full error response.
4. Relevant log lines with `debug: true`.
5. The relevant `config.yaml` section with every key and secret removed.
