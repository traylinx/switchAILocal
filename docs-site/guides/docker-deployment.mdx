## Image

| Item | Value |
| ---- | ----- |
| Registry | `ghcr.io/traylinx/switchailocal` |
| Tags | `X.Y.Z` per release (for example `0.6.2`, no `v`), `sha-<commit>` per build |
| Platforms | `linux/amd64`, `linux/arm64` |
| Working directory | `/app` |
| Command | `./switchAILocal` (reads `/app/config.yaml`) |
| User | `appuser`, UID `100`, GID `101`, home `/home/appuser` |
| Port | `18080` (exposed; the actual port is whatever `config.yaml` sets) |
| Bundled | `/app/static/management.html`, `/app/plugins`, `/app/config.example.yaml`, the `gemini` CLI, Node.js |

Pin a version tag. `latest` and `main` exist from older builds but are no
longer updated by the release pipeline, so they can be months behind.

## Quick start

<Steps>
  <Step title="Write a config for the container">
    ```yaml config.yaml
    host: ""              # must be empty in a container
    port: 18080
    auth-dir: "~/.switchailocal"
    api-keys:
      - "sk-your-key"
    remote-management:
      secret-key: "a-long-random-secret"
    ```

    `auth-dir: "~/.switchailocal"` resolves to `/home/appuser/.switchailocal`
    inside the container.
  </Step>

  <Step title="Run">
    ```bash
    docker run -d --name switchailocal \
      -p 18080:18080 \
      -v "$PWD/config.yaml:/app/config.yaml" \
      -v "$HOME/.switchailocal:/home/appuser/.switchailocal" \
      --add-host host.docker.internal:host-gateway \
      --restart unless-stopped \
      ghcr.io/traylinx/switchailocal:0.6.2
    ```
  </Step>

  <Step title="Verify">
    ```bash
    curl http://localhost:18080/health
    docker logs switchailocal | head -20
    ```
  </Step>
</Steps>

Without a mounted `/app/config.yaml` the container exits right away with
`failed to read config file: open /app/config.yaml: no such file or directory`.

## Docker Compose

The repository's `docker-compose.yml`:

```yaml docker-compose.yml
services:
  switchailocal:
    image: ${SWITCH_AI_IMAGE:-traylinx/switchailocal:latest}
    pull_policy: always
    build:
      context: .
      dockerfile: Dockerfile
      args:
        VERSION: ${VERSION:-dev}
        COMMIT: ${COMMIT:-none}
        BUILD_DATE: ${BUILD_DATE:-unknown}
    container_name: switchailocal
    environment:
      TZ: ${TZ:-UTC}
      REMOTE_COMMAND_HOST: ${REMOTE_COMMAND_HOST:-http://host.docker.internal:18888}
    extra_hosts:
      - "host.docker.internal:host-gateway"
    ports:
      - "18080:18080"
    volumes:
      - ./config.yaml:/app/config.yaml
      - ${HOME}/.switchailocal:/home/appuser/.switchailocal
      - ./logs:/app/logs
      - ./plugins:/app/plugins
    restart: unless-stopped
```

The default image name `traylinx/switchailocal:latest` is not published on
Docker Hub, so a plain `docker compose up -d` builds the image from the
checkout. Choose explicitly:

<CodeGroup>
```bash Published image
SWITCH_AI_IMAGE=ghcr.io/traylinx/switchailocal:0.6.2 docker compose up -d --no-build
```

```bash Build from source
VERSION=$(git describe --tags --always) COMMIT=$(git rev-parse HEAD) \
BUILD_DATE=$(date -u +%Y-%m-%dT%H:%M:%SZ) SWITCH_AI_IMAGE=switchailocal:local \
  docker compose up -d --build
```

```bash Interactive helper
# 1) docker compose up -d --no-build (set SWITCH_AI_IMAGE first)
# 2) build as switchailocal:local, then start it
./docker-build.sh
```
</CodeGroup>

`./ail.sh start -d` runs `docker compose up -d --remove-orphans` (add `-b` for
`--build`); `./ail.sh stop -d` and `./ail.sh logs -d -f` manage it.

| Variable | Default | Meaning |
| -------- | ------- | ------- |
| `SWITCH_AI_IMAGE` | `traylinx/switchailocal:latest` | Image to run or tag the build as |
| `TZ` | `UTC` | Container time zone |
| `REMOTE_COMMAND_HOST` | `http://host.docker.internal:18888` | Send CLI executions to a host bridge (see below) |
| `VERSION`, `COMMIT`, `BUILD_DATE` | `dev`, `none`, `unknown` | Build arguments embedded in the binary |

## Volumes and permissions

| Host | Container | Purpose |
| ---- | --------- | ------- |
| `./config.yaml` | `/app/config.yaml` | Configuration (required) |
| `~/.switchailocal` | `/home/appuser/.switchailocal` | Credential files from logins and the panel |
| `./logs` | `/app/logs` | `main.log` and request logs, when enabled |
| `./plugins` | `/app/plugins` | Lua plugins; replaces the bundled folder |

The server runs as UID `100`. It must be able to **read and write**
`config.yaml` (it hashes `secret-key` and saves panel edits in place) and write
`auth-dir` and `logs/`. On Linux hosts:

```bash
sudo chown 100:101 config.yaml && chmod 600 config.yaml
sudo chown -R 100:101 ~/.switchailocal ./logs
```

Docker Desktop on macOS and Windows maps file ownership for you.

Mounting `./plugins` over `/app/plugins` hides the plugins shipped in the image.
Drop that mount if you do not maintain your own plugins.

## Reaching services on the host

Inside the container `localhost` is the container. Use `host.docker.internal`
(enabled by `extra_hosts` / `--add-host ... host-gateway`):

```yaml config.yaml
ollama:
  enabled: true
  base-url: "http://host.docker.internal:11434"

openai-compatibility:
  - name: "lm-studio"
    base-url: "http://host.docker.internal:1234/v1"
```

On Linux, make the host service listen on an address the container can reach
(for Ollama: `OLLAMA_HOST=0.0.0.0`).

## CLI providers in Docker

The image contains the `gemini` CLI only. Its login state lives in the
container user's home, so log in inside the container or mount the CLI's
config folder.

`REMOTE_COMMAND_HOST` makes the gateway send every CLI execution to a
[bridge agent](/installation#bridge-agent) on the host instead of running it in
the container. In 0.6.2 the gateway does not send the bridge's required secret,
so these calls are rejected. Clear the variable in `docker-compose.yml` (an
empty shell variable is not enough, because the file uses
`${REMOTE_COMMAND_HOST:-...}`, which falls back to the default when empty):

```yaml docker-compose.yml
environment:
  REMOTE_COMMAND_HOST: ""
```

With `docker run`, simply do not pass `-e REMOTE_COMMAND_HOST`.

## Health check

The image includes BusyBox `wget`:

```yaml docker-compose.yml
services:
  switchailocal:
    healthcheck:
      test: ["CMD", "wget", "-q", "--spider", "http://127.0.0.1:18080/health"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 20s
```

## Management panel and API from the host

The panel is served at `http://localhost:18080/management`. Requests reaching
the container through a published port come from the Docker network, not from
loopback, so the management API treats them as **remote**. To use the panel
from your browser, set a secret and allow remote management:

```yaml config.yaml
remote-management:
  allow-remote: true
  secret-key: "a-long-random-secret"
```

Without `allow-remote`, management calls from the host get
`403 remote management disabled`. Calls from inside the container
(`docker exec switchailocal wget -qO- --header "X-Management-Key: ..." http://127.0.0.1:18080/v0/management/config`)
count as local.

## Updating

```bash
docker pull ghcr.io/traylinx/switchailocal:<new-version>
docker rm -f switchailocal
# re-run the docker run command with the new tag
```

With Compose, change `SWITCH_AI_IMAGE` to the new tag and run
`docker compose up -d --no-build`. For fleets of Linux hosts that should follow
a reviewed release channel with rollback, see
[Managed server updates](/guides/managed-server).

## Troubleshooting

<AccordionGroup>
  <Accordion title="Container exits immediately">
    `docker logs switchailocal`. Usually `/app/config.yaml` is not mounted, or
    the file is not readable by UID 100.
  </Accordion>
  <Accordion title="Connection refused from the host">
    Set `host: ""` in the config. `127.0.0.1` inside the container is not
    reachable through the published port. Also check that `port` matches the
    container side of `-p`.
  </Accordion>
  <Accordion title="Permission denied writing config.yaml or credentials">
    `chown 100:101` the mounted files and folders (Linux hosts).
  </Accordion>
  <Accordion title="CLI provider fails with a bridge error">
    Clear `REMOTE_COMMAND_HOST` (see [CLI providers in Docker](#cli-providers-in-docker)).
  </Accordion>
  <Accordion title="Ollama unreachable">
    Use `http://host.docker.internal:11434` and make sure Ollama listens on a
    reachable interface.
  </Accordion>
</AccordionGroup>
