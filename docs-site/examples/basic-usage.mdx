## Overview

These examples assume:

- switchAILocal is running on `http://localhost:18080`
- `config.yaml` contains `api-keys: ["sk-test-123"]` (use your own key)
- at least one provider is set up, e.g. Ollama with `llama3.2` pulled

```yaml config.yaml
port: 18080
api-keys:
  - "sk-test-123"
ollama:
  enabled: true
  base-url: "http://localhost:11434"
  auto-discover: true
```

Any OpenAI-compatible client works; Python and Node.js use the official `openai` packages ([Python](/sdk/python), [Node.js](/sdk/nodejs)).

## Simple chat completion

<CodeGroup>
```bash cURL
curl http://localhost:18080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-test-123" \
  -d '{
    "model": "ollama:llama3.2",
    "messages": [{"role": "user", "content": "Hello!"}]
  }'
```

```python Python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:18080/v1", api_key="sk-test-123")

completion = client.chat.completions.create(
    model="ollama:llama3.2",
    messages=[{"role": "user", "content": "Hello!"}],
)
print(completion.choices[0].message.content)
```

```javascript Node.js
import OpenAI from 'openai';

const client = new OpenAI({ baseURL: 'http://localhost:18080/v1', apiKey: 'sk-test-123' });

const completion = await client.chat.completions.create({
  model: 'ollama:llama3.2',
  messages: [{ role: 'user', content: 'Hello!' }],
});
console.log(completion.choices[0].message.content);
```
</CodeGroup>

## Selecting a model

The `model` string is the only routing input. switchAILocal resolves it in this order (`sdk/api/handlers/handlers.go`):

1. **Provider prefix** `provider:model` for a known provider name: goes only to that provider.
2. **Lua plugins** (if enabled) may rewrite the model, e.g. the Cortex Router for `auto`/`cortex`.
3. **Virtual model** from `virtual-models`: a member is picked by capability and weight.
4. **Auto-routing** for `auto` or `auto:<intent>` when `auto-routing.enabled: true`.
5. **Registered model ID or alias**: every provider that registered the ID is a candidate; credentials rotate per `routing.strategy`.

<Tabs>
  <Tab title="Provider prefix">
    ```python
    # Local Ollama
    client.chat.completions.create(model="ollama:llama3.2", messages=msgs)
    # Gemini CLI installed and logged in on this machine
    client.chat.completions.create(model="geminicli:gemini-2.5-pro", messages=msgs)
    # Claude Code CLI
    client.chat.completions.create(model="claudecli:claude-sonnet-4-5", messages=msgs)
    ```
  </Tab>
  <Tab title="Alias">
    ```yaml config.yaml
    claude-api-key:
      - api-key: "YOUR_ANTHROPIC_KEY"
        models:
          - name: "claude-sonnet-4-5"
            alias: "sonnet"
    ```
    ```python
    client.chat.completions.create(model="sonnet", messages=msgs)
    ```
  </Tab>
  <Tab title="Virtual model">
    ```python
    # ail-compound is a pool defined under virtual-models in config.yaml
    client.chat.completions.create(model="ail-compound", messages=msgs)
    ```
    See [Virtual models](/advanced/virtual-models).
  </Tab>
  <Tab title="Auto">
    ```python
    client.chat.completions.create(model="auto", messages=msgs)
    client.chat.completions.create(model="auto:coding", messages=msgs)
    ```
    See [Intelligent routing](/examples/intelligent-routing).
  </Tab>
</Tabs>

### Valid provider prefixes

| Prefix | Backend | Needs |
|--------|---------|-------|
| `ollama:` | Ollama | `ollama.enabled: true` |
| `geminicli:` | Google Gemini CLI | `gemini` on `PATH`, logged in |
| `claudecli:` | Claude Code CLI | `claude` on `PATH`, logged in |
| `vibecli:` | Mistral Vibe CLI | `vibe` on `PATH` |
| `codex:` | OpenAI Codex (Codex CLI on `PATH`, `--codex-login` OAuth, or `codex-api-key`) | see [Provider setup](/guides/setup-providers) |
| `opencode:` | OpenCode server | `opencode.enabled: true` |
| `gemini:` | Gemini API | `gemini-api-key` or OAuth |
| `claude:` | Anthropic API | `claude-api-key` or `--claude-login` |
| `switchai:` | switchAI cloud | `switchai-api-key` |
| `openai:`, `openai-compat:` | An `openai-compatibility` entry with exactly that `name` | config entry |

Other `name:model` strings are not prefixes. They work only if a provider registered that exact string, for example an `openai-compatibility` alias such as `groq:gpt-oss-20b`. LM Studio models are addressed by their plain ID (no `lmstudio:` prefix). With `prefix: team-a` on a credential, its models are also reachable as `team-a/<model>`.

## List available models

<CodeGroup>
```bash cURL
curl http://localhost:18080/v1/models -H "Authorization: Bearer sk-test-123"
```

```python Python
for m in client.models.list().data:
    print(m.id, m.owned_by)
```

```javascript Node.js
const models = await client.models.list();
for (const m of models.data) console.log(m.id, m.owned_by);
```
</CodeGroup>

Example response:

```json
{
  "object": "list",
  "data": [
    {"id": "llama3.2:latest", "object": "model", "created": 1730000000, "owned_by": "ollama", "capabilities": ["text"]},
    {"id": "sonnet", "object": "model", "created": 1730000000, "owned_by": "claude", "capabilities": ["text"]}
  ]
}
```

Notes on what the list contains:

- Aliases with `expose: false` or `visibility: private`, and `prefix/model` IDs (unless `force-model-prefix: true`), are routable but hidden.
- If any listed model ID starts with `ail-`, the list switches to **ail-only mode** and shows only `ail-*` IDs.
- `?modality=text|image|audio|embedding|vision` filters by declared capability.

Provider-level view, with model counts and status:

```bash
curl "http://localhost:18080/v1/providers?filter=active" -H "Authorization: Bearer sk-test-123"
```

## Multi-turn, system prompts and parameters

```python
messages = [
    {"role": "system", "content": "You are a concise assistant. Answer in one sentence."},
    {"role": "user", "content": "What is a goroutine?"},
]
first = client.chat.completions.create(model="ollama:llama3.2", messages=messages, temperature=0.2)
messages.append({"role": "assistant", "content": first.choices[0].message.content})
messages.append({"role": "user", "content": "And a channel?"})

second = client.chat.completions.create(
    model="ollama:llama3.2",
    messages=messages,
    temperature=0.2,
    max_tokens=200,
)
```

switchAILocal is stateless for chat: send the whole history every time. Parameters are translated to each backend's format; CLI providers receive the flattened conversation as a prompt and ignore sampling parameters.

## Other API formats

The same server also speaks:

| Endpoint | Format |
|----------|--------|
| `POST /v1/responses` | OpenAI Responses API |
| `POST /v1/messages` | Anthropic Messages API (`x-api-key` header accepted) |
| `POST /v1beta/models/{model}:generateContent` | Gemini API (`x-goog-api-key` or `?key=` accepted) |
| `POST /openai/v1/...` | Strict OpenAI shapes for `models`, `chat/completions`, `completions`, `embeddings`, `images/*` |

```bash
curl http://localhost:18080/v1/messages \
  -H "x-api-key: sk-test-123" \
  -H "Content-Type: application/json" \
  -d '{"model": "ollama:llama3.2", "max_tokens": 256, "messages": [{"role": "user", "content": "Hello"}]}'
```

## Error handling

```python
from openai import APIConnectionError, APIStatusError

try:
    client.chat.completions.create(model="ollama:llama3.2", messages=[{"role": "user", "content": "Hi"}])
except APIConnectionError:
    print("Server not reachable")
except APIStatusError as e:
    print(e.status_code, e.response.text)
```

Errors use the OpenAI shape `{"error": {"message", "type", "code"}}`.

| Status | Meaning | Fix |
|--------|---------|-----|
| 401 | Missing or invalid client key | Use a key from `api-keys` |
| 400 `unknown provider for model X` | Nothing registered `X` | Check `/v1/models`, prefix spelling |
| 503 `Provider 'x' is not active` | Known prefix, no credentials | Configure or log in to that provider |
| 429 `model_cooldown` | All credentials cooling down after errors | Wait `Retry-After` seconds, add credentials |
| 422 `no_eligible_backend` | Virtual model has no member for this request type | Add a member with the needed capability |
| 5xx | Upstream failure after retries | Check server logs |
