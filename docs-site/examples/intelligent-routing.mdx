## Overview

Send `model: "auto"` and let switchAILocal pick the backend. Three mechanisms can answer that request; they are checked in this order (`sdk/api/handlers/handlers.go`):

| Order | Mechanism | Handles | Configure |
|-------|-----------|---------|-----------|
| 1 | **Cortex Router** Lua plugin | `auto`, `cortex` (exact) | `plugin:` + `intelligence:` — [Cortex Router](/intelligent-systems/cortex-router) |
| 2 | **Auto-routing engine** | `auto`, `auto:<intent>`, `cortex`, empty model | `auto-routing:` — [Auto-routing setup](/guides/auto-routing-setup) |
| 3 | Legacy fallback | `auto` | none: first available registered model |

If the Cortex plugin is loaded it claims `auto`/`cortex`, so the auto-routing engine only sees `auto:<intent>`. Explicit models (`ollama:llama3.2`, `ail-compound`, an alias) bypass all three.

The examples assume `api-keys: ["sk-test-123"]` and Ollama running locally.

## Example 1: score-based routing with intent hints

The smallest setup. No plugin, no classifier model, no embeddings.

```yaml config.yaml
api-keys:
  - "sk-test-123"
ollama:
  enabled: true
  base-url: "http://localhost:11434"
  auto-discover: true
auto-routing:
  enabled: true
```

```bash
curl -i http://localhost:18080/v1/chat/completions \
  -H "Authorization: Bearer sk-test-123" \
  -H "Content-Type: application/json" \
  -d '{"model": "auto:coding", "messages": [{"role": "user", "content": "Write a binary search in Go"}]}'
```

Response headers tell you what was picked:

```text
X-Auto-Routed: true
X-Selected-Model: llama3.2:latest
X-Selected-Provider: llama3.2
```

<Note>
`X-Selected-Provider` is derived from the text before the first `:` of the selected model ID, so for Ollama IDs like `llama3.2:latest` it is not the provider name. The request is still served; see the limitations in [Auto-routing setup](/guides/auto-routing-setup).
</Note>

Read headers from Python with `with_raw_response`:

```python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:18080/v1", api_key="sk-test-123")
raw = client.chat.completions.with_raw_response.create(
    model="auto:coding",
    messages=[{"role": "user", "content": "Write a binary search in Go"}],
)
print(raw.headers.get("x-selected-model"))
print(raw.parse().choices[0].message.content)
```

Intent hints after `auto:` are normalised: `code`/`programming`/`dev` → `coding`, `think`/`math`/`logic` → `reasoning`, `write`/`story`/`poem` → `creative`, `quick`/`simple`/`chat` → `fast`, `image`/`screenshot` → `vision`, `private`/`local`/`sensitive` → `secure`. A hint only narrows the candidates if you define `auto-routing.intent-matrix`:

```yaml config.yaml
auto-routing:
  enabled: true
  intent-matrix:
    coding: ["qwen2.5-coder:7b"]
    secure: ["llama3.2:latest"]
  disabled-providers: []        # providers listed here are never selected
```

## Example 2: content-based routing with the Cortex Router

Route by what the prompt contains: code to a coding model, images to a vision model, e-mail addresses to a local model.

```yaml config.yaml
api-keys:
  - "sk-test-123"
ollama:
  enabled: true
  auto-discover: true

plugin:
  enabled: true
  plugin-dir: "./plugins"            # no default; relative to the server's working directory
  enabled-plugins:
    - "cortex-router"

intelligence:
  enabled: true
  router-model: "ollama:qwen2.5:0.5b"  # small, fast classifier
  confidence:
    enabled: true                      # needed to parse the classifier reply
  matrix:
    coding: "ollama:qwen2.5-coder:7b"
    reasoning: "ail-compound"
    creative: "ail-compound"
    fast: "ollama:llama3.2"
    secure: "ollama:llama3.2"
    vision: "ollama:llava"
    long_ctx: "ail-compound"
    research: "ail-compound"
    chat: "ollama:llama3.2"
    # The plugin errors out if these three are missing, even if unused:
    image_gen: "ail-image"
    transcription: "ail-transcribe"
    speech: "ail-speech"
```

Replace `ail-compound` with a [virtual model](/advanced/virtual-models) or alias you actually have.

```python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:18080/v1", api_key="sk-test-123")

prompts = {
    "code": "Fix this:\n```python\ndef add(a, b): return a - b\n```",
    "pii": "Write a polite reply to jane.doe@example.com about the invoice",
    "long": "Summarise: " + "lorem ipsum " * 500,
    "other": "What is the capital of Portugal?",
}
for name, text in prompts.items():
    r = client.chat.completions.create(model="auto", messages=[{"role": "user", "content": text}])
    print(name, "->", r.model)
```

Expected decisions (visible in the server log with the `[LUA]` prefix):

| Prompt | Tier | Slot |
|--------|------|------|
| Contains a code fence, `def x`, `function x(` or `class X` | reflex | `coding` |
| Contains an e-mail address | reflex | `secure` |
| Longer than 4000 characters | reflex | `long_ctx` |
| Has `image_url` content | reflex | `vision` |
| Anything else | cognitive (router model) | from the classifier's intent, else `fast` |

```text
[LUA] Reflex: Code detected -> Coding Model
[LUA] Final Routing -> Provider: ollama, Model: qwen2.5-coder:7b
```

The Cortex path does not set `X-Auto-Routed` headers. When a skill matches, the response carries `X-Matched-Skill`.

### Shortcut: send every `auto` request to one model

```yaml config.yaml
intelligence:
  matrix:
    auto: "ail-compound"     # no tiers, no classifier call
    image_gen: "ail-image"
    transcription: "ail-transcribe"
    speech: "ail-speech"
```

This gives clients a stable `auto` name while you change the backend in config.

## Example 3: add semantic matching

Skip the classifier call for clear-cut prompts by matching them against built-in intents with the local embedding engine:

```yaml config.yaml
intelligence:
  enabled: true
  embedding:
    enabled: true
    model: "all-MiniLM-L6-v2"
  semantic-tier:
    enabled: true
    confidence-threshold: 0.85
  semantic-cache:
    enabled: true
    similarity-threshold: 0.95
  skills:
    enabled: true
    directory: "plugins/cortex-router/skills"
  skill-matching:
    enabled: true
```

Requirements: ONNX Runtime installed and `./scripts/download-embedding-model.sh` run once. See [Local embedding engine](/sdk/embedding/overview) for setup and the intents file location.

A prompt that matches an intent at ≥ 0.85 is routed without calling the router model:

```text
[LUA] Semantic: reasoning (0.91 confidence, 4ms)
[LUA] Skill Match: go-expert (0.84 confidence)
```

## Overriding or bypassing routing

- Use an explicit model to bypass every mechanism: `model="ollama:llama3.2"`.
- A provider prefix on `auto` (for example `ollama:auto`) also bypasses Cortex and auto-routing; the provider receives the model name `auto`.
- To compare decisions, send the same prompt as `auto` and as `auto:<intent>` with the Cortex plugin unloaded.

## Defaults and limits

| Item | Value |
|------|-------|
| `auto-routing.enabled` | `false` |
| `intelligence.enabled` | `false` |
| Cortex reflex long-input threshold | 4000 characters |
| Cortex semantic threshold | 0.85 (skill match 0.80) |
| Cognitive low-confidence escalation | below 0.60 → `reasoning` |
| `cascade` | advisory only: flags low-quality answers in metadata, never re-sends |

## Troubleshooting

<AccordionGroup>
  <Accordion title="auto returns 400 unknown provider for model auto">
    No mechanism claimed the request and no model is registered. Enable `auto-routing` or the Cortex plugin, or make sure at least one provider has models.
  </Accordion>
  <Accordion title="Cortex plugin is loaded but auto is not routed">
    Check `plugin-dir` is set and points at the `plugins` folder, that `image_gen`, `transcription` and `speech` are in `intelligence.matrix`, and run with `debug: true` to see `[LUA]` lines.
  </Accordion>
  <Accordion title="Every Cortex request goes to the fast slot">
    The cognitive tier needs `intelligence.enabled: true`, `intelligence.confidence.enabled: true` and a reachable `router-model`.
  </Accordion>
  <Accordion title="Matrix value with a colon goes to the wrong provider">
    Cortex splits matrix values at the **first** colon into provider and model. Write Ollama models with tags as `ollama:llama3.2:latest`, not `llama3.2:latest`. Aliases that contain a colon (for example `groq:gpt-oss-20b`) are split too; point the slot at a virtual model or a colon-free alias instead. `matrix.auto` is the exception and is passed through unchanged.
  </Accordion>
  <Accordion title="No X-Auto-Routed header">
    The request was handled by the Cortex plugin or by the legacy fallback, or `auto-routing.enabled` is false. See [Auto-routing setup](/guides/auto-routing-setup).
  </Accordion>
</AccordionGroup>
