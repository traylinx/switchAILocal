## Overview

Set `"stream": true` on `/v1/chat/completions` (or `/v1/completions`, `/v1/responses`, `/v1/messages`) to receive the answer incrementally as Server-Sent Events. The examples assume `api-keys: ["sk-test-123"]` and an Ollama model; any routable model works.

**Use streaming for** chat UIs, long outputs and anything where time-to-first-token matters. **Skip it** when you post-process the full answer anyway; non-streaming requests get more transparent retries (see [Errors and retries](#errors-and-retries)).

## Basic streaming

<CodeGroup>
```python Python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:18080/v1", api_key="sk-test-123")

stream = client.chat.completions.create(
    model="ollama:llama3.2",
    messages=[{"role": "user", "content": "Tell me a short story"}],
    stream=True,
)
for chunk in stream:
    if chunk.choices and chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="", flush=True)
print()
```

```javascript Node.js
import OpenAI from 'openai';

const client = new OpenAI({ baseURL: 'http://localhost:18080/v1', apiKey: 'sk-test-123' });

const stream = await client.chat.completions.create({
  model: 'ollama:llama3.2',
  messages: [{ role: 'user', content: 'Tell me a short story' }],
  stream: true,
});
for await (const chunk of stream) {
  process.stdout.write(chunk.choices[0]?.delta?.content ?? '');
}
```

```bash cURL
curl -N http://localhost:18080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-test-123" \
  -d '{
    "model": "ollama:llama3.2",
    "messages": [{"role": "user", "content": "Tell me a short story"}],
    "stream": true
  }'
```

## Wire format

Response headers: `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `X-Accel-Buffering: no`. Each event is `data: <json>` followed by a blank line, and the stream ends with `data: [DONE]`:

```text
data: {"id":"chatcmpl-1","object":"chat.completion.chunk","created":1730000000,"model":"llama3.2","choices":[{"index":0,"delta":{"role":"assistant","content":"Once"},"finish_reason":null}]}

data: {"id":"chatcmpl-1","object":"chat.completion.chunk","created":1730000000,"model":"llama3.2","choices":[{"index":0,"delta":{"content":" upon"},"finish_reason":null}]}

: keep-alive

data: {"id":"chatcmpl-1","object":"chat.completion.chunk","created":1730000000,"model":"llama3.2","choices":[{"index":0,"delta":{},"finish_reason":"stop"}]}

data: [DONE]
```

- Lines starting with `:` are SSE comments (keep-alives). Ignore them; the official SDKs already do.
- For [virtual models](/advanced/virtual-models) the `model` field in every chunk is rewritten to the public name you requested (for example `ail-compound`), not the backend model.
- `/v1/messages` streams Anthropic-format events and `/v1/responses` streams Responses-API events instead of `chat.completion.chunk`.

## Raw SSE parsing

```python
import json
import requests

resp = requests.post(
    "http://localhost:18080/v1/chat/completions",
    headers={"Authorization": "Bearer sk-test-123"},
    json={"model": "ollama:llama3.2", "messages": [{"role": "user", "content": "Tell me a joke"}], "stream": True},
    stream=True,
    timeout=(5, 300),
)
resp.raise_for_status()  # pre-stream failures arrive as a normal HTTP error

for raw in resp.iter_lines():
    if not raw or raw.startswith(b":"):   # blank line or keep-alive comment
        continue
    data = raw.decode()[len("data: "):]
    if data == "[DONE]":
        break
    event = json.loads(data)
    if "error" in event:                  # mid-stream failure
        raise RuntimeError(event["error"]["message"])
    delta = event["choices"][0]["delta"].get("content")
    if delta:
        print(delta, end="", flush=True)
```

## Server-side streaming settings

```yaml config.yaml
streaming:
  keepalive-seconds: 15     # ": keep-alive" comment interval; 0 or unset = off
  bootstrap-retries: 2      # retries before the first byte is sent; unset = 0

performance:
  streaming:
    first-byte-timeout: 15s # wait for the first upstream chunk
    stall-timeout: 60s      # max gap between chunks after the first one
    per-provider:           # optional first-byte overrides by provider key
      minimax: 30s
```

| Setting | Default when omitted | Effect |
|---------|----------------------|--------|
| `streaming.keepalive-seconds` | off | Sends `: keep-alive` comments so proxies and clients with idle timeouts keep the connection open during long thinking phases |
| `streaming.bootstrap-retries` | 0 | If the upstream fails before any byte reaches the client (401, 403, 408, 429, 5xx, or no status), retry up to N times, allowing credential rotation |
| `performance.streaming.first-byte-timeout` | 15s | Cancels a stream that produced no first chunk |
| `performance.streaming.stall-timeout` | 60s | Cancels a stream whose chunks stop arriving |

<Note>
The first-byte and stall watchdog is applied to `openai-compatibility` providers (Groq, DeepSeek, MiniMax, Kimi, any custom entry) and to music streams. Other provider types rely on their HTTP client and the overall request context. `config.example.yaml` ships `keepalive-seconds: 15` and `bootstrap-retries: 2`; the code defaults apply only when the keys are absent.
</Note>

## Errors and retries

What you see depends on **when** the failure happens:

| When | What the client gets | Recovery |
|------|---------------------|----------|
| Before the first chunk | A normal HTTP error response (JSON body, real status code, e.g. 429 with `Retry-After`) | switchAILocal has already tried the other credentials and providers for the model, `bootstrap-retries`, and virtual-model fallback if enabled. The SDK raises a regular API error |
| After chunks were sent | An SSE event `data: {"error":{"message":...,"type":...,"code":...}}`, then the stream closes (no `[DONE]`) | Not retried transparently. Retry the request in your client |

```python
from openai import APIError, APIStatusError

def stream_with_retry(messages, attempts=2):
    for attempt in range(attempts):
        text = ""
        try:
            stream = client.chat.completions.create(model="ail-compound", messages=messages, stream=True)
            for chunk in stream:
                if chunk.choices and chunk.choices[0].delta.content:
                    text += chunk.choices[0].delta.content
            return text
        except APIStatusError as e:          # failed before streaming started
            retryable = e.status_code == 429 or e.status_code >= 500
            if attempt == attempts - 1 or not retryable:
                raise
        except APIError:                     # error event after chunks were sent
            if attempt == attempts - 1:
                raise
```

The OpenAI Python SDK raises `APIError` when it reads a mid-stream `{"error": ...}` event; pre-stream failures raise its subclass `APIStatusError`.

## CLI providers

`geminicli:` and `claudecli:` stream token deltas from the CLI's `stream-json` output. `vibecli:` and `codex:` (CLI) do not support streaming output: the request runs to completion and the full answer is delivered as a single chunk. CLI calls are capped at 5 minutes.

```python
stream = client.chat.completions.create(
    model="geminicli:gemini-2.5-pro",
    messages=[{"role": "user", "content": "Explain quantum computing in three paragraphs"}],
    stream=True,
)
```

## Measuring time to first token

```python
import time

start = time.perf_counter()
first = None
chunks = 0
for chunk in client.chat.completions.create(
    model="ollama:llama3.2",
    messages=[{"role": "user", "content": "Write a haiku about the sea"}],
    stream=True,
):
    if chunk.choices and chunk.choices[0].delta.content:
        first = first or time.perf_counter()
        chunks += 1
total = time.perf_counter() - start
print(f"TTFT {first - start:.2f}s, total {total:.2f}s, {chunks} chunks")
```

## Music streaming (binary audio)

`POST /v1/music/generations` with `"stream": true` returns progressive MP3 bytes (`Content-Type: audio/mpeg`) instead of SSE. Music generation is implemented only for MiniMax: an `openai-compatibility` entry whose `name` contains `minimax` (for example the `ail-music` alias in `config.example.yaml`). Other providers return `501`.

<CodeGroup>
```bash cURL
curl -N http://localhost:18080/v1/music/generations \
  -H "Authorization: Bearer sk-test-123" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "ail-music",
    "stream": true,
    "lyrics": "[Verse]\nCode flows through the night\n[Chorus]\nShipping makes it right"
  }' > song.mp3
```

```python Python
import httpx

with httpx.stream(
    "POST",
    "http://localhost:18080/v1/music/generations",
    headers={"Authorization": "Bearer sk-test-123"},
    json={"model": "ail-music", "stream": True, "lyrics": "[Verse]\nHello world\n[Chorus]\nLet us sing"},
    timeout=300.0,
) as response:
    response.raise_for_status()
    with open("song.mp3", "wb") as f:
        for chunk in response.iter_bytes():
            f.write(chunk)
```
</CodeGroup>

- First bytes typically arrive after about 20 seconds; the watchdog for music uses at least 60s first-byte and 120s stall timeouts, even if `performance.streaming` is lower.
- Errors before the first byte return a JSON error with a proper status code. Errors after bytes were sent close the stream; the partial MP3 remains playable.
- Without `stream`, the response is JSON with base64 audio and metadata (`duration_ms`, `sample_rate`, ...). Use that when you need the metadata up front.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Nothing arrives until the end">
    A proxy in front of switchAILocal is buffering. switchAILocal sends `X-Accel-Buffering: no`; also disable response buffering in your proxy. Use `curl -N` when testing. For `vibecli:`/`codex:` CLI models a single chunk is expected.
  </Accordion>
  <Accordion title="Connection drops during long thinking phases">
    Enable `streaming.keepalive-seconds` and raise your client's read timeout. For slow `openai-compatibility` providers raise `performance.streaming.first-byte-timeout` (globally or under `per-provider`).
  </Accordion>
  <Accordion title="upstream stall (mid_stream) on provider ...">
    The provider stopped sending chunks for longer than `stall-timeout`. The client receives an SSE error event; retry the request, or raise `stall-timeout` for that workload.
  </Accordion>
  <Accordion title="JSON decode errors in a custom parser">
    Skip lines that start with `:` (keep-alives) and blank lines, and handle an `{"error": ...}` event before `[DONE]`.
  </Accordion>
</AccordionGroup>
