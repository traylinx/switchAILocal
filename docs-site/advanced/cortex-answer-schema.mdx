`plugins/cortex-answer-schema` is a small bundled Lua plugin. It exists for one integration: a grounded-answer client called **Cortex** that sends prompts through switchAILocal to a small or local model such as `gpt-oss:20b` on Ollama. It is a compatibility shim, not a general feature. Despite the shared name, it is unrelated to the [Cortex Router](/intelligent-systems/cortex-router).

The plugin ignores every request whose body doesn't contain one of its marker strings. Leave it disabled unless you run that client.

## The problem it solves

The client's answer prompt asks the model to emit a `classification_code` for each statement but doesn't list the allowed values. The client then validates each code against a fixed set:

```
SUPPORTED · PARTIALLY_SUPPORTED · CONFLICTING · ABSTAINED
```

Without the list, a small model guesses (`"FACT"`, `"factual"`), validation fails, and the client keeps regenerating until its own deadline expires.

## What it does

`on_request` uses `switchai.json_inject` to add a system message at the start of `messages`. Nothing is injected unless the body contains a marker:

| Marker substring in the request body | Injected system message |
|---|---|
| `classification_code` | The four allowed codes, an instruction to abstain by returning `{"statements": []}` (never a statement with an empty `citation_ids` list), `Reasoning: low`, and "Output JSON only" |
| `material statement` or `Identify contradictions` | `Reasoning: low` and "Output JSON only" |

`Reasoning: low` is the reasoning-effort control phrase for `gpt-oss` models. It shortens the hidden reasoning, which keeps generate-then-verify chains within tight client deadlines.

```lua plugins/cortex-answer-schema/handler.lua (excerpt)
function Plugin:on_request(req)
    if not req.body then return req end
    if string.find(req.body, "classification_code", 1, true) then
        req.body = switchai.json_inject(req.body, STEER)
    elseif string.find(req.body, "material statement", 1, true)
        or string.find(req.body, "Identify contradictions", 1, true) then
        req.body = switchai.json_inject(req.body, LEAN)
    end
    return req
end
```

## Enable

```yaml config.yaml
plugin:
  enabled: true
  plugin-dir: "./plugins"          # required; no plugins load without it
  enabled-plugins:
    - "cortex-answer-schema"
```

Restart the server and look for `loading plugin: Cortex Answer Schema Steering (cortex-answer-schema)` in the log.

## Example request

Any OpenAI-format request whose body contains a marker is modified before routing:

```bash
curl http://localhost:18080/v1/chat/completions \
  -H "Authorization: Bearer sk-test-123" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "ollama:gpt-oss:20b",
    "messages": [{"role": "user", "content": "Answer from the evidence. Return statements with classification_code and citation_ids."}]
  }'
```

The upstream model receives an extra first message with `role: system` that lists the four codes.

## Defaults and limits

- The plugin runs on every request, including requests with a provider prefix such as `ollama:…`, because Lua `on_request` hooks run for both prefixed and unprefixed models.
- Matching is a plain substring test on the raw JSON body and is case-sensitive.
- `json_inject` only touches bodies with a top-level `messages` array. Other bodies are left as they are, apart from a fallback that appends the text when the body isn't valid JSON.
- It can run alongside `cortex-router`. All loaded plugins run in turn, and the order between them isn't guaranteed.

## Troubleshooting

<AccordionGroup>
  <Accordion title="The plugin doesn't load">
    Check that `plugin-dir` is set and contains `cortex-answer-schema/schema.lua` and `handler.lua`. `schema.lua`'s `name` must match the folder name.
  </Accordion>
  <Accordion title="Validation still fails">
    Check that the client's prompt contains the literal `classification_code`. Run with `debug: true` to see hook errors.
  </Accordion>
</AccordionGroup>

## Removing it

Once the client's prompt includes its own classification vocabulary, remove the plugin from `enabled-plugins`. See [Lua Plugins](/advanced/lua-plugins) for the hook API and [Payload Injection](/advanced/payload-injection) for config-only parameter overrides.
