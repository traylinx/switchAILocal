The **State Box** is the directory where switchAILocal keeps mutable data produced by its intelligence and routing subsystems: the discovery registry, the feedback database and the virtual-model scheduler state. It is resolved from environment variables, not from `config.yaml`.

## When it matters

- You run with `intelligence.enabled: true` (discovery, feedback, skills), or you use [virtual models](/advanced/virtual-models).
- You want that data somewhere other than `~/.switchailocal`, for example a mounted volume.
- You run on an immutable filesystem and need to stop all writes (`SWITCHAI_READONLY=1`).

<Note>
Provider credentials (OAuth token files) are **not** stored by the State Box. They live in `auth-dir` (default `~/.switchailocal`), configured in `config.yaml`. See [Authentication](/concepts/authentication).
</Note>

## Configuration

| Variable | Effect | Default |
|---|---|---|
| `SWITCHAI_STATE_DIR` | Root of the State Box. `~` is expanded. | `~/.switchailocal` |
| `SWITCHAI_READONLY` | Set to exactly `1` to block all State Box writes. | unset |

```bash
export SWITCHAI_STATE_DIR="$HOME/.local/share/switchailocal"
./switchAILocal --config config.yaml
```

## Layout

```text
$SWITCHAI_STATE_DIR/
├── discovery/
│   ├── available_models.json      # discovery registry
│   ├── available_models.json.bak  # previous version (restore source)
│   └── registry.json              # checked for restore on startup
├── intelligence/
│   └── feedback.db                # feedback collector database
├── credentials/                   # created on init; not used for auth tokens in this release
└── virtual_models_state.json      # weighted round-robin scheduler state
```

The `discovery/`, `intelligence/` and `credentials/` directories are created when the intelligence service initialises (`intelligence.enabled: true`) and the State Box is writable. `virtual_models_state.json` is written whenever the virtual-model router advances its scheduler, independent of `intelligence.enabled`.

## Behaviour

### Atomic writes

State Box files are written with a rename-swap:

1. write to `<file>.tmp.<uuid>` with mode `0600`
2. `fsync` the temp file
3. optionally copy the current file to `<file>.bak`
4. rename the temp file over the target and `fsync` the directory

A crash leaves either the old or the new file, never a partial one. Orphan `.tmp.*` files are logged at startup and left in place.

### Restore from backup

At startup (writable mode only) switchAILocal checks `discovery/available_models.json` and `discovery/registry.json`. If a file is missing, empty or does not look like a JSON object/array (first and last character check), and a non-empty `.bak` exists, the backup is restored.

### Permission hardening

At startup the intelligence service walks the State Box and corrects modes:

- directories → `0700`
- files ending in `.json`, `.db`, `.json.bak`, `.db.bak` → `0600`
- other files are left alone

Each correction is logged:

```text
security audit: corrected permissions for /home/me/.switchailocal/discovery/available_models.json from 0644 to 0600
permission hardening: corrected 1 file/directory permissions
```

### Read-only mode

With `SWITCHAI_READONLY=1`:

- every State Box write returns `Read-only environment: write operations disabled`
- directories are not created, backups are not restored, permissions are still audited
- discovery skips writing its registry; the feedback collector stops recording
- routing and request handling keep working; virtual-model scheduler state is kept in memory only

```bash
SWITCHAI_READONLY=1 ./switchAILocal --config config.yaml
```

## Docker

Mount the State Box and point the variable at it:

```bash
docker run -p 18080:18080 \
  -e SWITCHAI_STATE_DIR=/data/state \
  -v switchai-state:/data/state \
  -v "$PWD/config.yaml:/app/config.yaml" \
  switchailocal:latest
```

For an immutable container add `-e SWITCHAI_READONLY=1` and mount the volume `:ro`.

## Status endpoint

The server contains a `GET /v0/management/state-box/status` handler that reports the root path, read-only flag, the presence and mode of `discovery/registry.json` and `intelligence/feedback.db`, and permission warnings. The stock binary does not wire a State Box into the HTTP server in this release, so the route is not registered and returns `404`. Inspect the directory directly instead:

```bash
ls -la "${SWITCHAI_STATE_DIR:-$HOME/.switchailocal}"/{discovery,intelligence}
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Nothing is created under the State Box">
    The intelligence directories are only created when `intelligence.enabled: true` and `SWITCHAI_READONLY` is not `1`. Check the startup log for `StateBox initialized at ... (read-only: false)`.
  </Accordion>
  <Accordion title="Read-only environment: write operations disabled">
    Expected when `SWITCHAI_READONLY=1`. Unset it (any value other than `1` means writable) and restart.
  </Accordion>
  <Accordion title="permission hardening: failed to chmod">
    The process user does not own the file, or the filesystem rejects `chmod` (some network or cross-UID mounts). Run switchAILocal as the owner of the directory, or use a local volume.
  </Accordion>
  <Accordion title="Virtual-model weights restart from zero after every restart">
    The scheduler state file could not be written (read-only mode or permissions). Routing still works; only the round-robin position is not persisted.
  </Accordion>
</AccordionGroup>
