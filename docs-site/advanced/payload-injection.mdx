---
title: Payload Injection
description: Set default or forced fields in upstream request payloads per model, without changing clients
icon: syringe
---

Payload injection writes JSON fields into the request **after** switchAILocal has translated it into the provider's native format and **just before** it is sent upstream. Use it to turn on provider-specific features (thinking modes, safety settings) for every request to a model, or to set defaults clients forget.

## When to use it

- A provider needs a non-standard field your clients do not send (for example `enable_thinking` for Alibaba GLM, or `thinking.type` for MiniMax).
- You want a default `temperature` or `max_tokens` for a family of models.
- You want to force a field regardless of what the client sent.

For logic that depends on request content, use a [Lua plugin](/advanced/lua-plugins) instead.

## Minimal config

```yaml config.yaml
payload:
  default:            # write only if the field is missing
    - models:
        - name: "gemini-2.5-*"
      params:
        "generationConfig.temperature": 0.7
  override:           # always write, replacing client values
    - models:
        - name: "glm-5.2"
          protocol: "openai"
        - name: "alibaba:glm-5.2"
          protocol: "openai"
      params:
        "enable_thinking": true
```

Changes are picked up on config hot reload. Example request: any normal call to a matching model, for example

```bash
curl http://localhost:18080/v1/chat/completions \
  -H "Authorization: Bearer sk-test-123" \
  -H "Content-Type: application/json" \
  -d '{"model": "alibaba:glm-5.2", "messages": [{"role": "user", "content": "Explain CRDTs"}]}'
```

The upstream request then carries `"enable_thinking": true`.

## Rule structure

```yaml
payload:
  default | override:
    - models:            # list; the rule applies if ANY entry matches
        - name: "<pattern>"
          protocol: "<format>"   # optional, see below
      params:            # map of JSON path -> value
        "<path>": <value>
```

A rule with an empty `models` list never matches.

### Model name matching

The pattern is matched against the **model ID as routed**, after alias and virtual-model resolution:

| Client sends | Name the rule sees |
|---|---|
| `alibaba:glm-5.2` (an alias in an `openai-compatibility` block) | `alibaba:glm-5.2` |
| `ail-compound` (a [virtual model](/advanced/virtual-models)) | the selected member's native model, e.g. `MiniMax-M3` |
| `ollama:llama3.2` or `geminicli:gemini-2.5-pro` (known provider prefix) | the part after the colon |
| `teamA/gemini-2.5-pro` (credential `prefix`) | `gemini-2.5-pro` |

This is why the example config lists the native name, the provider alias and the private `ail-*` alias side by side: each route reaches the executor under a different name.

Pattern syntax: `*` matches any sequence of characters (including none); everything else is literal and case-sensitive. `*` alone matches every model. Examples: `gpt-*`, `*-pro`, `gemini-*-flash`.

### Protocol filter

`protocol` restricts a rule to one upstream format. It is only checked by executors that pass a format:

| Executor | Format passed | Path root |
|---|---|---|
| OpenAI-compatible providers (`openai-compatibility`, MiniMax, Kimi, DeepSeek, Groq, …) | `openai` | request root |
| Gemini CLI (`geminicli`) | `gemini` | `request` (paths are relative to it) |
| Antigravity | `antigravity` | `request` |
| Gemini API, Vertex, AI Studio, Claude API, Codex, Qwen, iFlow | none | request root |

When an executor passes no format, the `protocol` field is ignored and the rule applies on name alone. The payload is then in that executor's native format: Gemini `generateContent` JSON for Gemini/Vertex/AI Studio, Anthropic Messages JSON for Claude, Responses JSON for Codex, OpenAI chat JSON for Qwen/iFlow.

<Warning>
Payload rules are **not applied** to Ollama, LM Studio, OpenCode, or local CLI tools (`claudecli`, `vibe`, `codex` CLI). Use Lua or client-side parameters for those.
</Warning>

### Parameter paths

Keys use [gjson/sjson](https://github.com/tidwall/sjson) path syntax: dots separate levels, missing intermediate objects are created. Quote keys that contain dots. Values can be any YAML scalar, list or map.

```yaml
params:
  "temperature": 0.3
  "generationConfig.thinkingConfig.thinkingBudget": 8192
  "thinking.type": "adaptive"
  "stop": ["</answer>"]
```

## Default vs override

| | `default` | `override` |
|---|---|---|
| Writes when field exists | no | yes |
| Several matching rules set the same path | first rule wins | last rule wins |
| Order | applied first | applied after defaults |

Example with `default: {temperature: 0.7, max_tokens: 4096}` on a request that sent `temperature: 1.0`: upstream sees `temperature: 1.0` and `max_tokens: 4096`. With the same values under `override`, upstream sees `temperature: 0.7` and `max_tokens: 4096`.

## Examples

<CodeGroup>
```yaml Thinking for compound backends
payload:
  override:
    - models:
        - name: "glm-5.2"
          protocol: "openai"
        - name: "ail-compound-alibaba"
          protocol: "openai"
      params:
        "enable_thinking": true
    - models:
        - name: "MiniMax-M3"
          protocol: "openai"
        - name: "minimax:MiniMax-M3"
          protocol: "openai"
      params:
        "thinking.type": "adaptive"
```

```yaml Gemini CLI thinking budget
payload:
  default:
    - models:
        - name: "gemini-2.5-pro"
          protocol: "gemini"   # Gemini CLI; path is relative to "request"
      params:
        "generationConfig.thinkingConfig.thinkingBudget": 32768
```

```yaml Default max_tokens for Claude API
payload:
  default:
    - models:
        - name: "claude-*"
      params:
        "max_tokens": 8192
```
</CodeGroup>

## Limits

- Injection runs after translation, so paths must match the **upstream** format, not the format the client used.
- For OpenAI-compatible providers, the `model` field and `reasoning_effort` derived from model-name suffixes are written after payload rules; do not try to change the model through payload injection.
- An invalid path or a value sjson cannot write is skipped silently.
- Rules apply to chat/completions-style requests. Embeddings, image, audio and music operations are forwarded without payload rules.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Rule does not apply">
    - Check which name the executor sees (table above). Add the alias and the native name if requests arrive both ways.
    - Patterns are case-sensitive: `MiniMax-M3` does not match `minimax-m3`.
    - The provider may be one that ignores payload rules (Ollama, LM Studio, OpenCode, CLI tools).
  </Accordion>
  <Accordion title="Rule applies to the wrong provider">
    `protocol` only filters on OpenAI-compatible, Gemini CLI and Antigravity executors. Narrow the `name` pattern instead.
  </Accordion>
  <Accordion title="See what was sent upstream">
    Enable `request-log: true` (or toggle it via `PUT /v0/management/request-log`) and inspect the logged upstream request body.
  </Accordion>
</AccordionGroup>
