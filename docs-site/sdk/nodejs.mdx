## Overview

There is no switchAILocal client library for Node.js. switchAILocal speaks the OpenAI API, so you use the official `openai` package with `baseURL` pointed at your local server. Every configured provider is then reachable by changing the `model` string.

<Note>
The npm package `@traylinx/switchailocal` is a **launcher**, not a client: `npx @traylinx/switchailocal` downloads the release binary for your platform and runs the server. Arguments after the package name are passed to the binary.
</Note>

**Use this when** your Node.js or TypeScript code already uses the OpenAI SDK, or you want one client for several providers.

## Installation

```bash
npm install openai
```

You need a running switchAILocal server (default `http://localhost:18080`). `apiKey` is a **client key from `api-keys` in your `config.yaml`**, not a provider key. If `api-keys` is empty, any value is accepted.

## Quick start

```javascript
import OpenAI from 'openai';

const client = new OpenAI({
  baseURL: 'http://localhost:18080/v1',
  apiKey: 'sk-test-123', // must match an entry in api-keys
});

const completion = await client.chat.completions.create({
  model: 'ollama:llama3.2',
  messages: [{ role: 'user', content: 'What is the capital of France?' }],
});
console.log(completion.choices[0].message.content);
```

The SDK also reads `OPENAI_BASE_URL` and `OPENAI_API_KEY` from the environment, so `new OpenAI()` works once those are exported.

## Choosing a model

| Form | Example | Routes to |
|------|---------|-----------|
| `provider:model` | `ollama:llama3.2`, `claudecli:claude-sonnet-4-5` | That provider only. Valid prefixes: `ollama`, `geminicli`, `claudecli`, `vibecli`, `codex`, `opencode`, `gemini`, `claude`, `openai`, `switchai`, `openai-compat` |
| Alias or model ID | `sonnet`, `llama-3.3-70b` | Any provider that registered that ID |
| `prefix/model` | `groq/llama-3.3-70b` | Credentials configured with `prefix: groq` |
| Virtual model | `ail-compound` | A pool from `virtual-models` (see [Virtual models](/advanced/virtual-models)) |
| `auto`, `auto:<intent>`, `cortex` | `auto:coding` | Auto-routing (see [Auto-routing setup](/guides/auto-routing-setup)) |

<Note>
Any other `name:model` string (for example `lmstudio:qwen2.5`) is treated as a plain model ID. It only works if a provider registered exactly that string, such as an `alias:` under `openai-compatibility`.
</Note>

## Streaming

```javascript
const stream = await client.chat.completions.create({
  model: 'ollama:llama3.2',
  messages: [{ role: 'user', content: 'Tell me a short story' }],
  stream: true,
});

for await (const chunk of stream) {
  process.stdout.write(chunk.choices[0]?.delta?.content ?? '');
}
```

See [Streaming](/examples/streaming) for keep-alives, timeouts and error behaviour.

## TypeScript

```typescript
import OpenAI from 'openai';
import type { ChatCompletionMessageParam } from 'openai/resources/chat/completions';

const client = new OpenAI({ baseURL: 'http://localhost:18080/v1', apiKey: 'sk-test-123' });

export async function ask(prompt: string): Promise<string> {
  const messages: ChatCompletionMessageParam[] = [{ role: 'user', content: prompt }];
  const completion = await client.chat.completions.create({ model: 'ail-compound', messages });
  return completion.choices[0].message.content ?? '';
}
```

## CLI provider options (attachments, flags, sessions)

CLI providers (`geminicli:`, `claudecli:`, `vibecli:`, `codex:`) read a literal `extra_body.cli` object from the request body. The Node SDK sends unknown body fields unchanged, so add an `extra_body` key directly (TypeScript needs a cast):

```typescript
const completion = await client.chat.completions.create({
  model: 'geminicli:gemini-2.5-pro',
  messages: [{ role: 'user', content: 'Explain the logic in this file' }],
  extra_body: {
    cli: {
      attachments: [
        { type: 'file', path: './src/main.ts' },
        { type: 'folder', path: './src/lib' },
      ],
      flags: { sandbox: true, auto_approve: false, yolo: false },
      session_id: 'latest',
    },
  },
} as any);
```

| Field | Effect | Supported by |
|-------|--------|--------------|
| `attachments[]` | Prepends `@path` references. Paths must be inside the switchAILocal server's working directory | `gemini`, `vibe` |
| `flags.sandbox` | Adds the CLI's sandbox flag | `gemini`, `codex` |
| `flags.auto_approve` / `flags.yolo` | Adds the CLI's auto-approve flag | `gemini`, `vibe`, `claude`, `codex` |
| `session_id` | Resumes a CLI session | `gemini`, `claude`, `vibe` |

CLI calls time out after 5 minutes. See [CLI attachments](/api/cli-attachments).

## Other endpoints

```javascript
// Models visible to clients (hidden/private aliases are filtered out)
const models = await client.models.list();
for (const m of models.data) console.log(m.id);

// Embeddings are routed to a provider (Ollama or an OpenAI-compatible API)
const emb = await client.embeddings.create({ model: 'ollama:nomic-embed-text', input: 'hello world' });

// Images: use the strict /openai/v1 namespace for OpenAI-shaped image responses
const images = new OpenAI({ baseURL: 'http://localhost:18080/openai/v1', apiKey: 'sk-test-123' });
const img = await images.images.generate({ model: 'ail-image', prompt: 'a lighthouse at dusk' });
```

## Anthropic SDK

`/v1/messages` speaks the Anthropic Messages API and accepts the `x-api-key` header:

```javascript
import Anthropic from '@anthropic-ai/sdk';

const anthropic = new Anthropic({ baseURL: 'http://localhost:18080', apiKey: 'sk-test-123' });
const msg = await anthropic.messages.create({
  model: 'claude:claude-sonnet-4-5', // or any other routable model
  max_tokens: 512,
  messages: [{ role: 'user', content: 'Hello' }],
});
```

## Error handling

```javascript
import OpenAI from 'openai';

try {
  await client.chat.completions.create({ model: 'ail-compound', messages: [{ role: 'user', content: 'hi' }] });
} catch (err) {
  if (err instanceof OpenAI.APIConnectionError) {
    console.error('switchAILocal is not reachable');
  } else if (err instanceof OpenAI.APIError) {
    console.error(err.status, err.message);
  } else {
    throw err;
  }
}
```

| Status | Typical cause |
|--------|---------------|
| 401 | `apiKey` is not in `api-keys` |
| 400 `unknown provider for model X` | No provider registered `X` |
| 503 `Provider 'x' is not active` | Valid prefix, but the provider has no credentials |
| 429 `model_cooldown` | All credentials cooling down; see `Retry-After` |
| 422 `no_eligible_backend` | Virtual model has no member for this request type |

## Troubleshooting

<AccordionGroup>
  <Accordion title="fetch failed / ECONNREFUSED">
    The server is not running or listens elsewhere. Check `curl http://localhost:18080/health`.
  </Accordion>
  <Accordion title="Browser requests fail">
    Do not ship a client key to browsers. Call switchAILocal from your backend, or bind it to `127.0.0.1` for local tools only.
  </Accordion>
  <Accordion title="TypeScript rejects extra_body">
    It is not part of the SDK types. Cast the params object (`as any`) or build the request with `fetch`.
  </Accordion>
</AccordionGroup>
