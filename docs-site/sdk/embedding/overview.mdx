## Overview

switchAILocal ships an optional ONNX-based embedding engine (`internal/intelligence/embedding`) that turns text into 384-dimensional vectors on your machine. It is used **internally** by the Cortex intelligence features:

- **Semantic tier**: match a prompt to an intent (coding, reasoning, ...) by vector similarity instead of asking a router LLM
- **Semantic cache**: reuse a previous routing decision for a near-identical prompt
- **Skill matching**: pick a skill from `intelligence.skills.directory` and augment the prompt

<Warning>
The local engine is **not** what serves `POST /v1/embeddings`. That endpoint is routed to a provider like any other request (Ollama, an `openai-compatibility` entry, a virtual model). See [Using embeddings](/sdk/embedding/usage).
</Warning>

**Enable it when** you use `model: "auto"` / `"cortex"` routing through the Cortex Router plugin and want faster, deterministic intent matching or caching. You do not need it for normal requests.

## How it works

```mermaid
graph LR
    A[Text] --> B[Lower-case + WordPiece tokenizer]
    B --> C[ONNX Runtime: MiniLM]
    C --> D[Mean pooling]
    D --> E[L2 normalisation]
    E --> F[384-dim vector]
```

- Input is lower-cased, split on whitespace and punctuation, and tokenised with the model's `vocab.txt`; it is truncated to **256 tokens**.
- The ONNX graph must accept `input_ids`, `attention_mask`, `token_type_ids` and return `last_hidden_state`.
- Vectors are mean-pooled and L2-normalised, so cosine similarity is a dot product.

## Setup

<Steps>
  <Step title="Install ONNX Runtime">
    The engine loads the ONNX Runtime shared library at startup. It is looked up in this order:

    1. `ONNXRUNTIME_LIB_PATH` environment variable
    2. macOS: `/usr/local/lib/libonnxruntime.dylib`, `/opt/homebrew/lib/libonnxruntime.dylib`
    3. Linux: `/usr/local/lib/libonnxruntime.so`, `/usr/lib/libonnxruntime.so`, `/usr/lib/x86_64-linux-gnu/libonnxruntime.so`
    4. Windows: `C:\Program Files\onnxruntime\lib\onnxruntime.dll`
    5. `~/.switchailocal/lib/` (same file name)

    On macOS, `brew install onnxruntime` places it under `/opt/homebrew/lib`.
  </Step>

  <Step title="Download the model">
    From the repository root:

    ```bash
    ./scripts/download-embedding-model.sh
    ```

    This downloads `model.onnx` and `vocab.txt` for `all-MiniLM-L6-v2` from Hugging Face into `~/.switchailocal/models/all-MiniLM-L6-v2/`.
  </Step>

  <Step title="Enable in config.yaml">
    ```yaml config.yaml
    intelligence:
      enabled: true              # master switch; nothing below starts without it
      embedding:
        enabled: true
        model: "all-MiniLM-L6-v2"  # folder name under ~/.switchailocal/models/
      semantic-tier:
        enabled: true
        confidence-threshold: 0.85
      semantic-cache:
        enabled: true
        similarity-threshold: 0.95
        max-size: 10000
      skills:
        enabled: true
        directory: "plugins/cortex-router/skills"
      skill-matching:
        enabled: true
        confidence-threshold: 0.80
    ```
  </Step>

  <Step title="Restart and verify">
    Intelligence settings are read at startup. Look for:

    ```text
    Embedding engine initialized with model: all-MiniLM-L6-v2
    Semantic tier initialized with N intents
    Semantic cache initialized (threshold: 0.95, max size: 10000)
    ```
  </Step>
</Steps>

To route requests through these features, also enable the Cortex Router Lua plugin; see [Cortex Router](/intelligent-systems/cortex-router).

## Configuration reference

| Key | Default | Notes |
|-----|---------|-------|
| `intelligence.enabled` | `false` | Master switch for every intelligence feature |
| `intelligence.embedding.enabled` | `false` | Load the engine |
| `intelligence.embedding.model` | `all-MiniLM-L6-v2` | Directory name under `~/.switchailocal/models/` containing `model.onnx` and `vocab.txt` |
| `intelligence.semantic-tier.confidence-threshold` | `0.85` | Minimum similarity to accept an intent match |
| `intelligence.semantic-cache.similarity-threshold` | `0.95` | Minimum similarity for a cache hit |
| `intelligence.semantic-cache.max-size` | `10000` | Entries before LRU eviction |
| `intelligence.skill-matching.confidence-threshold` | `0.80` | Minimum similarity to attach a skill |
| `intelligence.skills.directory` | `plugins/cortex-router/skills` | Skill folders (`SKILL.md`) |

There are no `model-path`, `vocab-path` or `shared-library` keys: model files always come from `~/.switchailocal/models/<model>/` and the runtime library from the lookup list above.

## Defaults and limits

| Property | Value |
|----------|-------|
| Output dimension | 384 (fixed in code) |
| Max input length | 256 tokens (longer input is truncated) |
| Batch processing | Sequential (one inference per text) |
| Thread safety | Safe for concurrent `Embed` calls |
| Network use | None after the model files are downloaded |

Because the dimension is fixed at 384, only models with a 384-wide hidden state and a BERT WordPiece vocabulary work as drop-in replacements. See [Custom embedding models](/sdk/embedding/custom-providers).

## Troubleshooting

<AccordionGroup>
  <Accordion title="Embedding model not found: all-MiniLM-L6-v2">
    `~/.switchailocal/models/all-MiniLM-L6-v2/model.onnx` is missing. Run `./scripts/download-embedding-model.sh`, or make sure `intelligence.embedding.model` matches the folder name.
  </Accordion>
  <Accordion title="Failed to initialize embedding engine: failed to initialize ONNX runtime">
    The ONNX Runtime library was not found or does not match your CPU architecture. Set `ONNXRUNTIME_LIB_PATH` to the full path of `libonnxruntime.dylib` / `.so` / `.dll`.
  </Accordion>
  <Accordion title="Embedding engine not available, semantic tier will be disabled">
    The engine failed to load (see the warning just before it), or `intelligence.embedding.enabled` is `false`. Semantic tier and semantic cache both depend on the engine.
  </Accordion>
  <Accordion title="Failed to initialize semantic tier: failed to read intents file">
    The semantic tier loads intents from `<parent of intelligence.skills.directory>/internal/intelligence/semantic/intents.yaml`. With the default skills directory that is `plugins/cortex-router/internal/intelligence/semantic/intents.yaml`. Copy `internal/intelligence/semantic/intents.yaml` from the source tree to that location (or adjust `skills.directory`) and restart.
  </Accordion>
  <Accordion title="Nothing happens even though everything loaded">
    The engine only influences requests that go through the Cortex Router plugin (`model: "auto"` or `"cortex"` with `plugin.enabled: true` and `cortex-router` in `enabled-plugins`). Explicit model names bypass it.
  </Accordion>
</AccordionGroup>
