## Overview

What you can change depends on which embeddings you mean:

| Goal | How | Code changes |
|------|-----|--------------|
| Use a different embedding model in **your application** | Configure a provider model and call `/v1/embeddings` | None |
| Use a different model for **semantic routing / cache / skills** | Drop a compatible ONNX model into `~/.switchailocal/models/<name>/` and set `intelligence.embedding.model` | None, within the constraints below |
| Use a cloud API or a non-BERT model for semantic routing | Not configurable; requires changing switchAILocal source | Yes |

## Application embeddings: any provider model

Point `/v1/embeddings` at whichever model you want. Examples:

```yaml config.yaml
# Local, via Ollama (any embedding model you pulled)
ollama:
  enabled: true
  auto-discover: true

# Cloud, via any OpenAI-compatible API with an /embeddings endpoint
openai-compatibility:
  - name: "openai"
    base-url: "https://api.openai.com/v1"
    api-key-entries:
      - api-key: "YOUR_OPENAI_KEY"
    models:
      - name: "text-embedding-3-small"
        alias: "embed-small"

# Optional: default when a request omits "model"
intelligence:
  matrix:
    embedding: "embed-small"
```

```bash
curl http://localhost:18080/v1/embeddings \
  -H "Authorization: Bearer sk-test-123" \
  -H "Content-Type: application/json" \
  -d '{"model": "embed-small", "input": "hello"}'
```

Full details: [Using embeddings](/sdk/embedding/usage).

## Replacing the local ONNX model

The engine loads `model.onnx` and `vocab.txt` from `~/.switchailocal/models/<intelligence.embedding.model>/`. Any model that satisfies **all** of these constraints can be used without code changes:

| Requirement | Why |
|-------------|-----|
| Hidden size **384** | The output tensor shape is fixed at 384 (`EmbeddingDimension`) |
| ONNX inputs `input_ids`, `attention_mask`, `token_type_ids` (int64) | Names are hard-coded |
| ONNX output `last_hidden_state` | Name is hard-coded; mean pooling is applied by switchAILocal |
| BERT **WordPiece** `vocab.txt` (one token per line, `[CLS]`, `[SEP]`, `[UNK]`, `##` sub-words) | The built-in tokenizer is a lower-casing WordPiece tokenizer |
| Useful within 256 tokens | Input is truncated to 256 tokens |

Models with SentencePiece/BPE tokenizers, different hidden sizes, or pooled outputs will either fail to load or produce meaningless vectors.

### Steps

<Steps>
  <Step title="Export to ONNX">
    Export a 384-dimension BERT-style sentence-transformer so the graph returns `last_hidden_state`. With Hugging Face Optimum:

    ```bash
    pip install "optimum[exporters]"
    optimum-cli export onnx --model <hf-model-id> --task feature-extraction ./export
    ```

    Check the input and output names in the exported graph (for example with Netron) before continuing.
  </Step>

  <Step title="Install the files">
    ```bash
    mkdir -p ~/.switchailocal/models/my-minilm
    cp ./export/model.onnx ~/.switchailocal/models/my-minilm/model.onnx
    cp ./export/vocab.txt  ~/.switchailocal/models/my-minilm/vocab.txt
    ```
  </Step>

  <Step title="Select it">
    ```yaml config.yaml
    intelligence:
      enabled: true
      embedding:
        enabled: true
        model: "my-minilm"
    ```

    Restart switchAILocal. The log should show `Embedding engine initialized with model: my-minilm`.
  </Step>

  <Step title="Re-tune thresholds">
    Similarity scores differ between models. Re-check `semantic-tier.confidence-threshold` (default 0.85), `semantic-cache.similarity-threshold` (0.95) and `skill-matching.confidence-threshold` (0.80) against real prompts.
  </Step>
</Steps>

<Note>
The semantic cache is in memory and intent and skill vectors are recomputed at startup, so switching models does not leave stale vectors behind.
</Note>

## Why there is no plugin interface

The semantic tier and semantic cache accept any value with `Embed`, `CosineSimilarity` and `IsEnabled` methods (`internal/intelligence/semantic/tier.go`, `internal/intelligence/cache/semantic_cache.go`), but the intelligence service always constructs the ONNX engine itself and exposes no setter or config option to inject another implementation. These packages are also under `internal/`, so other modules cannot import them. Using a cloud embedding API or a different architecture for routing therefore means modifying `internal/intelligence/service.go` in a fork.

## Troubleshooting

<AccordionGroup>
  <Accordion title="failed to load ONNX model">
    The graph's input or output names differ from `input_ids` / `attention_mask` / `token_type_ids` → `last_hidden_state`. Re-export with the `feature-extraction` task.
  </Accordion>
  <Accordion title="ONNX inference failed (shape mismatch)">
    The model's hidden size is not 384.
  </Accordion>
  <Accordion title="Routing quality dropped after switching">
    The tokenizer does not match (non-WordPiece vocab), or thresholds need re-tuning for the new score distribution.
  </Accordion>
</AccordionGroup>
